◆SEED スクリプト API リファレンス （C# / WGSL）

基本形 ライフサイクル Time / Debug Mathf Vector / Quaternion / Color Random Input Physics Audio GameObject コンポーネント Scene ライブラリ シェーディング (WGSL)
このページの範囲: SEED には 2 種類のスクリプト対象があります。①ゲームロジック（C#）と ②画面全体の光応答式（WGSL シェーディングアセット）です。第 1〜9 節は C# の SEEDScript API、 第 8 節「シェーディング (WGSL)」は .wgsl ファイル 1 枚で ライティングの見た目を差し替える別系統の API です。用途が異なるので混同しないでください。
重要: SEED は Unity ではありません。UnityEngine / MonoBehaviour / GetComponent は存在しません。 エンジン API（Mathf / Vector3 / Time など）は SEED 名前空間にあり、 コードでは必ず SEED. を付けて呼び出します（例: SEED.Random.Range(0, 10)）。 本ページの一覧部分は簡潔さのため SEED. を省略しています（この節は C# の話です。WGSL は 第 8 節を参照）。

1. スクリプトの基本形

C# で書き、SEEDScript（SEEDEditor.Scripting 名前空間）を継承します。

using SEEDEditor.Scripting;   // SEEDScript・[SerializeField]・NativeFrameContext

public class Mover : SEEDScript
{
    // インスペクタに公開するフィールドは [SerializeField] を付ける
    [SerializeField(Label = "速度")]
    private float speed = 2.0f;

    public override void Update(ref NativeFrameContext ctx)
    {
        // 毎フレーム、自分の GameObject を右へ動かす
        transform.Position += SEED.Vector3.Right * speed * SEED.Time.DeltaTime;
    }
}
[SerializeField]フィールドをインスペクタに公開する属性。Label / Tooltip 指定可
ref NativeFrameContext ctxctx.DeltaTime（前フレームからの経過秒）と ctx.AnimTime（累計時間）を持つ
無修飾で書きたい場合はスクリプト先頭に自分で using SEED; を足します（System.Random 等との型名衝突は自己責任）。

インスペクタ公開の属性（SEEDEditor.Scripting 名前空間）

フィールドやクラスに付ける属性。すべて using SEEDEditor.Scripting;（テンプレートに含まれる）だけで使えます。

属性付ける先効果
[SerializeField]フィールドインスペクタに公開する。Label = "表示名" / Tooltip = "説明" を名前付き引数で指定できる（省略時のラベルはフィールド名を整形したもの）
[Header("見出し")]フィールドそのフィールドの直前に見出し行を挿入する
[Tooltip("説明")]フィールドマウスオーバー時の説明。[SerializeField(Tooltip = ...)] より独立した [Tooltip] が優先される
[Range(min, max)]フィールド数値フィールドをスライダー表示にする（float / int）
[ResetButton]フィールド行の右端に「デフォルトに戻す」ボタン（⟲）を出す。押すと宣言の初期化子の値（無ければ 0 / false / 空文字 / 参照は未設定）へ戻る。Ctrl+Z で取り消せる
[Bindable]フィールドこのフィールドをシェーダパラメータのバインド元として公開する（[SerializeField] との併用が必須）。対応型は float と Vector3 のみ
[RequireComponent(typeof(OtherScript))] / [RequireComponent("Camera")]クラスアタッチ時に不足コンポーネントを自動追加する。型指定＝他スクリプト（型名から .cs を探す）、文字列指定＝ネイティブコンポーネント名
[DisallowMultipleComponent]クラス同一アクターに同じスクリプトを 2 つ以上付けられなくする（追加操作が警告で中止される）
[RequireComponent("Camera")]
[DisallowMultipleComponent]
public class CameraShake : SEEDScript
{
    [Header("揺れ")]
    [SerializeField(Label = "強さ")]
    [Range(0f, 5f)]
    private float amplitude = 1.0f;

    [SerializeField]
    [Tooltip("1 秒あたりの振動回数")]
    private float frequency = 8.0f;

    // 行末の ⟲ を押すと 1.5 に戻る（初期化子が無い場合は 0 に戻る）
    [SerializeField, ResetButton]
    private float damping = 1.5f;
}

[ResetButton] の詳細

戻り先はフィールド宣言の初期化子の値です。初期化子が無ければ言語既定値（数値 0 / bool false / string 空文字）になります。参照フィールド（GameObject / Transform など）では「未設定」へ戻ります（✕ ボタンと同じ結果）。

リセットは通常の値編集と同じ経路を通るため Ctrl+Z で取り消せます（リセット前の値に戻る）。対応型は数値（float / double / int / long / short）・bool・string・参照フィールドで、列挙型などインスペクタが読み取り専用表示にする型ではボタンは出ません。既定値の文字列に改行が含まれる場合もボタンは出ません（1 行 1 コマンドの通信経路に載せられないため）。

[Serializable] ネストクラスのフィールドそのものに付けてもボタンは出ません（子をまとめて戻すと Ctrl+Z が 1 手にまとまらないため）。ネストの中の個々のフィールドには付けられます。その場合の戻り先はそのネストクラス側の初期化子であり、外側での new Nested { inner = 99f } のような初期化は反映されません。

[Bindable] の詳細

水面シェーディングアセット（.wgsl）が @ref を付けて宣言したパラメータは、インスペクタで「アクタ → コンポーネント → 変数」を選ぶだけで、このフィールドの実行中の値が毎フレームシェーダへ流し込まれます（water_shading_asset.md の「3.6 @ref — シーンから値を流し込む」を参照）。

[SerializeField] との併用が必須です。[SerializeField] の無いフィールドに付けてもバインド候補には現れません（インスペクタに出ない値をバインド候補に出すと、何がどこから流れているのか追跡できなくなるため）。

対応する型は WGSL 側と厳密に対応する 2 つだけです。float … WGSL の f32 パラメータへ繋がる／Vector3 … WGSL の vec3<f32>（色）パラメータへ繋がる。成分の部分取り出しは行いません。 Vector3 を f32 のパラメータへ繋ぐことはできません（X 成分だけ欲しいなら float のフィールドを別に用意してください）。上記以外の型に付けても候補には現れません。

値は毎フレーム、描画の直前に実行中のインスタンスから直接読まれます（Edit / Play の両方）。したがって Update などで書き換えた値がそのままシェーダへ届きます。

[Bindable] が付いているかどうかの検証は、値を読み取るたびにランタイム側で毎回行われます（設定時に一度だけ検証してキャッシュする方式ではありません）。そのため、バインドを張った後にこの属性を外す・フィールドを消す・型を変える、といった変更をすると、その瞬間からバインドは静かに切れます。シェーダのパラメータは保存値（無ければアセットの既定値）へフォールバックし、インスペクタのその行に ⚠ が出ます。

スクリプトのコンパイルに失敗している間は、そのスクリプトのフィールドはバインド候補に一切現れません（まずコンパイルエラーを直してください）。

[SerializeField, Bindable]
private float glowPower = 1.0f;

[Serializable] を付けたクラス／構造体型のフィールドに [SerializeField] を付けると、インスペクタで子フィールドが再帰的に展開されます（入れ子の上限は 8 段）。

GameObject やコンポーネントハンドル型（Transform / Camera など）のフィールドに [SerializeField] を付けると、他アクターへの参照フィールドになります（Hierarchy から D&D で設定）。詳細は第 7 節の「参照フィールド」を参照してください。

2. ライフサイクル関数

SEEDScript を継承して override。1 フレーム内で以下の順に呼ばれます。不要なものは override 不要。

BeginFrame(ref ctx)フレーム開始時。入力取得や状態リセット向け
EarlyUpdate(ref ctx)Update より前。他スクリプトへ渡す事前計算向け
Update(ref ctx)毎フレームの主更新。ゲームロジックの中心
ConstantUpdate(ref ctx)固定タイムステップの更新。物理など時間刻みを一定にしたい処理向け
LateUpdate(ref ctx)Update 後。追従カメラなど他更新の結果を使う処理向け
Render(ref ctx)描画フェーズ。描画に関わる処理向け
EndFrame(ref ctx)フレーム終了時。後片付けや状態確定向け

生成・破棄コールバック（OnStart / OnDestroy）

インスタンスの一生に 1 回ずつ呼ばれます。引数は取りません（Play モードのみ）。

OnStart()有効化後、そのスクリプト自身の最初の BeginFrame の直前に 1 回だけ
OnDestroy()スクリプトインスタンスが破棄される直前に 1 回だけ
public class Enemy : SEEDScript
{
    private float _initialY;

    public override void OnStart()
    {
        // 初期化はここ。gameObject / transform は利用可能
        _initialY = transform.Position.y;
    }

    public override void OnDestroy()
    {
        // 後片付けはここ（シーンへのアクセスは行わないこと）
        SEED.Debug.Log("Enemy 消滅");
    }
}

OnStart の規約: 「全スクリプトの BeginFrame 群より前にまとめて」ではなく、スクリプトごとに初回 BeginFrame の直前に呼ばれます（A の OnStart → A の BeginFrame → B の OnStart → …）。Play 開始時の全スクリプトが対象で、GameObject.Instantiate で生成した場合は生成が適用される次のフレームの BeginFrame 直前になります。無効化 → 再有効化しても 2 回目は呼ばれません。ctx は渡されないため、フレーム時間が要る初期化は BeginFrame で行ってください。

OnDestroy の規約: アクター破棄（gameObject.Destroy()）／シーン遷移・リロード／Play 終了／スクリプトのホットリロードのすべてで呼ばれます（OnStart 済みのインスタンスのみ）。Destroy は即時ではなく Render フェーズまで走り終えた後に適用され、その直後に OnDestroy が呼ばれます（＝破棄要求フレームの BeginFrame〜Render は通常どおり実行され、そのフレームの EndFrame は呼ばれません。EndFrame 内で Destroy した場合は同フレーム末尾で呼ばれます）。OnDestroy 後にそのインスタンスへコールバックが来ることはありません。破棄処理中のためシーンへのアクセスは保証されません（transform の読み書き・Find は既定値）。また OnDestroy 内の Instantiate / Destroy は無視されます（遅延実行もされません）。

物理イベントコールバック（3D / 2D 共通）

自分のコライダー（ColliderComponent / Collider2dComponent）が他コライダーと衝突・接触すると呼ばれます。other は相手アクター（特定できない場合 IsValid == false）。

OnCollisionEnter(GameObject other)衝突が始まったフレーム
OnCollisionStay(GameObject other)衝突継続中（毎物理ステップ）
OnCollisionExit(GameObject other)衝突が終わったフレーム
OnTriggerEnter(GameObject other)トリガーへの進入時（トリガー側・相手側の両方に通知）
OnTriggerStay(GameObject other)トリガーに重なり続けている間（毎物理ステップ・同上）
OnTriggerExit(GameObject other)トリガーからの退出時（同上）

OnTriggerStay は OnCollisionStay と同じ頻度規約で、重なりが続く限り毎物理ステップ呼ばれます（1 フレームに複数回呼ばれうる）。Enter が発火したステップでは Enter と Stay の両方が届きます。

public class Coin : SEEDScript
{
    public override void OnTriggerEnter(SEED.GameObject other)
    {
        SEED.Debug.Log($"取得: {other.IsValid}");
        gameObject.Destroy();   // 自分を消す
    }
}

ポインタイベントコールバック（キャンバス UI のクリック）

自分のアクターの Sprite / SkinnedSprite で 「ポインタ判定」（raycast_target）を ON にすると、Play 中のマウス操作が届きます。既定は OFF のオプトインです。判定は毎フレーム 1 回で、最前面の 1 アクターにだけ届きます（描画ゾーン → Layer が大きい方 → ヒエラルキー順で後）。

OnPointerEnter()カーソルがこのアクターへ乗った最初のフレーム
OnPointerExit()カーソルがこのアクターから外れた最初のフレーム
OnPointerDown()このアクターの上で左ボタンが押された瞬間
OnPointerUp()このアクターの上で左ボタンが離された瞬間
OnPointerClick()押下と解放が同一アクターで完結したとき（OnPointerUp の直後）

対応するのはスクリーンスペースキャンバス（Actor2D + Canvas）だけです。3D ワールド内キャンバス（Actor3D + Canvas）には届きません。非アクティブなアクター・無効化したスロットのスプライトも判定対象外です。

// ボタンの作り方（レシピ）: Canvas の子に Sprite → インスペクタで「ポインタ判定」ON → このスクリプトを追加
public class Button : SEEDScript
{
    private static readonly SEED.Color Normal = SEED.Color.White;
    private static readonly SEED.Color Hover  = new SEED.Color(0.85f, 0.95f, 1f, 1f);
    private static readonly SEED.Color Press  = new SEED.Color(0.6f, 0.7f, 0.9f, 1f);

    private void Tint(SEED.Color c)
    {
        if (gameObject.GetComponent<SEED.Sprite>() is { } s) s.Color = c;
    }

    public override void OnStart()        => Tint(Normal);
    public override void OnPointerEnter() => Tint(Hover);
    public override void OnPointerExit()  => Tint(Normal);
    public override void OnPointerDown()  => Tint(Press);
    public override void OnPointerUp()    => Tint(Hover);
    public override void OnPointerClick() => SEED.Debug.Log("押された");
}

スクリプト例外の扱い

ライフサイクル関数・物理イベントコールバックの中で未処理の例外（Nullable の .Value、NullReferenceException、IndexOutOfRangeException など）が発生しても、ランタイムプロセスは落ちません。エンジンがすべてのコールバック境界で例外を捕捉します。

項目挙動
プロセス継続する（強制終了しない）
ゲーム進行継続する。中断されるのは例外を出したスクリプトの、その 1 回の呼び出しだけ
ログエディタのログパネルに [SCRIPT ERROR] {型名}.{関数名}: {メッセージ} の 1 行と、続けてスタックトレースが出力される
繰り返し発生時全文スタックは初回のみ。以降は 300 回に 1 回、累計回数付きの 1 行サマリのみ（毎フレーム全文を吐くとログが溢れるため）
例外を放置しないこと。 落ちないのはあくまで安全網であり、正常動作ではありません。例外が出続けているスクリプトはその関数が毎フレーム途中で打ち切られているため、状態更新が飛んで挙動が壊れます。[SCRIPT ERROR] を見つけたら必ず原因を直してください。
// NG: hitInfo が null のフレームで例外 → その BeginFrame は以降が実行されない
var target = hitInfo.Value.Position;

// OK: null を明示的に扱う
if (hitInfo is { } hit) { var target = hit.Position; }

デバッガをアタッチしている場合でもブレークポイントは通常どおり機能します。ただしエンジンが例外を捕捉するため「ユーザー未処理例外」での自動停止は発生しません。例外の発生箇所で止めたい場合は、デバッガ側の例外ブレークポイント（first-chance）を有効にしてください。

6.5 Input（キーボード・マウス入力）

判定は 3 種類: 押している間 / 押した瞬間 / 離した瞬間。

キャラクターコントローラー（Transform を書くだけで地形に押し戻される）

Collider インスペクタの「キャラクターコントローラー」を ON にしたアクターは、専用 API を呼ばず transform.Position を書き換えるだけで地形・静的コライダーに衝突解決され、めり込んだぶんが自動で押し戻されます。押し戻しは移動のたびではなく 物理ステップ同期（60Hz）と同じタイミングで前回位置との差分を解決します。壁ずり・段差・スロープは内部の KCC が処理します。

Physics.IsGrounded(gameObject)bool: キャラクターが接地しているか（物理ステップ同期で自動更新）
transform.Teleport(pos)void: 衝突を無視して pos へ瞬間移動（前回位置もリセットされ押し戻されない）
// キャラクター移動: Position を希望位置へ書くだけ。地形にめり込めば押し戻される
velocityY += -9.81f * SEED.Time.DeltaTime;                // 重力は自前で積分
if (SEED.Physics.IsGrounded(gameObject) && velocityY < 0f) velocityY = 0f;
transform.Position += horizontal + new SEED.Vector3(0f, velocityY, 0f) * SEED.Time.DeltaTime;
対象は Collider（カプセル推奨）を持ち、インスペクタで「キャラクターコントローラー」を ON にしてください。1 フレーム内で Position を何度書いても物理ステップで 1 回だけまとめて解決されます（反映に 1 フレームの遅延あり）。補正後の位置は集約経路で反映され子アクタも追従します。重力・複数移動の合成はスクリプト側の責務です。瞬間移動は transform.Teleport() を使ってください。

スクリプトは自分がアタッチされた GameObject を gameObject、その Transform を transform（短縮）で参照できます。コンポーネントは gameObject.GetComponent<T>() で取得します。戻り値は T?（Nullable）で、未アタッチ・該当なしは null。SEED のアクターは同種を複数スロット持て、スロットには名前があります。

HasComponent(name) の名前: 受け付ける文字列は Transform / CanvasTransform / Sprite / Camera / Audio（AudioSource ではなく Audio）/ Animator / ParticleEmitter / InputMap の 8 つで、それ以外は常に false です。型で判定できる場面では GetComponent<T>() is { } のほうが安全です。

transformTransform: gameObject.GetComponent<Transform>() の短縮
gameObject.GetComponent<T>()T?: 0 番目のスロット（未アタッチは null）。T = Transform/CanvasTransform/Sprite/Camera/AudioSource/Animator/ParticleEmitter/InputMap
gameObject.GetComponent<T>(index)T?: index 番目のスロット
gameObject.GetComponent<T>("Name")T?: スロット名一致

{
    sprite.Color = SEED.Color.Red;
}

生成・破棄・検索（Instantiate / Destroy / Find）

GameObject.Instantiate("assets://actors/Bullet.actor").actor ファイル（プレハブ）からアクターを生成。戻り値に同フレーム中に Position 等を設定でき、その値が優先される
obj.Destroy() / GameObject.Destroy(obj)アクターを破棄（実際の破棄はフレーム末尾。Unity と同じ遅延モデル）
GameObject.Find("Player")アクターを名前で検索（ヒエラルキーの DFS 順で最初の一致）
var bullet = SEED.GameObject.Instantiate("assets://actors/Bullet.actor");

    bt.Position = transform.Position;
if (!bullet.IsValid) { /* 読み込み失敗 */ }

var player = SEED.GameObject.Find("Player");
if (player.GetComponent<Transform>() is { } pt) { pt.Position = SEED.Vector3.Zero; }
2D アクター（Actor2D）の注意: 構築時に Transform が CanvasTransform へ差し替わるため、生成直後の 3D Position 設定は反映されません。位置は翌フレーム以降に CanvasTransform.Position で設定してください。
破棄済み GameObject への読み取りは既定値、書き込みは無視されます（クラッシュしません）。
現時点の制限: Play 開始後に生成・破棄したアクターの物理コライダーは物理スレッドに反映されません。コライダーの収集は Play 開始時（およびシーン遷移時）の一括処理で、Instantiate / Destroy は物理側の追加・除去を行わないためです。衝突・トリガーのイベント通知自体は実装済みですが（第 2 節）、実行時に生成したアクターはその対象になりません。

後方互換: 旧 v1（version 欠落・WASD）も読み込め、内部で自動的に v2 へ移行（保存は常に v2）。
.inputmap は初回アクセス時に読み込み・キャッシュし、以降は 1 秒間隔の mtime 監視で自動再読込（毎フレーム再読込はしません）。編集・保存すれば約 1 秒以内に反映され、ランタイム再起動は不要です。再読込時はエッジ検出履歴もリセットされます。
複数持ち: gameObject.GetComponent<InputMap>(1)（index）や gameObject.GetComponent<InputMap>("Vehicle")（名前）で選択。

// レバーを引いたらバルブ全閉
if (gameObject.GetComponent<WaterLink>() is { } valve)

参照フィールド（インスペクタで他アクターを差し込む）

[SerializeField] を GameObject やコンポーネントハンドル型のフィールドに付けると、インスペクタ上で他のアクターへの参照として編集できます（Unity のオブジェクト参照フィールド相当）。

using SEEDEditor.Scripting;

public class FollowCamera : SEEDScript
{
    // 追従したい対象。Hierarchy からアクタ行をドロップして設定する
    [SerializeField(Label = "追従対象")]
    private SEED.Transform target;

    // 未設定を許したい参照は Nullable で宣言する（null = 未設定）
    [SerializeField(Label = "注視カメラ")]
    private SEED.Camera? lookCamera;

    [SerializeField] private SEED.Vector3 offset = new(0f, 3f, -8f);

    public override void LateUpdate()
    {
        // 非 Nullable 宣言は「未設定でも null にはならない」ので IsValid で確かめる
        if (!target.IsValid) return;

        transform.Position = target.Position + offset;

        // Nullable 宣言は null チェック → さらに IsValid で生存確認
        if (lookCamera is { } cam && cam.IsValid)
            cam.FieldOfView = 60f;
    }
}
宣言意味
SEED.GameObject / SEED.GameObject?アクター本体への参照
SEED.Transform / SEED.CanvasTransform（＋ ?）アクターのルートに直付けされた Transform 系への参照
SEED.Sprite / SEED.Camera / SEED.AudioSource / SEED.Animator / SEED.ParticleEmitter / SEED.InputMap（＋ ?）アクター内のコンポーネントスロットへの参照

参照フィールドは常に参照（ハンドル）です。「値としての Transform」は作れません。位置や回転を値で持ちたい場合は SEED.Vector3 などを使ってください。

null と IsValid の使い分け
null は「未設定」だけを意味します（Nullable T? 宣言のみ null になり得ます）。
IsValid は「参照先が今も生きているか」で、未解決（アクタが見つからない）・破棄済みのどちらでも false になります。
非 Nullable（T）で宣言した参照は未設定でも null にならず、IsValid == false の無効ハンドルになります。
IsValid はライフサイクル関数の中でのみ意味のある値を返します（実行フェーズ外では常に false）。

インスペクタでの設定: ① フィールド行の参照ボックスへ Hierarchy パネルからアクタ行を D&D ② その種別のスロットを複数持つアクターならスロット選択ダイアログが出る ③ ✕ ボタンで参照解除 ④ 参照ボックスのダブルクリックで Hierarchy の参照先へジャンプ ⑤ 参照先がその種別を持たない場合は警告が出て設定されません。

保存形式と制約
参照はアクタ名（コンポーネント参照は加えてスロット名）で保存されます（Player / Player|MainCamera）。未設定は空文字列です。
エディタでアクタをリネームした場合、旧名一致の参照は自動で新名に追従します（同名アクタが複数ある場合は旧名一致の参照がすべて書き換わります。コンパイルエラー中のスクリプトの参照は型判定できないため追従しません）。スロット名の変更は追従しないため再設定が必要です。アクタ名に | は使えません。
同名アクタが複数ある場合はヒエラルキーの DFS 順で最初に見つかったものが使われます。
解決は一度きりです。Play 開始時（および Instantiate 時）に、そのスクリプトの OnStart より前に解決・注入されます。実行中のアクタ名変更やアクタ生成には追従しません（実行中に探し直すなら SEED.GameObject.Find(name)）。
解決に失敗しても例外にはならず、Nullable 宣言は null、非 Nullable 宣言は IsValid == false の無効ハンドルになります。

7.5 Scene（シーン遷移）

シーンはプロジェクト設定 → シーンマネージャで登録した名前で参照します（assets:// パス直接指定も可能）。

Scene.Load("game")事前読み込みのみ（現在のシーンはそのまま）。保持できるのは 1 つで、直後の Transition で消費される
Scene.Transition("game")シーン切り替え。フレーム末尾に行われ、現在のシーンの全アクター・スクリプトは破棄される。Load 済みなら即座、未 Load なら内部で自動読み込み
// 推奨フロー: 事前読み込み → 遷移（遷移フレームのロード時間がなくなる）
SEED.Scene.Load("game");         // フェード中などに呼ぶ
// ... フェードアウト演出など ...
SEED.Scene.Transition("game");   // 即座に切り替わる
読み込みに失敗した場合は現在のシーンが維持されます（戻り値 true は「受理」であり成功保証ではない）。Transition を呼んだフレームで発行した Instantiate / Destroy は破棄されます。シーン遷移を決めたら、そのフレームではそれ以上シーン操作をしないでください。

7.6 Profiler（任意区間の時間計測）

エディタの「プロファイラ」パネルへ、自分のスクリプトの任意区間を計測項目として出せます。 計測結果はそのとき実行中のセクションの子として階層に現れます （例: スクリプト > Update > 敵の索敵）。詳細は docs/profiler.md。

using (Profiler.Scope("名前")) { … }推奨。using ブロックを抜けた時点で自動的に計測終了（例外で抜けても閉じる）
Profiler.Begin("名前")計測開始。必ず対応する End を呼ぶこと。戻り値は「計測されたか」
Profiler.End()直近の Begin に対応する区間を終了する
// 推奨: using で自動終了
using (SEED.Profiler.Scope("敵の索敵"))
{
    SearchEnemies();
}

// 明示的に書く場合は Begin と End を必ず対にする
SEED.Profiler.Begin("経路探索");
SolvePath();
SEED.Profiler.End();
計測されるのはエディタの「プロファイラ」パネルを開いている間だけです（閉じている間はほぼゼロコストで false を返します）。
名前は固定文字列にしてください。 名前の種類には上限（256）があり、Begin($"敵{i}") のようにループ変数を埋め込むと上限に達し、それ以降の名前が計測されなくなります。
Begin と End の対応が崩れてもエンジン側の計測は壊れません（End は自分が開いた区間しか閉じません）。

8. シェーディングアセット（WGSL）

C# スクリプトとは別系統の API です。ユーザーが書いた .wgsl ファイル 1 枚で、 1 ライト分の光応答式（BRDF）を差し替える仕組み。正典は docs/shading_asset.md （実装: runtime/src/engine/core/renderer/shading_asset.rs / 契約の正典 runtime/src/engine/core/renderer/shaders/shading_contract.wgsl）。本節は その要点をまとめたものです。食い違いがあれば md とソースが正しい。

概要

shade_default を書けば、アセットを差すだけで画面全体の見た目が変わります。 シェーディングモデルを設定していない全表面（＝ID 0。地形・草・既定マテリアルはすべてここ）が この実装で描かれます。マテリアル側の設定は一切不要です。 shade_model_1 / shade_model_2 / shade_model_3 は、 そこから例外オブジェクトだけをさらに上書きするための追加枠という位置づけです （マテリアルの shading_model を 1〜3 にした面だけがそちらへ回ります）。

fn shade_default(sf: ShadingSurface, li: LightSample) -> vec3<f32>全体の既定シェーディング。ID 0（地形・草・未設定マテリアル）＋未実装の例外 ID を受ける。これが基本
fn shade_model_1 / shade_model_2 / shade_model_3(sf, li) -> vec3<f32>マテリアルの shading_model が同値の面だけを上書きする例外枠

エンジンが渡すのは「面の情報（ShadingSurface）」と「そのライト 1 灯の実効放射輝度 （LightSample）」の 2 つだけで、バインディング（uniform / texture / storage）は アセット側から一切見えません。関数はすべて任意（書かなかったものは無いものとして扱われます）。

できないこと: compose（画面全体の組み立て＝ライト走査・アンビエント・エミッシブ加算・影の適用・GI・反射の合成）の差し替えは未対応（段階 L3-b、未実装）。 差し替えられるのはあくまで「1 ライト分の光応答式」。テクスチャの自前サンプリングは不可（下記）。 半透明 / WBOIT / フォワードパス / カメラプレビュー小窓には効きません。

// @shading_contract 1
const PULSE_SPEED: f32 = 3.0;   // 脈動の速さ（ラジアン/秒）

    return shade_model_0(sf, li) * pulse;   // 標準 PBR の結果を時間で変調する
}

入力の実体（テクスチャはどこにある／影はどこにある）

テクスチャはアセットから直接触れません。マテリアルのベースカラーテクスチャ・法線マップ・ ラフネス/メタリックマップは第 1 層（G-Buffer 書き込み）で既にサンプリング済みで、その結果が sf.base_color / sf.normal / sf.roughness / sf.metallic / sf.occlusion / sf.emissive として届きます。アセット側で @group / @binding / texture_2d<f32> / sampler を宣言する使い方は サポートしていません（供給経路が無く、naga 検証かパイプライン生成で失敗し組み込み標準へフォールバックします。画面は壊れません）。 模様を足したいときは、①画像で足す＝マテリアル側（第 1 層）でテクスチャを差す、②式で足す＝ sf.world_pos / sf.frag_coord / sf.user_data / sf.render_tag を種にプロシージャルに作る、のいずれかを使ってください。

影は li.color に織り込み済みです。通常は li.color を掛けるだけで正しく影も落ち、 アセット側で影を再計算してはいけません（二重適用になる）。「影の中だけ加工したい」場合は li.color_unshadowed との比から影係数を復元します（li.color = li.color_unshadowed × 影係数）。 

// 影係数の復元: 0 = 完全な影 / 1 = 影なし
let lit_full    = shading_luminance(li.color_unshadowed);
let shadow      = select(shading_luminance(li.color) / lit_full, 1.0, lit_full <= 0.0);

// 影の中だけ青紫に寄せる（影なしの側は白＝素通し）
let hard_shadow = step(0.5, shadow);
let shadow_tint = mix(vec3<f32>(0.4, 0.35, 0.6), vec3<f32>(1.0), hard_shadow);

// 加工した影係数は li.color ではなく li.color_unshadowed に掛ける
// （li.color に掛けるとエンジンの影が二重に乗る）
let radiance = li.color_unshadowed * shadow_tint;
return sf.base_color * shading_saturate(dot(sf.normal, li.direction)) * radiance;
select(f, t, cond) の引数順は「偽の値・真の値・条件」です。復元は輝度（スカラー）ベースなので、色付き影（RT のカラードシャドウ）をチャンネルごとに扱いたい場合は li.color / max(li.color_unshadowed, vec3<f32>(1e-6)) を使ってください。

shade_light(N, V, L, albedo, F0, metallic, roughness, radiance) -> vec3<f32>1 ライト分の Cook-Torrance BRDF。標準 PBR を土台に足したいときの基礎ブロック
shade_model_0(sf: ShadingSurface, li: LightSample) -> vec3<f32>エンジン標準 PBR（差し替え不可だがアセットから呼べる）。加算・混合や「この 1 体だけ標準 PBR に戻す」用途

ユーザー実装（shade_default / shade_model_1..3）の返り値にはエンジンが自動で shading_nan_guard を掛けます。shade_model_0 へ落ちる経路（アセット未指定時の既定ディスパッチ）にはガードが掛かりません（アセット導入前と完全に同値にするための設計）。

項目内容
書けるものshade_default / shade_model_1..3 の 4 関数（全部任意）。標準ライブラリ関数・定数の利用
書けないもの@group / @binding 宣言（テクスチャ・uniform 等）、compose（ライト走査・アンビエント・影適用・GI・反射合成）の差し替え、shade_model_0 自体の差し替え

設定方法

CameraComponent.shading_asset: Option<String>カメラごとの指定。インスペクタの Camera コンポーネント「Shading」行で .wgsl を D&D／選択。右クリックで解除
Scene.shading_asset: Option<String>シーン既定。.scene ルート直下の "shading_asset" キー（エディタ UI 無し。手編集か IPC で設定）
SET_CAMERA_SHADING_ASSET:{actor_dfs_id},{slot_idx},{path}IPC: 指定アクタの Camera スロットの shading_asset を設定。path が空なら解除
SET_SCENE_SHADING_ASSET:{path}IPC: シーン既定を設定。path が空なら解除

解決順（フォールバック連鎖）: Play はメインカメラの shading_asset → シーン既定 → 組み込み標準。 Edit のメインビュー／Play ポーズ中はシーン既定 → 組み込み標準（デバッグカメラで描くためカメラ指定は使われない）。

既知の制限

半透明 / WBOIT / フォワードパスには効かない（常に標準ディスパッチが連結される）。カメラプレビュー小窓は常に組み込み標準。 deferred が無効なフレーム（Edit のワイヤーフレーム表示・2D シーンビュー・post_fx.deferred オフ）には効かない。 例外用の ID は 1..3 の 3 枠のみ（G-Buffer のビット幅制約。shade_default はこの枠を消費しない）。 マテリアルの shading_model にはエディタ UI が無い（.mat / .smdl の直編集のみ。 ただし shade_default だけを使う分にはマテリアルを一切触らないのでこの制限には当たらない）。

トゥーンの実装例（完全サンプル）

shade_default が主役です。このファイルを差すだけで世界全体がトゥーンになり、 末尾の shade_model_1 は「例外的にこのオブジェクトだけ標準 PBR に戻す」ための上書きです。 

// @shading_contract 1
// toon.wgsl — 3 階調セルシェーディング + リムライト（全体の既定シェーディング）
// このファイルをカメラまたはシーンの「Shading」に差すだけで、シェーディングモデルを
// 設定していない全表面（地形・草・全マテリアル）がトゥーンで描かれる。マテリアル側の設定は不要。

const TOON_DIFFUSE_STEPS: f32 = 3.0;      // 拡散光の階調数
const TOON_SHADOW_FLOOR: f32 = 0.15;      // 最暗階調の下限
const TOON_SPECULAR_THRESHOLD: f32 = 0.6; // スペキュラを 2 値化するしきい値
const TOON_SPECULAR_STRENGTH: f32 = 0.7;
const TOON_SPECULAR_POWER: f32 = 48.0;
const TOON_RIM_POWER: f32 = 3.0;
const TOON_RIM_STRENGTH: f32 = 0.35;

// 全体の既定シェーディング: トゥーン。ID 0（未設定表面）がこれで描かれる。
fn shade_default(sf: ShadingSurface, li: LightSample) -> vec3<f32> {
    let N = sf.normal;
    let V = sf.view_dir;
    let L = li.direction;

    // ── 拡散: N・L を階調化する ──
    let ndl  = shading_saturate(dot(N, L));
    let band = shading_posterize(ndl, TOON_DIFFUSE_STEPS) + 0.5 / TOON_DIFFUSE_STEPS;
    let diffuse_term = max(shading_saturate(band), TOON_SHADOW_FLOOR);

    // ── スペキュラ: Blinn-Phong を 2 値化する ──
    let H    = normalize(V + L);
    let ndh  = shading_saturate(dot(N, H));
    let spec = pow(ndh, TOON_SPECULAR_POWER);
    let spec_term = select(0.0, TOON_SPECULAR_STRENGTH, spec > TOON_SPECULAR_THRESHOLD);

    // ── リムライト: 視線に対して立っている面ほど明るく ──
    let rim  = pow(1.0 - shading_saturate(dot(N, V)), TOON_RIM_POWER);
    let rim_term = rim * TOON_RIM_STRENGTH * ndl;

    // li.color は減衰・スポット円錐・影まで織り込み済み（再計算してはならない）。
    return (sf.base_color * diffuse_term + vec3<f32>(spec_term) + vec3<f32>(rim_term)) * li.color;
}

// シェーディングモデル 1: 例外オブジェクト用の上書き。標準 PBR をそのまま素通しする。
fn shade_model_1(sf: ShadingSurface, li: LightSample) -> vec3<f32> {
    return shade_model_0(sf, li);
}

試し方: 上のコードを assets/shading/toon.wgsl として保存し、カメラの「Shading」行に D&D するか、.scene の "shading_asset" に指定します。マテリアルには何も触らなくても、 地形・草を含む画面全体が 3 階調＋リムライトになります（stderr の [SHADING] loaded path=... models=shade_default,1 ... で有効化を確認可能）。 Edit モードで動かしたまま TOON_DIFFUSE_STEPS を書き換えて保存すると約 1 秒で反映されます。
