# シャドウマップ（CSM / スポット）の設計と設定

影方式が `features.shadow = "shadowmap"`（既定）のときに使われる、ラスタ シャドウマップ経路の正典。
RT 影（`features.shadow = "rt"`）は別経路（`rt_shadow_on.wgsl` / `shadow_mask.wgsl`）で、本書の設定は
一切参照しない。**両方式は併存する**（プロジェクト／シーンごとに選べる）。

関連: [rendering_flow.md](rendering_flow.md) §2.5（パスとしてのシャドウ深度）、
[rendering_roadmap.md](rendering_roadmap.md) Phase R2 / R8。

---

## 1. 構成

| 要素 | 実装 | 備考 |
|---|---|---|
| 方向光 CSM | `runtime/src/engine/core/renderer/shadow.rs` | 3 カスケード（`CSM_CASCADE_COUNT`）。影付き方向光は先頭 1 灯のみ |
| スポット影 | 同上 | 最大 4 灯（`MAX_SHADOW_SPOTS`）、1024x1024 固定（`SPOT_SHADOW_SIZE`） |
| 品質設定 | `renderer/shadow_settings.rs`（`ShadowQuality`） | `project_settings.json` の `shadow` ブロックが供給。**値の正典はここ 1 か所** |
| 深度描画 | `pipelines/shadow_depth_{mesh,skinned}.toml` ＋ `depth_prepass.wgsl` | slope-scaled バイアスは設定で上書きされる |
| サンプリング | `shaders/shadow.wgsl`（`sample_shadow_dir` / `sample_shadow_spot`） | フォワード・デファード**共通**。呼び出しは `lighting_eval.wgsl` |
| 起動時の読み込み | `app_base/app/app_init.rs::handle_resumed` | `Renderer::new` より**前**に読む（テクスチャ確保とパイプライン生成が設定に依存するため） |

## 2. `project_settings.json` の `shadow` ブロック

```json
"shadow": {
  "resolution": 2048,
  "distance": 150.0,
  "split_lambda": 0.8,
  "normal_offset": 1.5,
  "depth_bias": 1.0,
  "slope_bias": 2.0,
  "pcf_radius_texels": 1.5,
  "pcf_taps": 12
}
```

| キー | 既定 | 範囲 | 意味 / 触るとどうなるか |
|---|---|---|---|
| `resolution` | 2048 | 1024 / 2048 / 4096 | CSM 1 カスケードの解像度。上げるほど影が精細（VRAM は 3 レイヤぶん）。**変更はランタイム再起動後に反映**（深度テクスチャと BindGroup を起動時に確保するため） |
| `distance` | 150.0 | 1〜100000 | 影を描く最大距離[m]。カメラ far との**小さい方**が使われる。小さくするほど手前の影が精細になり、これより遠くは影が付かなくなる |
| `split_lambda` | 0.8 | 0.0〜1.0 | カスケード分割の log/uniform ブレンド。0=均等分割、1=対数分割。大きいほど手前のカスケードが小さく＝近景が精細 |
| `normal_offset` | 1.5 | 0〜8 | 法線オフセット量[テクセル]。アクネ（自己遮蔽の縞）対策の主役。大きすぎるとピーターパン（影の浮き）。**PCF 半径と同程度以上**にすること |
| `depth_bias` | 1.0 | 0〜8 | 定数深度バイアス[テクセル]。法線オフセットが効かない「光と正対する面」の残差用。大きすぎるとピーターパン |
| `slope_bias` | 2.0 | 0〜16 | 深度を書く側（ラスタライザ）の slope-scaled バイアス。三角形の傾きに比例して押し込む |
| `pcf_radius_texels` | 1.5 | 0〜8 | PCF フィルタ半径[テクセル]。大きいほど輪郭が柔らかい。接地部の影が弱く（光漏れに）見えたら下げる |
| `pcf_taps` | 12 | 1〜16 | PCF のタップ数。多いほど滑らかだが GPU コストが線形に増える。1 なら中心 1 タップ（＝ハードウェア 2x2 バイリニア PCF のみ） |

- ブロックごと無い／キーが欠けている場合は**上の既定値**が使われる（部分指定可）。
- 壊れた値（NaN・∞）は既定値へ、範囲外はクランプされる（`ShadowQuality::sanitize`）。
- エディタの「プロジェクト設定 → グラフィックス → シャドウマップ品質」から編集できる。
- 起動ログに実効値が 1 行出る: `[SEED INIT] shadow quality  resolution=… distance=… …`

### 既定値を「従来と同じ絵」にしていない理由

Phase R2 当時の既定（`split_lambda = 0.5` / 影距離はカメラ far そのまま / PCF 3x3 固定 / NDC 定数
バイアス 0.0012）は、遠景まで映すカメラ（例 `far = 1000`, `fov_y = 25°`）で

- カスケード 0 のバウンディング球半径が **約 113m** → 1 テクセル ≒ **11cm**
- そのカスケードの深度レンジが約 565m → NDC 定数バイアス 0.0012 は **約 0.68m** の押し込み

となり、「壁の影が 11cm 刻みの階段になる（ジャギー）」「地面の接地影が 0.68m 浮いて消える
（ピーターパン）」が同時に起きていた。設定ファイルを持たない既存プロジェクトこそこの状態なので、
**既定値そのものを改善後の値**にしてある。

## 3. アクネ（自己遮蔽の縞）対策

シャドウマップのアクネは「受光ピクセルの深度」と「シャドウマップ 1 テクセルへ量子化された深度」の
ズレで起きる。対策は 3 段構えで、**どれか 1 つでは必ず穴が残る**。

1. **ラスタライザの slope-scaled 深度バイアス**（`shadow_depth_*.toml` → `shadow.slope_bias` で上書き）
   深度を書く側で、三角形の傾きに比例した量だけ押し込む。
2. **法線オフセット**（`shadow.wgsl::shadow_normal_offset_amount`）
   シャドウ空間へ投影する**前**に、ワールド位置を幾何法線 `Ng` 方向へずらす。
   ずらす量 = `そのカスケードの 1 テクセルのワールド幅 × normal_offset × sinθ`
   （`sinθ = sqrt(1 − (Ng·L)²)`。正対する面で 0、かすめる面で 1）。
   深度ではなく**位置**を動かすため、傾きがきつい面でもピーターパンになりにくい。
   - 法線は必ず `Ng`（幾何法線）を使う。法線マップ後の `N` を使うと面から外れた方向へずれて影が崩れる。
   - テクセル幅は**カスケードごと**に違う（既定値では近 7mm / 遠 8.8cm ＝ 12 倍差）ため、
     カスケードを決めてからそのカスケードの値で計算する（`ShadowMatricesUbo::cascade_texel_world`）。
3. **カスケード別の定数深度バイアス**（`ShadowMatricesUbo::cascade_depth_bias`）
   法線オフセットが 0 になる面（光と正対する面）の量子化残差を潰す最終保険。
   `depth_bias[テクセル] × テクセルのワールド幅 ÷ そのカスケードの深度レンジ` を CPU 側で NDC へ
   換算して渡す。**カスケードによらず効きが一定**になるのがポイント（旧実装の NDC 固定値は
   遠カスケードで 0.5m 超に膨らんでいた）。

スポットだけは NDC 固定の定数バイアス（`SPOT_SHADOW_CONST_BIAS = 0.0012`）を据え置いている。
透視投影の NDC 深度は非線形で、ワールド距離からの換算にライトごとの near/far が要るため。
量子化の主因は法線オフセットが吸収する（スポットのテクセル幅は距離に比例するので、
`ShadowMatricesUbo::spot_texel_scale × 光源距離` で求める）。

## 4. ジャギー（輪郭の階段）対策 — 回転 Vogel ディスク PCF

旧実装は PCF 3x3（固定格子・9 タップ）で、シャドウマップのテクセルが画面上で大きいほど段差が
そのまま見えた。現在は

- **Vogel ディスク**（黄金角らせん）で円板上に `pcf_taps` 個のタップを均等配置
- ピクセルごとに **IGN（Interleaved Gradient Noise）** で回転

させ、段差を「向きの揃わない細かなディザ」へ分解する。IGN はピクセル座標だけの関数なので
フレーム間で不動＝静止時にちらつかない。比較サンプラーが `Linear` なので 1 タップが 2x2 の
バイリニア PCF になり、実効の柔らかさは `半径 + 0.5` テクセル程度。

半径・タップ数はテクセル単位でデータ化してあるので、解像度を変えても見た目の柔らかさは保たれる。

## 5. カスケード配分とテクセルスナップ

- 分割は practical split（log と uniform のブレンド、`cascade_split_distances`）。
  遠端は `min(カメラ far, shadow.distance)`。
- 各カスケードはカメラ視錐台スライスの**バウンディング球**を包むタイト正射で、
  半径は `RADIUS_QUANTIZE` で量子化する（カメラ回転で半径が揺れて影がスケールするのを防ぐ）。
- **テクセルスナップ**: 正射の原点がシャドウマップのテクセル格子へ必ず載るよう、
  NDC の平行移動成分を丸める（`compute_cascade_matrices` 末尾）。これが無いと、カメラが
  サブテクセル単位で動くたびに影の模様が「泳ぐ」。
  ユニットテスト `cascade_projection_is_texel_snapped` がカメラ位置を変えながら不変条件を検査している。

参考値（`fov_y = 25°`, `aspect = 16:9`, `resolution = 2048`, `split_lambda = 0.8`, 3 カスケード）:

| 設定 | カスケード 0 / 1 / 2 のテクセル幅 | 分割距離 | 備考 |
|---|---|---|---|
| 影距離1000m・λ=0.5（旧既定相当） | 11.1cm / 18.3cm / 54.2cm | 168 / 357 / 1000m | 壁の影が階段状になり、接地影はバイアスで浮く |
| 影距離150m・λ=0.8（現在の既定） | 0.72cm / 1.7cm / 8.8cm | 10.9 / 30.5 / 150m | 近景のディテール影が出る |
| 影距離80m・λ=0.8・4096 | 0.20cm / 0.5cm / 2.3cm | 5.7 / 17.4 / 80m | 近距離特化。80m より遠くは影なし |

（`fov_y = 25°`, `aspect = 16:9`。カスケード 0 が 11.1cm → 0.72cm ＝ **約 15 倍**細かくなる）

## 6. 制限・既知の割り切り

- 影付き方向光は 1 灯・スポットは 4 灯まで。point / rect の影はシャドウマップ非対応（RT 影で対応）。
- カスケード境界のスムーズブレンドは無し（選択のみ）。境界で影の解像度が段階的に変わる。
- `shadow.distance` より遠いフラグメントは**影なし**になる（カスケード外は可視率 1.0）。
  遠景の大きな影が要るシーンでは `distance` を伸ばすこと（そのぶん手前が粗くなる）。
- `resolution` の変更はランタイム再起動が必要。
- `receive_shadows`（モデル側の影受け無効化）は未対応。

### よく似ているが**シャドウマップではない**症状

遠景（数十 m 以上）のモデルの斜面に出る**規則的な点状・ハッチ状の黒いドット**は、
シャドウマップのアクネではない。deferred の幾何法線 Ng が深度バッファの量子化で荒れ、
`lighting_eval.wgsl` の幾何ゲート（`dot(Ng,L)` による直接光の遮断）がターミネータ付近で
0/1 に振れることが原因である（2026-09-13 に実機で切り分け・対策済み）。
バイアスや PCF をいくら触っても消えない。詳細は
[rendering_flow.md](rendering_flow.md) の「遠景では Ng を捨てて G-Buffer 法線 N へ倒す」を参照。

見分け方: `.scene` の `settings.rendering.deferred` を `false`（フォワード）にすると消えるなら
このケース。影方式を変えても・`shadow.distance` を縮めても消えないのも特徴。
