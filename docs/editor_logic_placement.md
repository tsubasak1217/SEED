# ロジック配置

規則的な配置（円形・グリッド・直線・ランダム散布）を **1 操作・Undo 1 件** で作る機能。
新規アクタ群の生成と、`ControlPoint` の点列への一括追加の 2 つに使える。

---

## 導線

### 1. ヒエラルキー右クリック → 「アクタを追加」

```
アクタを追加
 ├ 3D アクタ            … 従来どおり 1 クリックで 1 体追加
 ├ 2D アクタ            … 同上
 └ ロジック配置          … ダイアログを開く
    ├ 3D アクタ
    └ 2D アクタ
```

- 空きスペースを右クリック → 生成グループは**ルート直下**へ入る。
- アクタを右クリック → 生成グループは**そのアクタの子**へ入る
  （このときサブメニューは `2D アクタ / 3D アクタ → 親としてラップ / 子として追加` の
  下に「ロジック配置」が並ぶ）。
- **通常の追加操作は 1 クリックのまま**。ロジック配置だけが 1 段下がる。

無効化される場合:

| 状況 | 挙動 |
| --- | --- |
| キャンバス編集タブでルートを右クリック | 「3D アクタ」が無効（理由をツールチップ表示） |
| 2D アクタを右クリック | 「3D アクタ」が無効（3D は 2D の子になれない） |

### 2. インスペクタ → ControlPoint → 「ロジック配置で点を追加…」

同じダイアログを **配置元・基準点の説明を隠した状態**で開く。
生成した点列は既存の点列の**末尾へ追記**される（時刻は既存の続きから連番）。
上限（`MAX_CONTROL_POINTS` = 256 点）を超えるぶんは切り詰め、件数を警告として通知する。

---

## ダイアログ

左がパラメータ、右が**真上から見たプレビュー**（画面の右が +X、上が +Z）。
パラメータを変えるとプレビューが即座に更新される。

### 配置元（新規アクタ生成時のみ）

| 選択 | 生成されるもの |
| --- | --- |
| 空アクタ | Transform（3D）または CanvasTransform（2D）だけを持つ空のアクタ |
| アクタファイル | 選択した `.actor`（3D）/ `.actor2d`（2D）から構築したプレハブインスタンス |

アクタファイル由来のアクタは `prefab_source` を持つので、
「プレハブから更新」「シーン内の全プレハブを更新」の対象になる。

### パターンとパラメータ

すべてのパターンは **XZ 平面**上に点を作る（Y は「段」）。
2D 配置では `(X, Z)` をキャンバスの `(X, Y)` へ写す。

#### 円形／円弧

| 項目 | 説明 |
| --- | --- |
| 個数 | 生成する点の数 |
| 半径 | 中心からの距離 [m] |
| 開始角 | 最初の点の角度 [度]（0 = +X 方向） |
| 角度範囲 | 360 で全周。360 未満は円弧になり**両端に点が置かれる** |
| 中心を向く | 各点のヨーが中心を向く（「進行方向を向く」より優先） |

全周のときは始点と終点が重ならないよう、角度の分母を「個数」にする
（円弧のときは「個数 − 1」で両端を含める）。

半径はダイアログの数値欄でも決められるが、**配置モードのドラッグでも決められる**
（後述の[半径ドラッグ](#半径ドラッグ円形円弧のみ)）。
ドラッグで決めた値はダイアログの前回値へ書き戻され、次に開いたときの初期値になる。

#### グリッド

| 項目 | 説明 |
| --- | --- |
| 行 / 列 / 段 | Z 方向 / X 方向 / Y 方向の個数（**段は 3D のみ**） |
| 間隔 X / Z / Y | 各方向の間隔 [m]（2D では「間隔 Y」が第 2 軸の間隔になる） |
| 基準アンカー X / Z（2D では Y） | パターンのどこを基準点に合わせるか（0〜1）。下表参照 |
| 市松オフセット | 奇数行を X 方向へ半間隔ずらす |

走査順は **段 → 行 → 列**。この順が生成アクタの連番（`_01`, `_02`, …）になる。

##### 基準位置アンカーの座標規約

グリッド全体の広がりを `(n-1) × 間隔` としたとき、
**アンカー比のぶんだけパターンを手前へ寄せる**（`位置 = i × 間隔 − アンカー × 広がり`）。

| アンカー (X, Y) | 基準点に合う場所 |
| --- | --- |
| `(0, 0)` | グリッドの **-X 側・-Z 側の角**（2D キャンバスでは**左上**） |
| `(0.5, 0.5)` | **中心**（既定。旧「中心揃え」オンと同じ） |
| `(1, 1)` | グリッドの **+X 側・+Z 側の角**（2D キャンバスでは**右下**） |

- 軸ごとに独立して効く（例: `(1, 0)` = 右上）。
- 範囲外の値は 0〜1 へ丸める（NaN は 0.5）。
- **段（Y 方向）はアンカーの対象外**。常に基準点の高さから**上へ積む**。
  アンカーは「平面上のどこを基準点に合わせるか」という 2 次元の概念なので、
  高さ方向へは持ち込まない。
- ダイアログには「左上 / 中央 / 右下」のプリセットボタンがある。

> 旧「中心揃え」チェックはアンカーへ統合して廃止した。
> 前回値の互換: `center_align: true` → アンカー 0.5、`false` → アンカー 0。
> **挙動変更**: 旧「中心揃え」は段（Y）も中央寄せしていたが、
> 新仕様では段は常に基準の高さから上へ積む。

#### 直線

| 項目 | 説明 |
| --- | --- |
| 個数 | 生成する点の数 |
| 方向 | 直線の方位 [度]（0 = +Z、90 = +X） |
| 間隔 | 点間の距離 [m] |
| 基準アンカー | 線に沿った 0〜1（0 = 始点が基準点 / 0.5 = 線の中心 / 1 = 終点が基準点） |

直線は 1 次元なので `anchor_x` だけを使う（`anchor_y` は無視される）。

#### ランダム散布

| 項目 | 説明 |
| --- | --- |
| 範囲 | 円（半径）または矩形（幅 X / 幅 Z） |
| 個数 | 目標個数 |
| 最小間隔 | 点同士の XZ 距離の下限 [m]。**拒否サンプリング**で保証する |
| 回転をランダムにする | ヨーを 0〜360 度でランダム化 |
| スケールばらつき | ±の割合（0.2 なら 0.8〜1.2 倍） |

最小間隔が厳しすぎて目標個数を置けない場合は、**置けた数まで減らしたうえで警告**する
（黙って減らさない）。円範囲は面積一様（半径に √ を掛ける）。

### 共通

| 項目 | 説明 |
| --- | --- |
| 位置ジッター | 各軸 ± この値 [m] だけランダムにずらす |
| 回転ジッター | ヨーを ± この値 [度] だけランダムにずらす |
| シード | 乱数の種。**同じ値なら常に同じ結果**。「ランダム」ボタンで引き直す |
| 進行方向を向く | 円形＝接線方向 / 直線＝線の方向 / グリッド・ランダム＝直前の点からの向き |
| 地形に接地させる | **3D の新規アクタ生成時のみ**。地表が見つからない点は基準の高さのまま |

ジッターはパターン本体とは**別の乱数ストリーム**（シードにソルトを XOR）を使う。
そのためジッター量を変えても散布位置そのものは動かない。

### 基準点＝カーソル位置（新規アクタ生成時）

基準点の選択肢（旧「対象アクタの位置 / ワールド原点」）は**廃止**した。
新規アクタ配置の基準点は常に**ビューポートのカーソル位置**で、
「配置」ボタンを押すと後述の**配置モード**へ入る。

制御点への追加では、点はもともとアクタ相対座標なので基準点そのものが無い
（従来どおりダイアログを閉じた時点で即座に末尾へ追記される）。

---

## 配置モード（カーソル位置へ置く）

ダイアログの「配置」を押すとダイアログが閉じ、ビューポートが**配置モード**になる。

```
[配置] を押す
  → LOGIC_PLACE_BEGIN:{json}（spec・配置元・親。基準点は含まない）
  → 配置モード開始（PLACEMENT_STATE:1）
       ├ 開始時: 生成予定のアクタ群を**実際にシーンへ仮スポーン**（Undo は積まない）
       ├ 毎フレーム: カーソルのレイで基準点を解決 → 仮スポーン群をそこへ移動
       ├ 左クリック  → そのまま採用（Undo 1 件）＋生成物を全選択 → 終了（PLACEMENT_STATE:0）
       └ 右クリック / Esc → 仮スポーンを削除して終了（PLACEMENT_STATE:0）
```

### 仮スポーン方式

プレビューは**線マーカーではなく本物のアクタ**である。
`LOGIC_PLACE_BEGIN` を受けた時点で、確定時とまったく同じ生成経路
（`spawn_placement_actors`）で新しいグループフォルダごとシーンへ置いてしまう。

| 場面 | やること |
| --- | --- |
| 開始 | 開始**直前**のアクタツリーを `before` として控える → 仮スポーン → `send_hierarchy` を 1 回 |
| 毎フレーム | 基準点が動いたフレームだけ、仮スポーン群の**位置だけ**を更新（`send_hierarchy` は送らない） |
| 確定 | `before` → 現在 を `ActorTreeSnapshotCommand` **1 件**で記録 → `SCENE_MODIFIED` → 全選択 |
| 取消 | 仮スポーンしたグループをサブツリーごと削除 → `send_hierarchy` を 1 回。**Undo 履歴は積まず `SCENE_MODIFIED` も送らない** |

こうする理由:

- **プレビュー＝結果**になる。メッシュの実寸・スケール・接地した高さが、
  置く前にそのまま見える（線マーカーでは分からなかった情報）。
- **Undo が 1 回で済む**。仮スポーンは履歴に載せず、確定時に「開始前 → 現在」を
  1 件記録するので、Ctrl+Z 一発でグループごと消える。
- シーンのダーティ（`SCENE_MODIFIED`）は**確定時のみ**。取消しただけで
  「未保存の変更あり」にはならない。

> **取消でツリー全体を再構築しない理由**
> スナップショットからの完全再構築（`rebuild_actors_for_wl`）は、その世界線の
> 全アクタを作り直す。取消は最も頻度の高い操作なので重すぎるうえ、
> プレビュー中にヒエラルキーで行った無関係な編集まで巻き戻してしまう。
> 実装は**自分が足したグループだけ**を正確に取り除くので、結果は開始前のツリーと
> 一致し（ユニットテストで固定）、副作用が無い。

移動はギズモドラッグ・モーダルトランスフォームと**同じ経路**
（`set_actor_world_transform` = 差分行列のサブツリー適用 + `instance_mats` 同期）を通る。
アクタツリーのフル再構築は起こさない。基準点が実質動いていないフレームでは
何もしないので、カーソルを止めている間はコストが掛からない。

### 基準点の決め方

| ビュー | 基準点 |
| --- | --- |
| 3D | カーソルのレイが当たった**メッシュ・水面（GPU ピック）／地形（CPU レイマーチ）の表面**。両方当たればカメラに近い方 |
| 3D（何にも当たらない） | **カメラからレイ方向へ一定距離**（アクタ D&D と同じ定数 `SPAWN_FALLBACK_DIST` = 10m） |
| 2D | カーソルのキャンバス座標（`window_to_canvas_2d`。2D ドロップ・2D ピックと同じ規約） |

「地形に接地させる」がオンなら、**各点が個別に**接地する（従来どおり）。
プレビューも確定と同じ接地関数を通すので、**マーカーが立っている高さに必ず置かれる**。

### プレビューの見え方

| 要素 | 見え方 |
| --- | --- |
| 配置元 = アクタファイル | **実物がそのまま見える**（仮スポーンした本物なので） |
| 配置元 = 空アクタ | 見た目を持たないので、**選択時と同じ人型アイコン**を全プレビューアクタに出す。色は水色寄りの半透明で、確定済みの選択マーカー（白・不透明）と区別できる |
| 基準点 | 白の大きめの十字（カーソルの着弾点そのもの。アンカーの効きが見える） |
| 半径ドラッグ中 | 水色の円＋中心から円周への 1 本（いま決めている半径） |

アイコンは選択マーカーと同じ 1 パス（`font/icon_overlay.rs`）で描く。
プレビュー対象は**選択状態にはしない**（頂点の色だけを変えて区別する）。

**旧仕様の点ごとの線マーカー（十字＋向き線）と 512 点の上限は撤去した。**
実物がそこに見えている以上、線マーカーを重ねると二重像になって却って読みにくく、
上限のせいで「見えている数と置かれる数が違う」という不一致も生んでいた。
残したのは基準点の十字と、半径ドラッグ中の円だけである。

### 操作ガイド（カーソル脇）

モード中はカーソルの右下に、いま何ができるかをテキストで出す
（`font/screen_hint.rs`。フォントシステムを使ったスクリーンスペース描画）。

| 状況 | 表示 |
| --- | --- |
| 通常 | `左クリック: 配置 / 右クリック: 取消` |
| 円形パターン（ドラッグ前） | ＋ `左ドラッグ: 半径を調整` |
| 半径ドラッグ中 | `ドラッグ: 半径 {現在値} m` / `離す: 配置` |

視認性のため、同じ文字列を暗色で 1.5px ずらして描いてから明色で重ねる（影付き）。
画面端ではガイドが見切れないよう内側へ寄せる。
プレイバーの既存ヒント（`MainWindow.Placement.cs`）はそのまま残してある。

### 半径ドラッグ（円形／円弧のみ）

円の半径は数値では決めにくいので、ビューポート上で直接引けるようにしてある。

```
左ボタン押下 → その位置を中心として固定
  ├ 押したままドラッグ（閾値 4px 以上動いた）
  │     → 中心とカーソルの**水平距離**が半径になる（プレビューの円が追従・ガイドに数値）
  │     → 離した時点で配置確定。決めた半径は PLACEMENT_RADIUS でエディタへ返る
  └ 押してすぐ離した（4px 未満）
        → クリック扱い。ダイアログの半径値へ戻して従来どおり即配置
```

- 半径は **Y を無視した水平距離**で決まる（丘の斜面でも「地図上の半径」になる）。
  中心と重なっても 0 にはならず、最小 0.01m で下支えする。
- 半径を変えても**点の個数は変わらない**ので、仮スポーンし直しは起きない
  （点列を引き直して位置を更新するだけ）。シードが同じなのでジッターの模様も保たれる。
- **円形以外のパターンは従来どおり押下した時点で配置**する（半径という概念が無いため）。

### モード中の排他

| 操作 | モード中の扱い |
| --- | --- |
| 左クリック | **確定**（通常の選択ピックは走らない）。円形パターンでは押下＝中心固定、解放＝確定 |
| 右クリック | **取消**（カメラ回転より優先。モード中はカメラを回せない） |
| Esc | **取消**（削除ダイアログには回らない） |
| ホイール／中ボタン | 無効（モード中は視点を固定する） |
| ギズモドラッグ・矩形選択・ホバー | 無効 |
| モーダルトランスフォーム（G/R/S） | 開始しない（相互に排他） |

> **カメラ操作との衝突について**: 取消は最も頻度の高い操作なので、
> 右クリックを「取消」に割り当て、**モード中は右ドラッグのカメラ回転を止める**。
> 視点を変えてから置きたい場合は、いったん取り消してからカメラを動かす。

Play 開始・シーン切り替え（`LOAD_SCENE`）・タブ（世界線）切り替えでは**自動で取り消す**。
取消は仮スポーンの削除まで含むので、Undo 履歴にもシーンのダーティにも影響しない。

### エディタ側の受け持ち

エディタが持つのは表示上の都合だけで、状態の正はランタイムにある。

- `PLACEMENT_STATE:1|0` を受けて `_placementModeActive` を更新（`MainWindow.Placement.cs`）
- モード中は Esc を `PLACEMENT_CANCEL` へ回す（`MainWindow.Input.cs` のキーフック）
- プレイバーに操作ヒント「配置モード: 左クリックで配置 / 右クリック・Esc で取消」を表示
- `PLACEMENT_RADIUS:{値}` を受けて `EditorPreferences.LogicPlacement.Radius` を更新し保存する
  （ダイアログは既に閉じているので、設定オブジェクトを直接書き戻すのが唯一の経路）

マウス操作はランタイムの子ウィンドウが直接受け取れるため、
モーダルトランスフォーム（`MainWindow.ModalTransform.cs`）のような
低レベルマウスフックは**使わない**。

### 確定後の選択

生成した**全アクタ**が選択状態になり、`SELECTED_MULTI:{仮想 ID 列}` で
ヒエラルキー／インスペクタへ同期される（プライマリは連番の末尾）。
置いた直後にそのままギズモやモーダルトランスフォームでまとめて動かせる。

## 生成結果

- 新しい**グループフォルダ**（名前 = パターン名。既存と重複する場合は `円形配置(2)` のように連番）
  が作られ、その配下に `パターン名_01`, `パターン名_02`, … として並ぶ。
- 2D 配置のグループは `CanvasTransform` を持つ 2D アクタになる
  （フォルダノードにするとスプライトの描画収集がサブツリーで打ち切られるため）。
- **Undo 1 件**（`ActorTreeSnapshotCommand`）でグループごと消える。
  制御点への追加は `ComponentSlotsSnapshotCommand` 1 件。

パラメータの前回値は `editor/settings/editor_preferences.json` の
`logic_placement` / `logic_placement_ground` に保存され、次に開いたときの初期値になる。
**基準点の選択は前回値に含まない**（常にカーソル位置なので記憶する対象が無い）。
アンカー導入前に保存された `center_align` は読み込み時にアンカーへ翻訳される。

## IPC 形式

エディタ → ランタイムへ **1 コマンド**だけ送る。

| コマンド | 用途 |
| --- | --- |
| `LOGIC_PLACE_BEGIN:{json}` | 新規アクタ配置。**配置モードへ入る**（基準点はカーソル位置で後から決まる） |
| `LOGIC_PLACE:{json}` | ControlPoint への即時追記（基準点を持たない）。`target` が `actors` の場合はワールド原点基準の直接生成 |
| `PLACEMENT_CANCEL` | 配置モードの取消（エディタの Esc から。仮スポーンも削除される） |

ランタイム → エディタ:

| メッセージ | 意味 |
| --- | --- |
| `PLACEMENT_STATE:1` / `PLACEMENT_STATE:0` | 配置モードの開始 / 終了 |
| `PLACEMENT_RADIUS:{f32}` | 半径ドラッグで確定した半径 [m]。ダイアログの前回値へ書き戻す（ドラッグしたときだけ送る） |
| `SELECTED_MULTI:{ids}` | 確定後、生成した全アクタの選択 |
| `LOAD_ERROR:{メッセージ}` | 警告（最小間隔・上限切り詰め・接地失敗など） |

`{json}` は両コマンドで**同じ本体**（`LogicPlaceRequest`）である。

`{json}` は 1 行（改行を含まない）。フィールドは以下のとおり。

| キー | 型 | 説明 |
| --- | --- | --- |
| `target` | string | `"actors"`（新規アクタ群）/ `"control_points"`（制御点へ追記） |
| `is_2d` | bool | 2D 配置か |
| `parent_dfs` | uint or null | グループを収める親アクタの DFS id（ルートなら null） |
| `group_name` | string | 生成するグループフォルダ名 |
| `name_prefix` | string | 生成アクタ名の接頭辞（`{prefix}_01` の形で連番） |
| `source_path` | string or null | 配置元アクタファイル（仮想パス）。null なら空アクタ |
| `ground` | bool | 地形へ接地させるか（3D のみ有効） |
| `actor_dfs_id` | uint | `control_points` 時の対象アクタ |
| `slot_idx` | uint | `control_points` 時の対象スロット |
| `spec` | object | パターン指定（下表） |

`spec` のフィールド（すべて省略可能。省略時は既定値）:

| キー | 型 | 既定 | 用途 |
| --- | --- | --- | --- |
| `pattern` | string | `"Circle"` | `Circle` / `Grid` / `Line` / `Random` |
| `count` | uint | 8 | 個数（Grid では未使用） |
| `seed` | u64 | 0 | 乱数シード |
| `jitter_pos` | f32 | 0 | 位置ジッター [m] |
| `jitter_rot` | f32 | 0 | 回転ジッター [度] |
| `face_forward` | bool | false | 進行方向を向く |
| `radius` | f32 | 5 | 円の半径 |
| `start_angle` | f32 | 0 | 開始角 [度] |
| `angle_span` | f32 | 360 | 角度範囲 [度] |
| `face_center` | bool | false | 中心を向く |
| `rows` / `cols` / `layers` | uint | 3 / 3 / 1 | グリッドの行・列・段 |
| `spacing_x` / `spacing_z` / `spacing_y` | f32 | 2 | 各方向の間隔 |
| `anchor_x` | f32 | 0.5 | 基準位置アンカー X（0〜1）。直線では線に沿ったアンカー |
| `anchor_y` | f32 | 0.5 | 基準位置アンカー Y（0〜1。3D では Z 軸 / 2D ではキャンバス Y） |
| `checker_offset` | bool | false | 市松オフセット |
| `line_angle` | f32 | 0 | 直線の方向 [度] |
| `line_spacing` | f32 | 2 | 直線の間隔 |
| `area_circle` | bool | true | ランダム範囲が円か（false = 矩形） |
| `area_radius` | f32 | 5 | 円範囲の半径 |
| `area_size_x` / `area_size_z` | f32 | 10 | 矩形範囲の幅 |
| `min_spacing` | f32 | 0 | 最小間隔 |
| `random_rotation` | bool | false | 回転をランダム化 |
| `scale_variance` | f32 | 0 | スケールばらつき（±割合） |

例:

```
LOGIC_PLACE_BEGIN:{"target":"actors","is_2d":false,"parent_dfs":3,"group_name":"円形配置","name_prefix":"円形配置","source_path":"assets://prefabs/tree.actor","ground":true,"actor_dfs_id":0,"slot_idx":0,"spec":{"pattern":"Circle","count":12,"seed":42,"radius":8.0,"angle_span":360.0,"face_center":true}}
```

警告（最小間隔が満たせない・上限で切り詰めた・接地できなかった等）は
既存のエラートースト経路 `LOAD_ERROR:{メッセージ}` で返る。

### なぜ 1 コマンドなのか

点列の生成そのものは C# でもできるが、**地形接地とアクタ生成はランタイムにしか
材料が無い**（密度場・ECS・プレハブ構築）。点ごとに IPC を往復させると Undo が
多数件に割れ、途中で失敗したときに半端な状態が残る。
「1 コマンド = 1 Undo」を守るため、パターン指定だけを送って残りを任せる。

### 二重実装について

プレビューは IPC 往復を挟むと即時性が出せないため、C# 側にも同じアルゴリズムを持つ。
**正典は Rust 側**であり、実際にシーンへ置かれる点は必ずランタイムが生成する。
一致は双方のユニットテストが**同じ既知入力の期待値**で固定している。

```bash
cargo test --manifest-path runtime/Cargo.toml placement          # Rust 側
dotnet run --project editor/tests/PlacementTests                 # C# 側（Rust と同じ既知ベクタ）
```

片方のアルゴリズムを変えたら必ず両方を直し、既知ベクタも同時に更新すること
（片方だけ直すとどちらかのテストが落ちる）。

乱数は splitmix64（`PlacementRng`）。`rand` クレートや `System.Random` を使わないのは、
どちらも実装がバージョンに依存し、Rust と C# を一致させられないため。
