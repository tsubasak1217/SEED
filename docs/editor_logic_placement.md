# ロジック配置

規則的な配置（円形・グリッド・直線・ランダム散布）を **1 操作・Undo 1 件** で作る機能。
新規アクタ群の生成と、`ControlPoint` の点列への一括追加の 2 つに使える。

---

## 導線

### 1. ヒエラルキー右クリック → 「アクタを追加」

```
アクタを追加
 ├ 3D アクタ            … 従来どおり 1 クリックで 1 体追加
 ├ 2D アクタ            … 同上
 └ ロジック配置          … ダイアログを開く
    ├ 3D アクタ
    └ 2D アクタ
```

- 空きスペースを右クリック → 生成グループは**ルート直下**へ入る。
- アクタを右クリック → 生成グループは**そのアクタの子**へ入る
  （このときサブメニューは `2D アクタ / 3D アクタ → 親としてラップ / 子として追加` の
  下に「ロジック配置」が並ぶ）。
- **通常の追加操作は 1 クリックのまま**。ロジック配置だけが 1 段下がる。

無効化される場合:

| 状況 | 挙動 |
| --- | --- |
| キャンバス編集タブでルートを右クリック | 「3D アクタ」が無効（理由をツールチップ表示） |
| 2D アクタを右クリック | 「3D アクタ」が無効（3D は 2D の子になれない） |

### 2. インスペクタ → ControlPoint → 「ロジック配置で点を追加…」

同じダイアログを **配置元・基準点の選択を隠した状態**で開く。
生成した点列は既存の点列の**末尾へ追記**される（時刻は既存の続きから連番）。
上限（`MAX_CONTROL_POINTS` = 256 点）を超えるぶんは切り詰め、件数を警告として通知する。

---

## ダイアログ

左がパラメータ、右が**真上から見たプレビュー**（画面の右が +X、上が +Z）。
パラメータを変えるとプレビューが即座に更新される。

### 配置元（新規アクタ生成時のみ）

| 選択 | 生成されるもの |
| --- | --- |
| 空アクタ | Transform（3D）または CanvasTransform（2D）だけを持つ空のアクタ |
| アクタファイル | 選択した `.actor`（3D）/ `.actor2d`（2D）から構築したプレハブインスタンス |

アクタファイル由来のアクタは `prefab_source` を持つので、
「プレハブから更新」「シーン内の全プレハブを更新」の対象になる。

### パターンとパラメータ

すべてのパターンは **XZ 平面**上に点を作る（Y は「段」）。
2D 配置では `(X, Z)` をキャンバスの `(X, Y)` へ写す。

#### 円形／円弧

| 項目 | 説明 |
| --- | --- |
| 個数 | 生成する点の数 |
| 半径 | 中心からの距離 [m] |
| 開始角 | 最初の点の角度 [度]（0 = +X 方向） |
| 角度範囲 | 360 で全周。360 未満は円弧になり**両端に点が置かれる** |
| 中心を向く | 各点のヨーが中心を向く（「進行方向を向く」より優先） |

全周のときは始点と終点が重ならないよう、角度の分母を「個数」にする
（円弧のときは「個数 − 1」で両端を含める）。

#### グリッド

| 項目 | 説明 |
| --- | --- |
| 行 / 列 / 段 | Z 方向 / X 方向 / Y 方向の個数（**段は 3D のみ**） |
| 間隔 X / Z / Y | 各方向の間隔 [m]（2D では「間隔 Y」が第 2 軸の間隔になる） |
| 中心揃え | 基準点をグリッドの中心に置く（オフなら基準点が隅） |
| 市松オフセット | 奇数行を X 方向へ半間隔ずらす |

走査順は **段 → 行 → 列**。この順が生成アクタの連番（`_01`, `_02`, …）になる。

#### 直線

| 項目 | 説明 |
| --- | --- |
| 個数 | 生成する点の数 |
| 方向 | 直線の方位 [度]（0 = +Z、90 = +X） |
| 間隔 | 点間の距離 [m] |
| 基準点を線の中心にする | オンで線の中心が基準点、オフで基準点が始点 |

#### ランダム散布

| 項目 | 説明 |
| --- | --- |
| 範囲 | 円（半径）または矩形（幅 X / 幅 Z） |
| 個数 | 目標個数 |
| 最小間隔 | 点同士の XZ 距離の下限 [m]。**拒否サンプリング**で保証する |
| 回転をランダムにする | ヨーを 0〜360 度でランダム化 |
| スケールばらつき | ±の割合（0.2 なら 0.8〜1.2 倍） |

最小間隔が厳しすぎて目標個数を置けない場合は、**置けた数まで減らしたうえで警告**する
（黙って減らさない）。円範囲は面積一様（半径に √ を掛ける）。

### 共通

| 項目 | 説明 |
| --- | --- |
| 位置ジッター | 各軸 ± この値 [m] だけランダムにずらす |
| 回転ジッター | ヨーを ± この値 [度] だけランダムにずらす |
| シード | 乱数の種。**同じ値なら常に同じ結果**。「ランダム」ボタンで引き直す |
| 進行方向を向く | 円形＝接線方向 / 直線＝線の方向 / グリッド・ランダム＝直前の点からの向き |
| 地形に接地させる | **3D の新規アクタ生成時のみ**。地表が見つからない点は基準の高さのまま |

ジッターはパターン本体とは**別の乱数ストリーム**（シードにソルトを XOR）を使う。
そのためジッター量を変えても散布位置そのものは動かない。

### 基準点（新規アクタ生成時のみ）

| 選択 | 意味 |
| --- | --- |
| 対象アクタの位置 | 右クリックしたアクタの位置を原点にする（ルート右クリック時は選べない） |
| ワールド原点 / キャンバス中心 | 原点 `(0, 0, 0)` を基準にする |

制御点への追加では、点はもともとアクタ相対座標なので基準点の選択は無い（常に原点基準）。

## 生成結果

- 新しい**グループフォルダ**（名前 = パターン名。既存と重複する場合は `円形配置(2)` のように連番）
  が作られ、その配下に `パターン名_01`, `パターン名_02`, … として並ぶ。
- 2D 配置のグループは `CanvasTransform` を持つ 2D アクタになる
  （フォルダノードにするとスプライトの描画収集がサブツリーで打ち切られるため）。
- **Undo 1 件**（`ActorTreeSnapshotCommand`）でグループごと消える。
  制御点への追加は `ComponentSlotsSnapshotCommand` 1 件。

パラメータの前回値は `editor/settings/editor_preferences.json` の
`logic_placement` / `logic_placement_ground` に保存され、次に開いたときの初期値になる。

## IPC 形式

エディタ → ランタイムへ **1 コマンド**だけ送る。

```
LOGIC_PLACE:{json}
```

`{json}` は 1 行（改行を含まない）。フィールドは以下のとおり。

| キー | 型 | 説明 |
| --- | --- | --- |
| `target` | string | `"actors"`（新規アクタ群）/ `"control_points"`（制御点へ追記） |
| `is_2d` | bool | 2D 配置か |
| `parent_dfs` | uint or null | グループを収める親アクタの DFS id（ルートなら null） |
| `base` | string | `"parent"`（対象アクタ位置）/ `"origin"`（原点） |
| `group_name` | string | 生成するグループフォルダ名 |
| `name_prefix` | string | 生成アクタ名の接頭辞（`{prefix}_01` の形で連番） |
| `source_path` | string or null | 配置元アクタファイル（仮想パス）。null なら空アクタ |
| `ground` | bool | 地形へ接地させるか（3D のみ有効） |
| `actor_dfs_id` | uint | `control_points` 時の対象アクタ |
| `slot_idx` | uint | `control_points` 時の対象スロット |
| `spec` | object | パターン指定（下表） |

`spec` のフィールド（すべて省略可能。省略時は既定値）:

| キー | 型 | 既定 | 用途 |
| --- | --- | --- | --- |
| `pattern` | string | `"Circle"` | `Circle` / `Grid` / `Line` / `Random` |
| `count` | uint | 8 | 個数（Grid では未使用） |
| `seed` | u64 | 0 | 乱数シード |
| `jitter_pos` | f32 | 0 | 位置ジッター [m] |
| `jitter_rot` | f32 | 0 | 回転ジッター [度] |
| `face_forward` | bool | false | 進行方向を向く |
| `radius` | f32 | 5 | 円の半径 |
| `start_angle` | f32 | 0 | 開始角 [度] |
| `angle_span` | f32 | 360 | 角度範囲 [度] |
| `face_center` | bool | false | 中心を向く |
| `rows` / `cols` / `layers` | uint | 3 / 3 / 1 | グリッドの行・列・段 |
| `spacing_x` / `spacing_z` / `spacing_y` | f32 | 2 | 各方向の間隔 |
| `center_align` | bool | true | 中心揃え（直線でも使う） |
| `checker_offset` | bool | false | 市松オフセット |
| `line_angle` | f32 | 0 | 直線の方向 [度] |
| `line_spacing` | f32 | 2 | 直線の間隔 |
| `area_circle` | bool | true | ランダム範囲が円か（false = 矩形） |
| `area_radius` | f32 | 5 | 円範囲の半径 |
| `area_size_x` / `area_size_z` | f32 | 10 | 矩形範囲の幅 |
| `min_spacing` | f32 | 0 | 最小間隔 |
| `random_rotation` | bool | false | 回転をランダム化 |
| `scale_variance` | f32 | 0 | スケールばらつき（±割合） |

例:

```
LOGIC_PLACE:{"target":"actors","is_2d":false,"parent_dfs":3,"base":"parent","group_name":"円形配置","name_prefix":"円形配置","source_path":"assets://prefabs/tree.actor","ground":true,"actor_dfs_id":0,"slot_idx":0,"spec":{"pattern":"Circle","count":12,"seed":42,"radius":8.0,"angle_span":360.0,"face_center":true}}
```

警告（最小間隔が満たせない・上限で切り詰めた・接地できなかった等）は
既存のエラートースト経路 `LOAD_ERROR:{メッセージ}` で返る。

### なぜ 1 コマンドなのか

点列の生成そのものは C# でもできるが、**地形接地とアクタ生成はランタイムにしか
材料が無い**（密度場・ECS・プレハブ構築）。点ごとに IPC を往復させると Undo が
多数件に割れ、途中で失敗したときに半端な状態が残る。
「1 コマンド = 1 Undo」を守るため、パターン指定だけを送って残りを任せる。

## 実装

| 層 | 場所 | 責務 |
| --- | --- | --- |
| パターン生成（正典） | `runtime/src/engine/placement/` | 決定的な点列生成の純関数。ECS・IPC・地形に依存しない |
| 実行 | `runtime/src/engine/core/app_base/app/logic_placement_ops.rs` | 接地・アクタ生成・制御点追記・Undo |
| IPC | `runtime/src/engine/core/app_base/ipc.rs`（`IpcCommand::LogicPlace`） | コマンドのパース |
| ダイアログ | `editor/src/Placement/` | パラメータ編集とプレビュー |
| パターン生成（写し） | `editor/src/Placement/Patterns/` | プレビュー専用。WPF 非依存 |

### 二重実装について

プレビューは IPC 往復を挟むと即時性が出せないため、C# 側にも同じアルゴリズムを持つ。
**正典は Rust 側**であり、実際にシーンへ置かれる点は必ずランタイムが生成する。
一致は双方のユニットテストが**同じ既知入力の期待値**で固定している。

```bash
cargo test --manifest-path runtime/Cargo.toml placement          # Rust 側
dotnet run --project editor/tests/PlacementTests                 # C# 側（Rust と同じ既知ベクタ）
```

片方のアルゴリズムを変えたら必ず両方を直し、既知ベクタも同時に更新すること
（片方だけ直すとどちらかのテストが落ちる）。

乱数は splitmix64（`PlacementRng`）。`rand` クレートや `System.Random` を使わないのは、
どちらも実装がバージョンに依存し、Rust と C# を一致させられないため。
