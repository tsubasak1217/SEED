# エディタ ワールド/ビューポート シーンタブ分離 — 設計仕様

エディタのシーンパネル（旧称ビューポートパネル）を「ワールド」「ビューポート」の
タブに分離する機能の確定仕様。
（2026-07-07 ユーザー承認済み。2026-07-08 タブ名称・自動切替キーを改訂。
実装時はこのドキュメントを正典とする）

## world / viewport 概念（分類の考え方）

オブジェクトは表示のされ方で 2 種類に分類される:

- **ワールド (world)**: カメラに撮られて相対的に映るもの。
  3D アクターに加え、**3D ワールドキャンバス上の 2D スプライトも含む**
  （キャンバスごと 3D 空間に置かれ、カメラとの位置関係で見え方が変わるため）。
- **ビューポート (viewport)**: 画面/カメラ枠基準で張り付くもの。
  スクリーンスペースキャンバスとその子孫。カメラがどこを向いていても
  最終フレームに対して固定でオーバーレイされる。

判定基準は「アクターのトップレベルルートが Actor2D（スクリーンスペース
キャンバス系）か」であり、Actor2D/Actor3D の種別そのものではない点に注意。

## 目的

3D ビューポート空間に 2D キャンバスが「板」として表示される違和感を解消する。
ワールドタブにはワールド所属オブジェクトのみを表示し、ビューポート所属
オブジェクトは専用タブでスクリーンスペース表示（ゲームの最終見た目 = WYSIWYG）
のまま編集する。

## パネル・タブ構成

- ランタイムビューをホストする AvalonDock パネルの表示タイトルは**「シーン」**
  （ContentId は保存レイアウト互換のため "viewport" のまま変更しない）
- 既存のアクター編集タブのタブバーに固定 2 タブを常設する:
  - **「ワールド」**（旧「3Dシーン」）: ワールド所属のみ表示
    （スクリーンスペースキャンバスは非表示）
  - **「ビューポート」**（旧「2Dシーン」）: 全スクリーンスペースキャンバスを
    重ね表示（ゲームでの最終合成と同じ見え方）。ワールドは表示しない
  - アクター編集タブ・キャンバス編集タブはその右に並ぶ
- IPC のワイヤフォーマットは内部表現のため従来どおり `EDIT_VIEW:3d`（ワールド）/
  `EDIT_VIEW:2d`（ビューポート）を使用する
- タブ分離は **Edit モード限定**。Play 中は従来どおり 3D + UI の最終合成を表示する

## 3D ワールドキャンバスの扱い

- Actor3D + CanvasComponent（3D 空間配置のキャンバス）は **ワールドタブに表示**する
  （その配下の 2D スプライトもワールド所属として扱う）
- その中身（スプライト配置）の編集は、**インスペクタのボタン**から
  「キャンバス編集タブ」（アクター編集タブと同様の隔離タブ・2D 表示）を開いて行う
  - ダブルクリックでは開かない（誤操作防止）
  - このボタンは 2D のスクリーンスペースキャンバスにも同様に付ける（個別編集したい場合用）

## ヒエラルキー・選択との連動

- ヒエラルキーは共通のまま（タブで絞り込まない。2D/3D 両方を 1 つの階層に表示）
- アクターを選択したら、その**ビューポート所属**（HIERARCHY JSON の `is_vp`:
  トップレベルルートが Actor2D のサブツリーか）に応じて対応タブへ**自動切替**する
  - Actor2D/Actor3D 種別（`is_2d`。アイコン色分け用）ではなく所属で判定するため、
    3D ワールドキャンバス配下の 2D スプライトを選択するとワールドタブへ切り替わる
  - ワールドとビューポートの**混在複数選択**時は切替しない
  - 自動切替は環境設定（EditorPreferences）でオン/オフ可能。既定はオン
- Undo/Redo は共通履歴（実行してもタブは自動で飛ばさない）

## ドラッグ＆ドロップ

- プロジェクトパネルからのドラッグ中、**ドロップ前の段階で**アクタの種類に応じてタブを自動切替する
  （切替後にドロップ位置を決められるようにするため）
  - 種類判定: 拡張子で行う（`.actor2d` = ビューポートタブ / `.actor` = ワールドタブ）
  - ドロップせずキャンセルした場合（Esc・枠外リリース）は**元のタブへ戻す**（仮切替扱い）
- 2D アクタのドロップ配置:
  - **アクタ保存時にルートの CanvasTransform（ローカル座標）は 0 で保存する**
    （3D の .actor が既にルート Transform を 0 化しているのと同じ規則）
  - ドロップ時はカーソルのスクリーン座標をキャンバス座標へ変換して position を設定する
  - **アクタファイルのルートに Canvas がアタッチされていない場合**:
    シーン内の既存キャンバスの子として入れる。どのキャンバスに入るかは
    **カーソルがヒットしているキャンバス矩形**で決める（ヒット中のキャンバスは
    枠線を明るく太くして視覚化する）
  - **ルートに Canvas がある場合**: そのままルートとして配置する

## カメラ・ナビゲーション

- タブごとにカメラ状態を保持・復元する:
  - ワールド: 既存のデバッグカメラ
  - ビューポート: 2D パン・ズーム（既存の canvas_cameras を流用）
- ビューポートタブではカメラ操作を 2D 用（パン・ズームのみ）に切り替える

## 実装メモ（既存部品）

- `canvas_screen_space_overlay`（App）: スクリーンスペース表示切替が既にある
- `canvas_cameras[world_line]`: 2D 正射影カメラ（パン・ズーム）が既にある
- `actor_edit_canvas_wls` / アクター編集タブ: 隔離タブの仕組みが既にある
- `pick_2d`: 2D ピッキングが既にある
- IPC で `EDIT_VIEW:3d` / `EDIT_VIEW:2d` のようなビューモード切替コマンドを追加し、
  ランタイム側で描画パス・ピッキング・ギズモ・カメラ操作を分岐する

## 段階実装計画

1. **Phase 1（ランタイム）**: ビューモード（Edit3D / Edit2D）の導入。
   描画フィルタ（3D ビューでスクリーンスペースキャンバス非表示 / 2D ビューで 3D 非表示・
   スクリーンスペース重ね表示）、カメラ・ピッキング・ギズモの分岐、IPC コマンド
2. **Phase 2（エディタ）**: タブバー（ワールド/ビューポート固定タブ）、選択連動の自動切替、
   ドラッグ中の仮切替と復帰、環境設定トグル
3. **Phase 3**: 2D アクタのドロップ配置（座標変換・キャンバスヒット判定・枠線ハイライト）、
   .actor2d 保存時のルート座標 0 化
4. **Phase 4**: インスペクタの「キャンバスを編集」ボタン（キャンバス編集タブを開く。
   3D ワールドキャンバス・2D キャンバス共通）

## 2D 編集でのピック（クリック選択）対象

CPU ピック（`runtime/src/engine/core/app_base/app/pick_2d.rs` の `walk_pick_candidates_2d`）が
候補にするコンポーネントと判定形状は次のとおり。優先度は
「表示物 > Canvas」→「前面ゾーン優先」→「深い階層優先」→「DFS 後方（＝最前面）優先」。

| コンポーネント | 判定形状 | 変換 | ポインタイベント（Play） |
| --- | --- | --- | --- |
| `SpriteComponent` | 幅×高さの矩形 | `to_sprite_mat4` | `raycast_target` が true のときのみ |
| `SkinnedSpriteComponent` | 変形後メッシュの三角形 | `to_mesh_mat4` | `raycast_target` が true のときのみ |
| `TextComponent` | 実測したテキストブロック枠 | `to_mesh_mat4` | **対象外**（オプトインする項目が無いため） |
| `CanvasComponent` | キャンバス矩形（補助候補） | `to_mat4_sized` | 対象外 |

テキストの枠は `runtime/src/engine/core/font/text_layout.rs::measure_text_box` が
`font_size` / `line_spacing` / `align` / `vertical_align` から求める
（描画 `canvas_text.rs` と同じ規則・同じ送り幅。`FontSystem::advance_em` もこの関数へ委譲）。
実測にはフォント実体が要るので、走査の前に
`App::build_text_bounds_map`（`canvas_text_bounds.rs`）が
「Text スロット entity → ローカル境界矩形」の表を作り、
ピック（`pick_2d`）と選択アウトライン（`canvas_collect::collect_canvas_rects`）が
**同じ表**を引く。したがって「枠は出るのにクリックできない」ズレは起きない。

矩形選択（`collect_canvas_actors_in_rect`）は形状ではなく `CanvasTransform.position` の
点包含で判定するため、テキストを含む全ての 2D アクターが元から対象になっている。
