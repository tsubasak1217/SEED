# 水面シェーディングアセット（Phase W8・契約 v1）

ユーザーが書いた WGSL ファイル 1 枚で、**水面 1 ピクセルの最終色**を差し替える仕組み。
マグマ・毒沼・スライム・血の池などを「アセットの差し替えだけ」で作るための土台である。

**使い方は「WaterVolume の『水面シェーダ』に .wgsl を 1 枚差すだけ」**。
その水域だけが指定したアセットの色で描かれ、他の水域は影響を受けない。

- 実装: `runtime/src/engine/core/renderer/water/shading_asset.rs`（ロード・検証・生成・キャッシュ）
- 契約の正典: `runtime/src/engine/core/renderer/shaders/water_shading_contract.wgsl`
- 既定ディスパッチ: `runtime/src/engine/core/renderer/shaders/water_shade_dispatch.wgsl`
- 呼び出し側: `runtime/src/engine/core/renderer/shaders/water_surface.wgsl`（`fs_water`）
- 連結順の正典: `runtime/src/engine/core/renderer/pipelines/water_surface.toml`
- バケット分割と描画: `runtime/src/engine/core/renderer/water/mod.rs`（`WaterRenderer`）
- 同梱サンプル: `runtime/assets/shaders/magma.wgsl` / `runtime/assets/shaders/poison.wgsl`

> 表記ルール: 本ドキュメントは実装から確認した事実のみを書く。記載の関数名・定数名・既定挙動は
> すべて上記ソースが正典であり、食い違ったらソース側が正しい。

## 1. 概要

### できること

- **水域ごとに水面の色の作り方を丸ごと差し替えられる**。同じシーンにマグマ池と普通の湖と
  毒沼を同時に置ける（水域ごとに別のアセットを指定できる）。
- エンジンが渡すのは `WaterShadeInput` という 1 つの構造体だけで、
  バインディング（uniform / texture / storage）は一切見えない。
- **エンジン標準の見た目を `water_shade_default()` として呼べる**。
  「標準の水を作ってから少しだけ加工する」書き方も、
  「吸収だけ標準を流用して残りは自作」という部分流用もできる。
- ファイルを保存するだけで再コンパイルされる（ホットリロード）。Edit は常時、
  Play 中もエディタ設定「Play中もシェーダをホットリロード」（既定オン）で有効。
  この設定は L3-a のシェーディングアセットと**共有**である。
- 構文エラー・契約バージョン不一致はエディタへ**アセット内の行番号付きで**通知され、
  その水域は自動的にエンジン標準へフォールバックする（画面は壊れない）。

### できないこと（設計上の境界）

**アセットが変えられるのは「色」だけである。** 以下は共有の高さ場
（`water_height_field.wgsl`）が正典で、アセットからは一切変更できない。

| 変えられないもの | 正典 | 理由 |
|---|---|---|
| 水面の格子・頂点変位・波の高さ場 | `water_height_field.wgsl` | ID パス・水面反射パスと**同じ関数**を呼んで形状を一致させている |
| ピック形状（エディタのクリック判定） | `water_id.wgsl` | 見た目とピック形状が食い違うと選択できない水域が生まれる |
| 反射像そのもの（何が映るか） | `water_reflection_*.wgsl` | 別パスで焼く。アセットは焼けた結果を**どれだけ混ぜるか**だけ決められる |
| 水中コースティクス（水底の光模様） | `caustics.wgsl` | 水面の裏で光を集める計算で、色の合成とは別の物理 |
| 波・流れ・粘度・波紋の物性 | `WaterVolume` の各パラメータ | シーン側の設定であり、アセットは値を**読む**だけ |

つまりアセットは「エンジンが集めた材料（厚み・泡・反射・屈折・法線…）を、
どう混ぜて 1 つの色にするか」だけを担当する。

## 2. 最小のアセット

```wgsl
// @water_shading_contract 1

fn water_shade(input: WaterShadeInput) -> vec4<f32> {
    return water_shade_default(input);
}
```

これはエンジン標準とまったく同じ見た目になる（＝アセットの雛形）。
1 行目の契約バージョン宣言は**必須ではないが強く推奨**（無いと警告が 1 回出る。3 章）。

「標準の水を少しだけ緑へ寄せる」なら:

```wgsl
// @water_shading_contract 1
const TINT_COLOR: vec3<f32> = vec3<f32>(0.2, 0.9, 0.35);

fn water_shade(input: WaterShadeInput) -> vec4<f32> {
    let base  = water_shade_default(input);
    let depth = water_shade_saturate(input.thickness / max(input.absorption_distance, 0.01));
    return vec4<f32>(mix(base.rgb, base.rgb * TINT_COLOR, depth), base.a);
}
```

## 3. 契約 v1

### 3.1 実装すべき関数

```wgsl
fn water_shade(input: WaterShadeInput) -> vec4<f32>
```

**この 1 本だけ**である。返り値は `rgb` = リニア HDR の最終色、`w` = アルファ。

> **アルファについて**: 水面パスのブレンドは `Replace` で、背景（屈折グラブ）の合成は
> アセット自身が行う。したがってアルファは HDR RT の a チャンネルへ書かれるだけで、
> **現在は合成に使われない**。標準実装は常に 1.0 を返す。契約 v1 では将来のための予約枠である。

### 3.2 契約バージョン宣言

アセットの先頭コメントに次の 1 行を書く。

```wgsl
// @water_shading_contract 1
```

- 宣言が無い → v1 とみなして読み込み、警告を 1 回通知する。
- 宣言があってエンジンと版が違う → **読み込まず**エンジン標準へフォールバックし、
  1 行目を指すエラーを通知する。

このマーカーは L3-a のシェーディングアセット（`// @shading_contract 1`）とは
**別のマーカー**である。エディタの WGSL 検証は、この宣言の有無で
「水面シェーディング契約として検証するか、L3-a の契約として検証するか」を切り替える
（IPC に種別パラメータは無い。ファイル内容が唯一の判別材料）。

### 3.3 `WaterShadeInput` の全フィールド

単位系は一貫してワールド空間・メートル・秒・リニア色。

#### 幾何

| フィールド | 型 | 意味 |
|---|---|---|
| `world_pos` | `vec3<f32>` | このフラグメントのワールド座標（頂点変位後の水面上の点） |
| `normal` | `vec3<f32>` | 波法線（正規化済み）。解析波・プロシージャルノイズ・波紋・岸波の**勾配を合算**した法線で、**常に視線側を向く**（水中視点では反転済み）。フレネル・屈折はこれで評価する |
| `normal_up` | `vec3<f32>` | 上向き基準の生の法線（反転していない）。水面の傾きそのものが欲しいとき用 |
| `view_dir` | `vec3<f32>` | フラグメント → カメラ方向の単位ベクトル |
| `underwater` | `bool` | カメラが水面より下（＝水面を裏側から見ている）か |

#### 水の厚み

| フィールド | 型 | 意味 |
|---|---|---|
| `thickness` | `f32` | 水面点から水底（シーン深度が示す背景点）までの距離 [m]。背景が空のときは「十分深い」を表す大きな値。`underwater = true` では **0** |

#### 泡（すべて 0..1・水中視点ではゼロ）

| フィールド | 型 | 意味 |
|---|---|---|
| `foam` | `f32` | 岸フォーム量。水深が `foam_width` 未満の帯で立ち上がり、強度を掛け済み |
| `ripple_foam` | `f32` | 航跡フォーム量（インタラクションの波紋が高い所） |
| `shore_foam` | `f32` | 岸波の泡量（砕け波の白帯と打ち上げ） |
| `ripple_height` | `f32` | 波紋の生の波高 [m]。符号付き。独自の泡表現用 |

#### 背景と反射（すでにサンプル済み）

| フィールド | 型 | 意味 |
|---|---|---|
| `refraction_color` | `vec3<f32>` | 屈折（グラブ）サンプル。波法線で UV をずらして読んだ**水中の背景色**。岸際で歪み先が不正になるケースはエンジン側で補正済み |
| `reflection_color` | `vec3<f32>` | 反射サンプルの色。プリマルチプライドの逆算済み＝素の反射色 |
| `reflection_strength` | `f32` | 反射の強度 0..1。反射パスが走らないフレーム・非対応 GPU・`reflection_intensity = 0` の水域では 0。**必ずこの値を掛けること**（掛けないと反射なしの画素で黒が滲む） |

#### 流れと時間

| フィールド | 型 | 意味 |
|---|---|---|
| `flow` | `vec2<f32>` | 流速ベクトル（ワールド XZ・[m/s]）。川以外の水域ではゼロ |
| `time` | `f32` | ゲーム内累計時間 [秒]。明滅・スクロールに使う |

#### 水域パラメータ（インスペクタの設定値）

| フィールド | 型 | 意味 |
|---|---|---|
| `shallow_color` | `vec3<f32>` | 浅場の色 |
| `deep_color` | `vec3<f32>` | 深場の色 |
| `absorption_distance` | `f32` | 吸収距離 [m] |
| `surface_opacity` | `f32` | 深場での最大不透明度 0..1 |
| `foam_color` | `vec3<f32>` | 泡の色（3 種の泡が共有） |
| `fresnel_power` | `f32` | フレネル指数 |
| `fresnel_strength` | `f32` | フレネル寄与率 0..1 |
| `wave_amplitude` | `f32` | 波の振幅 [m]（形状には反映済み。色側で荒れ具合を測る用） |
| `viscosity` | `f32` | 粘度 0..1（0 = 水 / 1 = 溶岩・スライム）。波速と波紋減衰へ既に反映済みで、**色には自動で効かない**。粘つく艶を出したいアセットが自分で使う |

> フィールドの**追加は末尾へ**行い、契約バージョンは上げない（既存アセットは壊れない）。
> 削除・意味の変更は契約バージョンを上げること。

### 3.4 呼べる標準ライブラリ

| 関数 | 意味 |
|---|---|
| `water_shade_default(input) -> vec4<f32>` | **エンジン標準の水の見た目**（Phase W7 までの合成と完全に同一） |
| `water_shade_fresnel(n, v, power, strength) -> f32` | Schlick 近似のフレネル項（標準実装が使うものと同一） |
| `water_shade_absorption(thickness, distance) -> f32` | Beer-Lambert 近似の透過率（吸収だけ流用したいとき） |
| `water_shade_saturate(x) -> f32` | 0..1 への飽和 |
| `water_shade_luminance(c) -> f32` | Rec.709 の相対輝度 |
| `water_shade_hash21(p) -> f32` | 決定的な擬似乱数（0..1） |
| `water_shade_value_noise(p) -> f32` | バイリニア補間の値ノイズ（0..1） |
| `water_shade_fbm(p) -> f32` | 4 オクターブの fBm ノイズ。溶岩の亀裂・毒の澱みなどの模様に |
| `water_shade_nan_guard(c) -> vec4<f32>` | NaN/Inf/負値のガード（エンジンが自動で掛けるので通常は不要） |

加えて、共有高さ場（`water_height_field.wgsl`）の定数 `WATER_EPSILON` も使える。

### 3.5 `water_shade_default` の中身

標準実装は次の順で色を作る（アセットが部分流用しやすいよう、式をそのまま示す）。

```wgsl
// ① 吸収（Beer-Lambert 近似）
let absorb = exp(-thickness / max(absorption_distance, WATER_EPSILON));
let tint   = mix(deep_color, shallow_color, absorb);
// ② 背景合成
let opacity = clamp(surface_opacity, 0.0, 1.0) * (1.0 - absorb);
var color   = mix(refraction_color, tint, opacity);
// ③ 泡（3 種とも同じ foam_color）
color = color + foam_color * (foam + ripple_foam + shore_foam);
// ④ フレネル
let fresnel = water_shade_fresnel(normal, view_dir, fresnel_power, fresnel_strength);
// ⑤ 反射像の混合
color = mix(color, reflection_color, fresnel * clamp(reflection_strength, 0.0, 1.0));
return vec4<f32>(color, 1.0);
```

## 3.5 パラメータ宣言 — インスペクタから触れる値を作る（Phase W8.2）

アセットに **`override` 宣言**を書くと、その水域のインスペクタに編集行が生えて、
値を**水域ごと**に設定できるようになる。同じ `magma.wgsl` を差した 2 つの池に
別の発光色を設定する、といった使い方ができる。

> **旧構文（`//! param` コメント）は廃止**（W5.2）。ただのコメントとして無視されるので、
> 古いアセットはインスペクタ行が出なくなる。下の構文へ書き換えること。

> **この構文は L3 シェーディングアセットと共通である**。解析の実装は 1 本だけで
> （`runtime/src/engine/core/renderer/shade_params.rs`）、水面と L3 の違いは
> 「予約接頭辞」を持つ `ShadeParamDialect` というデータだけである
> （水面 = `water_shade` / `u_water` / `WATER_`、L3 = `shade_` / `shading_` / `SHADING_` /
> `u_shading` / `u_camera`）。属性・上限・インスペクタ行の見た目・IPC のワイヤ表現も同一。
> L3 側の説明は `docs/shading_asset.md` の 5.5 / 5.6 節。
>
> GPU への運び方だけが違う: 水面は**水域ごとに値が要る**のでストレージバッファの配列
> （group1 binding7）、L3 は**カメラ／シーンにつき 1 セット**でよいので uniform 1 本
> （group2 binding0）である。

### 3.5.1 構文

```wgsl
@color
override emission_color: vec3<f32> = vec3(1.0, 0.4, 0.1);  // 発光色

@range(0.0, 10.0) @reset
override crack_speed: f32 = 1.5;                           // 亀裂の流速

override glow_boost: f32 = 2.0;                            // 属性なし = 数値行
```

| 属性 | 型 | インスペクタの行 |
|---|---|---|
| `@color` | `vec3<f32>` | カラーピッカー（リニア RGB） |
| `@range(min, max)` | `f32` | スライダー＋数値ボックス |
| （属性なし） | `f32` | 数値行（範囲なし・ドラッグ可） |
| `@reset` | 併記 | 行の右端に「デフォルトに戻す」ボタンを出す（3.5.6） |
| `@ref` | `f32` / `vec3<f32>` | 値の入力欄の代わりに**参照バインド行**を出す（3.6） |

- **属性は宣言の上の行にも同一行にも書ける**。複数併記は空白区切り（`@color @reset`）。
- 型は **`f32`** と **`vec3<f32>`**（`vec3f` でも可）の 2 つ。既定値は WGSL の初期化子構文
  （`2.0` / `vec3(1.0, 0.4, 0.1)` / `vec3(0.5)`＝splat / `1.5f` のような型サフィックス可）。
- `vec3<f32>` は `@color` を省いても色として扱う（他に UI の形が無いため）。
  型と属性が食い違う書き方（`@color` を `f32` に、`@range` を `vec3<f32>` に）はエラー。
- 行末の `// …` が**インスペクタの表示ラベル**になる（省略時は識別子そのもの）。
- 宣言できるのは **1 アセットあたり 8 個まで**。超過した宣言は無視され、
  `LOAD_ERROR` に「上限を超えるため無視しました」と行番号付きで通知される
  （黙って切り捨てはしない）。
- 壊れた宣言行（型が未対応・`;` が無い・既定値が読めない・`@range` の max ≦ min・
  識別子として不正・名前の重複）も**その行だけ**が無視され、行番号付きで通知される。
  アセット自体は正常にコンパイルされ、画面は壊れない。
- **未知の属性**（将来追加される `@ref` 等）は警告を出したうえで無視し、宣言自体は生きる
  （新しい属性を書いたアセットが古いエンジンで丸ごと壊れないため）。
- `water_shade` / `u_water` / `WATER_` で始まる名前は**エンジン予約**なので使えない
  （生成コードと名前が衝突するため、解析段階で弾かれる）。
- `@group` / `@binding` のような **WGSL 本来の属性しか無い行には一切触らない**
  （エンジンが解釈する属性を 1 つも含まない属性行は宣言ブロックとみなさない）。

### 3.5.2 宣言した名前はそのまま値として読める

宣言だけ書けば、`water_shade` の中で**その名前を値として参照できる**。
バインディングもインデックスも書く必要はない。

```wgsl
// @water_shading_contract 1
@color @reset
override emission_color: vec3<f32> = vec3(3.2, 0.75, 0.08);   // 発光色

fn water_shade(input: WaterShadeInput) -> vec4<f32> {
    // `emission_color` はインスペクタで設定された vec3<f32>
    return vec4<f32>(emission_color, 1.0);
}
```

**仕組み（前処理 → 生成）**: WGSL の `override` は**スカラーしか許さず**、`@color` の
ような独自属性も通らないため、宣言をそのまま naga へ渡すことはできない。そこでエンジンは
連結の前に宣言ブロック（宣言行と、その宣言に付いた属性だけの行）を
**行数を変えずに空行へ潰して除去**し（`shade_params::strip_declarations`）、
代わりに宣言 1 個につき `var<private> <名前>: <型>;` を生成して**アセット本体の前**へ連結、
生成した `water_shade_entry` の先頭でストレージバッファの値を代入する。

除去が**行数を変えない**のは、naga が報告する行番号をアセットの行番号として
そのまま使うためである（エディタの赤線が実際の行を指し続ける）。

```wgsl
// エンジンが生成する（アセットの前）
var<private> emission_color: vec3<f32>;

// エンジンが生成する（アセットの後）
fn water_shade_entry(input: WaterShadeInput) -> vec4<f32> {
    emission_color = water_shade_param(input.instance_index, 0u).xyz;
    return water_shade_nan_guard(water_shade(input));
}
```

スロット番号は**アセット内の宣言の出現順**である。

### 3.5.3 値の保存とアセットの変更

- 値は `WaterVolumeComponent.shader_params`（名前 → `vec4` のマップ）としてシーンに保存される。
  **触っていないパラメータは保存されない**（＝アセットに書いた既定値がそのまま効く）。
- アセット側の宣言が変わったときの対応は**名前一致**である。
  - 宣言が増えた → 新しいパラメータはアセットの既定値から始まる。
  - 宣言が消えた／改名された → その値は**孤児として無視**される。シーンからは消さないので、
    アセットを元に戻せば値も戻る。
- アセットを保存して宣言（名前・型・範囲・既定値・ラベル）が変わると、
  選択中アクタのインスペクタ行が**自動で作り直される**（ホットリロード連動）。

### 3.5.4 GPU 側のレイアウト

パラメータは `WaterParams`（形状の共有構造体）ではなく、**水面パス専用の別ストレージ**で運ぶ。

| | 場所 |
|---|---|
| バインディング | `@group(1) @binding(7)`（`water_shade_params.wgsl`。水面パスだけが連結する） |
| 1 インスタンスあたり | `vec4<f32>` × 8（＝ 128 バイト） |
| 添字 | `u_water` と**同じインスタンス添字**（川は 1 水域が複数インスタンスへ広がるので、
値は分割ぶん複製される） |

`WaterParams` へ足さないのは、ID パス・水面反射パス・コースティクスパスと共有する構造体であり、
パラメータを一切使わないパスのストライドまで太らせてしまうためである。
**ID パス・反射パス・コースティクスパスはこのファイルを連結しない**（W8 の責務境界どおり）。

### 3.5.5 IPC

```
SET_WATER_SHADER_PARAM:{actorId},{slotIdx},{名前},{x},{y},{z},{w}
```

型に依らず**常に 4 成分**を送る（`color` は xyz、スカラーは x のみ意味を持つ）。
`field_edit.rs::field_edit_target` でスロット編集として分類してあるので、
**Ctrl+Z / Ctrl+Y がそのまま効く**（スライダーのドラッグは 1 コマンドにまとまる）。

インスペクタへ送る側は `ACTOR_COMPONENTS` の水コンポーネント JSON に載る:

```json
"shader_params":[{"name":"emission_color","type":"color","label":"発光色",
                  "min":0.0,"max":0.0,"reset":true,"value":[3.2,0.75,0.08,0.0]}]
```

**構文解析は Rust 側（`renderer/water/shade_params.rs`）だけが持つ**。
C# は名前・型・範囲・リセット可否・現在値を受け取って行を作るだけで、`.wgsl` を読まない。

### 3.5.6 `@reset` — デフォルトに戻すボタン

`@reset` を付けたパラメータには、インスペクタ行の右端に「⟲」ボタンが出る。
押すとその値が**アセットの既定値**（`= …` に書いた値）へ戻る。

```
RESET_WATER_SHADER_PARAM:{actorId},{slotIdx},{名前}
```

実装は「**シーン側の上書き値を消す**」であり、既定値を書き込むのではない。
`shader_params` は上書きだけを持つ差分マップで、値が無い名前は描画・インスペクタとも
自動的にアセットの既定値へ落ちるからである（`build_block` / `params_json`）。
この方式だと、後からアセットの既定値を書き換えたとき「戻した水域」が新しい既定値へ
追随する（既定値を焼き込む方式では追随しない）。

Undo は `field_edit.rs` の共通機構がそのまま担当する（`field_edit_target` で
スロット編集に分類済み。**マージキーの先頭が値編集と別のコマンド名**なので、
直前のスライダー操作と 1 手にまとまらず、Ctrl+Z 1 回でリセット前へ戻る）。
既に既定値のパラメータ（上書きが無い）に対するリセットは**何もしない**
（無意味な `SCENE_MODIFIED` で「未保存」印を付けないため）。

### 3.5.7 スクリプトから動かす（Phase W8.2）

宣言したパラメータは C# スクリプトからも読み書きできる。ゲーム内変数を
見た目へ流し込む用途（例: ボス HP で毒沼の蛍光を変える）を想定している。

```csharp
if (gameObject.GetComponent<WaterVolume>() is { } water)
{
    water.SetShaderParam("glow_boost", 2.5f);                          // f32
    water.SetShaderParam("glow_color", new Vector3(0.2f, 0.6f, 0.1f)); // vec3<f32>
    float g = water.GetShaderParamFloat("glow_boost");                 // 未設定ならアセット既定値
    Vector3 c = water.GetShaderParamVector3("glow_color");             // 宣言が無ければ (0,0,0)
}
```

**Play 中の書き込みはシーンへ焼き付かない。** これは意図した挙動であり、根拠は
`play_mode_ops.rs` の Play スナップショットである: ENTER_PLAY で対象アクタを
`ActorData` へ退避し、EXIT_PLAY で despawn → 再構築するため、Play 中に ECS へ
書いた `shader_params` は Play 終了と同時に開始時点の値へ巻き戻る
（水位の `sim_level_y` と同じ「Play 中だけの値」になる）。
そのためスクリプト経路は `SCENE_MODIFIED` も Undo 記録も行わない
（スクリプトの実行はシーンの編集ではない、というエンジン全体の方針どおり）。

読み取りの既定値解決には、アセットのパスごとに mtime で無効化する小さなキャッシュを
使う（`shading_asset::declaration_default`）。毎フレーム呼ばれてもファイル I/O は
アセットを保存した直後の 1 回だけになる。

## 3.6 `@ref` — シーンから値を流し込む（バインド、Phase W8.3）

`@ref` を付けたパラメータは、値を手で入れる代わりに「シーン内のどのコンポーネントの
どの変数から値を貰うか」を指定する**参照バインド**になる。ボスの HP を毒沼の蛍光強度に
連動させる、プレイヤーの移動速度を波立ちに反映する、といった「ゲーム内の値で見た目を
動かす」用途を想定している。

### 3.6.1 構文

```wgsl
@ref
override player_speed: f32 = 0.0;   // 未バインド時は保存値、無ければこの既定値
```

- `@color` / `@range` / `@reset` と**併用できる**（空白区切りで併記）。
- `@reset` を併用したときのボタンは、通常の「デフォルトに戻す」ではなく
  「**バインドを解除してアセット既定値へ戻す**」動作になる。
- 型は他の宣言と同じく `f32` と `vec3<f32>`（`vec3f` 可）の 2 つ。
  バインドが要求する値の型もこれで決まる（3.6.2）。

### 3.6.2 バインド元にできる値

型は**厳密一致**（3.6.3）。組込コンポーネントの一覧は
`runtime/src/engine/binding/catalog.rs` の `BUILTIN_BINDABLES` が正典で、
供給値を足すときもここ 1 か所（表への 1 行 ＋ 読み取りの 1 腕）だけを触ればよい。

| コンポーネント | 変数 | 型 |
|---|---|---|
| Transform | 位置 | `vec3<f32>` |
| Transform | スケール | `vec3<f32>` |
| Light | 強度 | `f32` |
| Light | 色 | `vec3<f32>` |
| WaterVolume | 波の振幅 | `f32` |
| WaterVolume | 水位 | `f32` |
| WaterVolume | 浅場色 | `vec3<f32>` |
| WaterVolume | 深場色 | `vec3<f32>` |

スクリプトの `[SerializeField, Bindable]` フィールドもバインド元になれる
（`float` → `f32`、`Vector3` → `vec3<f32>`）。詳細は
`docs/scripting_api.md` の `[Bindable]` の節を参照。

### 3.6.3 型は厳密一致（成分の部分取り出しは不可）

`f32` のパラメータには `f32` の供給値だけ、`vec3<f32>`（色）のパラメータには
`vec3` の供給値だけが繋がる。「`vec3` の X 成分だけ欲しい」はできない。
成分を切り出したいなら、供給側（コンポーネントやスクリプト）が
その専用の `f32` 変数を明示的に持つべき、という設計判断による
（バインド機構が勝手に切り出すと、繋いだ本人にも何が流れているか分からなくなる）。

### 3.6.4 毎フレーム上書き・保存値は変わらない

バインドが解決できると、その実値で**毎フレーム**パラメータが上書きされる
（Edit / Play 両方）。**`WaterVolumeComponent.shader_params`（シーンの保存値）は
書き換わらない**ので、バインドを外せばバインド前の値へそのまま戻る。

### 3.6.5 解決に失敗したときのフォールバックと ⚠

アクタ／コンポーネント（スロット）／変数のいずれかが見つからない、型が変わった、
スクリプトが `[Bindable]` を外した ── いずれの場合も**保存値 → アセット既定値の順に
フォールバック**し、インスペクタのその行に **⚠** が出る。
解決に失敗しても例外にもログにもならない（毎フレーム走る経路で失敗をログに
書くと実質使い物にならないため。詳細は `engine::binding` モジュールコメント）。

### 3.6.6 操作手順（インスペクタ）

1. `@ref` 行のドロップゾーンへ Hierarchy のアクタをドラッグ＆ドロップする。
2. 1 ページ目でコンポーネント（Transform / Light / WaterVolume / スクリプト）を選ぶ。
3. 2 ページ目で、そのコンポーネント内の変数（型が一致するものだけが候補に出る）を選ぶ。
4. 確定するとバインドが張られ、以後は参照先の実値がその場に表示され続ける。
5. 行の「✕」ボタンでバインドを解除する（保存値へ戻る）。

IPC は次の 1 コマンドに乗る（Undo はランタイム側の共通機構が拾う）:

```
SET_WATER_SHADER_BINDING:{actorId},{slotIdx},{名前},{"アクタ名|スロット名|変数名"}
```

`binding` を空文字列で送るとバインド解除になる。

### 3.6.7 保存形式とアクタ改名の追従

バインドは `WaterVolumeComponent.bindings`（パラメータ名 → バインド先文字列）として
シーンに保存される。バインド先文字列は 1 本 **`"アクタ名|スロット名|変数名"`** で持つ
（`engine::binding::resolve` が正典）。`serde` の `default` 付きなので、
`bindings` を持たない旧シーンもそのまま読める（＝空のバインド扱い）。

参照先のアクタが改名されると、`rename_refs.rs` が `bindings` の値（1 要素目の
アクタ名）を書き換えるので、バインドは**改名に自動で追従する**。

### 3.6.8 設計判断: `[Bindable]` の検証はランタイム読み取り時が正典

スクリプトの `[SerializeField, Bindable]` フィールドを毎フレーム読むとき、
`[Bindable]` 属性が付いているかどうかの検証は**値を読むたびに CLR 側で行う**
（Rust 側で一度だけ検証してキャッシュする、という方式は採っていない）。

理由は、バインドを張った**後**にスクリプトの属性を外す・フィールドを消す・
コンパイルが失敗する、といった変化がエディタ上でいつでも起こり得るため。
読み取りのたびに検証しておけば、属性を外した瞬間からバインドは解決失敗になり
（3.6.5 のフォールバックへ落ちる）、設定時だけの検証では追随できない
「張った時点では有効だったが今は無効なバインド」を構造的に防げる。
スクリプトのコンパイルに失敗している間は、そのスクリプトのフィールドは
バインド候補にも現れない（先にコンパイルエラーを直すこと）。

### 3.6.9 使用例: スクリプトの `[Bindable] float` を毒沼の蛍光強度にバインドする

`poison.wgsl` に `@ref` 付きの蛍光強度パラメータを用意する。

```wgsl
@ref @range(0.0, 4.0)
override glow_boost: f32 = 1.0;   // 蛍光の強さ（未バインド時はこの既定値）
```

スクリプト側にバインド可能なフィールドを用意する。

```csharp
[SerializeField, Bindable]
private float bossRagePower = 1.0f;

void Update()
{
    // ボスの残り HP が減るほど毒沼が禍々しく光る、といった演出に使える。
    bossRagePower = Mathf.Lerp(1.0f, 4.0f, 1.0f - boss.HpRatio);
}
```

インスペクタで水域アクタを選び、`glow_boost` 行のドロップゾーンへボスアクタを
ドロップ → 1 ページ目でスクリプトコンポーネントを選択 → 2 ページ目で
`bossRagePower` を選択、で完了。以後 `bossRagePower` の実行中の値が
毎フレーム `glow_boost` へ流れ込む。バインドを外せば、外した瞬間から
`glow_boost` は元の保存値（またはアセット既定値の `1.0`）に戻る。

## 4. エディタでの設定

`WaterVolume` コンポーネントのインスペクタ「色と透明度」セクション先頭に
**「水面シェーダ」**のファイル参照行がある。

- `.wgsl` をドラッグ&ドロップ、または「参照」ボタンで選ぶ。
- **空欄 = エンジン標準の水**。「×」ボタンで標準へ戻る。

```
SET_WATER_FIELD:{actorId},{slotIdx},surface_shader,{仮想パス}
```

アセットが `override` でパラメータを宣言していれば、**この参照行の直下**に
編集行（カラーピッカー／スライダー／数値）が自動で並ぶ（3.5 節）。
`@reset` の付いた行には右端に「デフォルトに戻す」ボタンが出る。
アセットを外す（「×」）と行も消える。

## 5. 同梱サンプル

> **どちらのサンプルもパラメータ宣言（3.5 節）付き**である（全パラメータに `@reset` 付き）。差した直後から
> インスペクタに色・強さのつまみが並ぶので、まずはそこを触って挙動を掴むとよい。
> 　magma: 溶岩の発光色 / 発光の強さ / 亀裂の流れる速さ / 亀裂の開き具合
> 　poison: 毒の蛍光色 / 艶の強さ（ぬめり感） / 澱みの濃さ

### 5.1 `assets://shaders/magma.wgsl` — マグマ（溶岩）

- **深いほど発光する**。厚み `thickness` を温度として読み替え、黒い殻 → 橙 → 黄白の 2 段補間。
- **亀裂の模様**。`water_shade_fbm` を `flow`（＋微速のドリフト）で流し、
  ノイズの谷を「殻の割れ目」として温度を持ち上げる。川に指定すれば下流へ流れる溶岩になる。
- **泡 → 焦げ ＋ 火の粉**。標準の泡量を「白い泡」ではなく
  「黒い焦げ」（`mix` で暗くする）と「明滅する火の粉」（値ノイズの粒 × `sin(time)` の加算）に読み替える。
- **反射は弱め**。溶岩は粗い黒体なので、フレネル指数を上げ（縁だけ）強度を 0.25 倍に落とす。
- 屈折グラブ（`refraction_color`）は**一切使わない**＝完全に不透明。

**シーン側の推奨設定**（物性はアセットの担当外なのでインスペクタで設定する）:

| パラメータ | 値 | 理由 |
|---|---|---|
| 粘度 `viscosity` | 0.85 | 波がゆっくり進み、波紋がすぐ減衰する |
| 波紋減衰 `ripple_damping` | 0.9 | 落下物の波紋が広がらず、その場で消える |
| 波振幅 `wave_amplitude` | 0.15 | うねりは小さく |
| 波速度 `wave_speed` | 0.2 | ゆっくり |
| 吸収距離 `absorption_distance` | 0.6 | 底が見えない |
| 深場色 `deep_color` | (0.02, 0.005, 0.0) | ほぼ黒 |
| 浅場色 `shallow_color` | (0.25, 0.05, 0.01) | 暗い赤 |
| 反射強度 `reflection_intensity` | 0.15 | 鏡にならない |
| 反射粗さ `reflection_roughness` | 0.8 | ぼやけた反射 |

### 5.2 `assets://shaders/poison.wgsl` — 毒沼

- **毒々しい緑と強い吸収**。標準の吸収式（`water_shade_absorption`）を、
  吸収距離を 0.55 倍に縮めて使う＝「標準と同じ理屈で濃さだけ違う」。
- **澱みの模様**。低周波の fBm を薄く重ね、表面が均一な板に見えないようにする。
- **蛍光**。深い所ほど緑を加算し、底が見えないぶん不気味さを出す。
- **粘つく艶**。`viscosity` に応じて Blinn-Phong の指数を 24 → 180 で補間し、
  ハイライトを狭く硬くする。反射の**後**に加算するので、反射像に埋もれず常に表面のぬめりとして見える。
  水面パスはライト配列を持たない（バインドグループが上限）ため、**アセット固有の固定光**で
  評価している点に注意（シーンのライトとは連動しない）。
- **泡 → 泡立ちの白緑**。シーン設定の泡色を白緑へ寄せ、さらに膨らんで弾ける粒を上乗せする。

**シーン側の推奨設定**:

| パラメータ | 値 | 理由 |
|---|---|---|
| 粘度 `viscosity` | 0.6 | 艶の鋭さがこの値で決まる |
| 波紋減衰 `ripple_damping` | 0.75 | 粘って波紋が残らない |
| 波振幅 `wave_amplitude` | 0.06 | 波立ちにくい |
| 波速度 `wave_speed` | 0.35 | — |
| 吸収距離 `absorption_distance` | 0.5 | 底が見えない |
| 深場色 `deep_color` | (0.02, 0.09, 0.03) | 暗い緑 |
| 浅場色 `shallow_color` | (0.25, 0.55, 0.12) | 黄緑 |
| 泡色 `foam_color` | (0.7, 0.95, 0.6) | 白緑 |
| 反射強度 `reflection_intensity` | 0.5 | 表面が濡れている |
| 反射粗さ `reflection_roughness` | 0.25 | やや鋭い反射 |

## 6. 実装の仕組み

### 6.1 連結とディスパッチ

水面パスの WGSL は 5 本の連結で作られる（正典は `water_surface.toml` の `shader_sources`）。

```
water_height_field.wgsl      形状・高さ場・WaterParams・WATER_EPSILON（ID/反射パスと共有）
water_shading_contract.wgsl  契約 v1（WaterShadeInput / water_shade_default / 標準ライブラリ）
water_shade_params.wgsl      パラメータ値の受け皿（group1 binding7。水面パス専用。W8.2）
water_shade_dispatch.wgsl    契約関数 water_shade_entry の既定実装  ← ここが差し替え対象
water_surface.wgsl           頂点/フラグメント本体（材料を集めて契約へ渡す）
```

アセット指定時、差し替え対象の 1 要素は **3 要素**へ広がる（W8.2）:

```
<生成: var<private> のパラメータ宣言>   ← アセットより前（アセットが名前を参照するため）
<アセット本体>
<生成: water_shade_entry>              ← 先頭でパラメータを取り込んでからユーザー実装を呼ぶ
```

アセットが指定されると、Rust 側が**3 番目の 1 要素だけ**を
「アセット本体 ＋ 自動生成した `water_shade_entry`」へ置き換える。

| アセットの状態 | 生成される `water_shade_entry` |
|---|---|
| `water_shade` を定義している | `return water_shade_nan_guard(water_shade(input));` |
| 定義していない（警告） | `return water_shade_default(input);` |
| アセット未指定 | （既定ディスパッチがそのまま連結される）`return water_shade_default(input);` |

**NaN ガードはユーザー実装にしか掛からない。** 既定経路にガードを掛けないのは、
「アセットを指定していない水は W7 以前と 1 ビットも変わらない」という設計要件に
疑いを残さないためである（ガードは上限クランプも行うため、極端な HDR 値だけは値が変わり得る）。

### 6.2 バケット分割（アセットごとの描画）

水面の最終色はパイプライン（＝連結された WGSL）が決めるため、
**見た目の違う水を 1 ドローで描くことはできない**。そこで `WaterRenderer::prepare` が
パラメータ配列を並べ替える。

```
[ アセットA のクアッド…, アセットB のクアッド…, … ,
  アセットA の川…,       アセットB の川…,       … ]
```

- 外側の 2 区画（クアッド／川）は W5.1 のまま崩さない。
  1 ドローに指定できる頂点数は 1 つだけで、クアッドと川では格子の分割数が桁違いだからである。
- アセットによる分割は**それぞれの区画の内側**で行う。1 グループは
  「クアッド区画内の連続レンジ」と「川区画内の連続レンジ」を 1 本ずつ持つ。
- グループの順序は**初出順**（`HashMap` を使わない）。フレーム間で順序が揺れると
  描画順が変わって重なりが不安定になるため。
- **アセットを 1 つも使っていないプロジェクトではグループが 1 個しかできず、
  並びもドローコール数も Phase W5.1 と完全に同一である**（コスト 0）。

`draw` はグループごとに `set_pipeline` → BindGroup 再設定 → そのレンジだけを `draw` する。

**ID パス・水面反射パス・コースティクスパスはこの分割を使わない**（従来どおり全レンジを一括）。
形状は全水域で共通であり、色を作らないパスにアセットは関係しないためである。

### 6.3 キャッシュとホットリロード

L3-a のシェーディングアセットと**同一の流儀**である。

- **キーはアセット内容のハッシュ**。同じ内容なら別パスでもパイプラインを共有する
  （マグマ池を 10 個置いてもパイプラインは 1 本）。
- ビルド失敗も内容ハッシュで記録し、**内容が変わるまで再ビルドしない**
  （毎フレームの naga 検証を避ける）。
- パスごとに mtime を**1 秒間隔**でポーリングし、変化したときだけ読み直す。
- どのパスからも参照されなくなったハッシュのエントリは破棄する
  （編集を重ねても GPU メモリが単調増加しない）。
- ホットリロードの可否は Edit で常に ON、Play 中はエディタ設定
  `play_shader_hot_reload`（既定 ON）に従う。**L3-a と同じ設定を共有**している
  （片方だけ挙動が違うと「保存したのに反映される／されない」が分かれて混乱するため）。

### 6.4 検証とエラー通知

- 生成した連結ソースは**必ず naga で parse + validate してから**
  `device.create_shader_module` へ渡す（デバイスロスト回避）。
  水面パスは RT / バインドレスの変種を持たないので、検証は**1 回だけ**である。
- naga が返す行番号は連結ソース基準なので、**アセット内の行番号へ写して**返す。
  アセット外（エンジン側の連結コード）で落ちた場合は行を返さず、その旨をメッセージに書く。
- エラー・警告は `LOAD_ERROR:` として IPC でエディタへ流れ、コンソールには
  `[SEED water_shading_asset]` 付きで出る。同一メッセージの連投は抑止される。

### 6.5 診断ログ

「アセットを指定したのに見た目が変わらない」を切り分けるための行が常時出る（内容が変わったときだけ）。

```
[WATER SHADING] loaded path=assets://shaders/magma.wgsl water_shade=あり
[WATER SHADING] groups=[<標準>:quad1+river0, assets://shaders/magma.wgsl:quad1+river0]
```

- `groups=` に自分のアセットパスが出ていない → 水域の設定がランタイムへ届いていない
  （インスペクタの操作か IPC を疑う）。
- 出ているのに `(標準へフォールバック)` と付く → ロードに失敗している
  （`[SEED water_shading_asset]` 行を見る）。

## 7. 実機での確認手順（マグマ池の作り方）

1. エディタでシーンを開き、アクタを 1 つ作る。
2. そのアクタへ `WaterVolume` コンポーネントを追加する。
3. 種別を **Region** にし、`region_half_extents` を池の大きさに合わせる
   （例: 8, 2, 8）。`surface_height` で水面の高さを調整する。
4. インスペクタ「色と透明度」の先頭にある **「水面シェーダ」** の「参照」から
   `runtime/assets/shaders/magma.wgsl` を選ぶ（または `.wgsl` を D&D）。
   → その瞬間に水面がマグマになる。
5. 5.1 節の表に従って粘度・波・吸収距離・色・反射を設定する
   （**色そのものはアセットが決めるが、`deep_color` / `shallow_color` は
   アセットが入力として読むので効く**）。
6. 「水面シェーダ」行の**直下**に出ている「溶岩の発光色」のピッカーをクリックし、
   色を変える → その水域だけ発光色が変わる。**Ctrl+Z で元に戻る**。
   「亀裂の流れる速さ」のスライダーを動かすと、模様の流速がその場で変わる。
   シーンを保存して開き直しても値が残る（`WaterVolumeComponent.shader_params`）。
7. `magma.wgsl` をエディタで開き、`MAGMA_CRACK_SCALE` などの定数を書き換えて保存する。
   → 1 秒以内に画面へ反映される（ホットリロード）。
   `override` 宣言を足して保存すれば、**インスペクタの行がその場で増える**。
8. わざと構文を壊して保存する → エディタに**アセット内の行番号付き**でエラーが出て、
   水面はエンジン標準へ戻る（画面は壊れない）。直して保存すれば戻る。
9. 毒沼も見たいなら、別のアクタで同じ手順を `poison.wgsl` で繰り返す。
   → 1 シーンにマグマ池・毒沼・普通の水が同居し、それぞれ別のパイプラインで描かれる
   （`[WATER SHADING] groups=` の行で 3 グループが確認できる）。

## 8. 既知の制限・申し送り

- **スクリプトエディタの補完に水面契約のシンボルが出ない。**
  `WaterShadeInput` のフィールド名や `water_shade_*` 関数は、現状 L3-a の契約シンボル補完には
  含まれていない。エディタの WGSL 検証（`VALIDATE_WGSL`）は契約マーカーで正しく切り替わるので
  **エラー検出は効く**が、補完だけが未対応である。
- **水面パスからライト配列を読めない。** 水面パイプラインのバインドグループが上限に達しており、
  TLAS・ライト・GI を足せない（`water_surface.wgsl` 冒頭コメント参照）。
  ライトに応じたスペキュラが欲しいアセットは `poison.wgsl` のように**固定光**で近似すること。
- **アルファは合成に使われない**（3.1 節）。半透明の水面を作りたい場合は、
  `refraction_color`（屈折グラブ）を自分で混ぜる形で表現する。
- **粗さブラー・反射の焼き込みは標準のまま**。アセットは反射像の「混ぜ方」しか変えられない。
- **パラメータ宣言は 1 アセット 8 個まで**（3.5 節）。GPU 側の 1 インスタンスあたりの
  ブロックが `vec4` × 8 の固定長であるため。増やす場合は
  `shade_params.rs` の `WATER_SHADE_PARAM_MAX` と `water_shade_params.wgsl` の
  配列長・`WATER_SHADE_PARAM_SLOTS` を**同時に**直すこと
  （食い違いはユニットテスト `rust_and_wgsl_param_slot_counts_match` が検出する）。
- **パラメータの型は `f32` と `vec3<f32>` の 2 つだけ**（UI は色／スライダー／数値の 3 種）。
  vec2・整数・真偽値・テクスチャ参照は未対応である（必要になったら
  `WaterShadeParamKind` へ追加し、C# の行ビルダーに分岐を足す）。
- **パラメータ値はアセットのファイルへ書き戻さない。** 値はシーン側
  （`WaterVolumeComponent.shader_params`）に持つ。アセットに書いた値は
  あくまで「新しく差したときの既定値」である。
- サンプル 2 点は `runtime/assets/shaders/` にあり、
  ユニットテスト `bundled_sample_assets_pass_naga_validation` が naga 検証を、
  `bundled_samples_declare_inspector_params` がパラメータ宣言の存在を固定している。
