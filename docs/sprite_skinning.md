# 2D メッシュ変形スキニング（Spine 風スプライト）

`SkinnedSpriteComponent` と `.sprite_mesh` アセットによる「メッシュを変形させる 2D スプライト」の仕様書。

- **Phase A1**: ランタイム（描画・変形・ピッキング・スクリプト API）
- **Phase A2**: エディタ（ボーン対応表 UI・ボーンアクター生成・ビューポートのボーン表示）— §8 が操作手順
- **Phase B1a**: スプライトリグパネル（画像から `.sprite_mesh` を作る・編集する）— §7 が操作手順

ウェイトペイントとボーン配置 UI（Phase B1b）はまだ無い。
B1a が書き出す `.sprite_mesh` は「ルートボーン 1 本・全頂点がルートへ 1.0」で、
ボーンを増やす場合は §8 の手順でシーン側に子アクターを生やす。

---

## 1. 設計の要（なぜこの形なのか）

### ボーン＝普通の 2D 子アクター

独立した Skeleton アセットは**作らない**。ボーンは `SkinnedSpriteComponent` を持つアクターの
**子孫アクター**（`CanvasTransform` を持つ Actor2D）そのものである。

この選択の見返り:

| 欲しいもの | 追加実装 |
|---|---|
| ボーンのギズモ操作 | 不要（既存のアクターギズモがそのまま効く） |
| ボーンの Undo/Redo | 不要（既存のアクター Undo 機構） |
| ボーンのキーフレームアニメ | 不要（既存 `.anim` の汎用プロパティトラック） |
| ボーンの階層・親子付け | 不要（既存のヒエラルキー） |

ボーンを動かすアニメーションは、`.anim` に
`{ actor_path: "root/elbow", component: "CanvasTransform", property: "rotation" }`
のトラックを打ち、`AnimatorComponent` で再生するだけでよい。

### 描画は既存のスプライトパイプラインを「任意メッシュ対応」へ拡張した

別パイプラインは作っていない。スキニングは**コンピュートシェーダ**が担当し、
その出力を「既存のスプライト頂点レイアウトそのもの」で書き出すことで、
描画側は頂点バッファを差し替えるだけで済むようにしてある（詳細は §4）。

## 2. `.sprite_mesh` アセット形式（JSON）

```json
{
  "version": 1,
  "name": "quad_one_bone",
  "comment": "制作者向けメモ（実行時挙動に影響しない）",
  "texture": "quad_one_bone.png",

  "vertices": [[0.0, 0.0], [100.0, 0.0], [100.0, 80.0], [0.0, 80.0]],
  "uvs":      [[0.0, 0.0], [1.0, 0.0],   [1.0, 1.0],    [0.0, 1.0]],
  "triangles": [0, 1, 2, 0, 2, 3],

  "bones": [
    { "name": "root",  "parent": "",     "position": [0.0, 0.0],   "rotation": 0.0, "scale": [1.0, 1.0] },
    { "name": "elbow", "parent": "root", "position": [100.0, 0.0], "rotation": 0.0, "scale": [1.0, 1.0] }
  ],

  "weights": [
    [{ "bone": 0, "weight": 1.0 }],
    [{ "bone": 0, "weight": 0.5 }, { "bone": 1, "weight": 0.5 }],
    [{ "bone": 1, "weight": 1.0 }],
    [{ "bone": 1, "weight": 1.0 }]
  ]
}
```

| フィールド | 意味 |
|---|---|
| `version` | スキーマバージョン。現行 `1`（省略＝`0` も受け入れる） |
| `texture` | **省略可**。元画像への `.sprite_mesh` からの相対パス。<br>エディタのスプライトリグパネルが再編集時に画像を引き当てるための**ヒント**で、<br>実行時の描画には使わない（描画テクスチャは `SkinnedSpriteComponent.texture_path`）。<br>省略時は空文字列。**旧ファイルはそのまま読める**（後方互換） |
| `vertices` | 頂点位置。**スプライトローカルのキャンバスピクセル座標**（§3） |
| `uvs` | 頂点 UV。`[0,1]×[0,1]`・左上原点。`vertices` と同数 |
| `triangles` | 三角形インデックス。3 の倍数個・全て頂点範囲内 |
| `bones` | ボーンのバインドポーズ宣言。`parent` は**ボーン名**（空 = ルート） |
| `weights` | 頂点ごとの影響。**1 頂点あたり最大 4 本**。`bone` は `bones` の添字 |

### バリデーション（読込時に必ず走る）

以下はすべて**読み込みエラー**になる（描画されず、警告を 1 度だけ出す）:

- `vertices` が空 / `uvs`・`weights` の数が `vertices` と不一致
- `triangles` が空、3 の倍数でない、範囲外インデックスを含む
- `bones` が空、ボーン数が 128 本超、ボーン名が空または重複
- `parent` が存在しないボーン名、自分自身を親にしている、親子関係が循環している
- ある頂点の影響が 0 本または 5 本以上
- ウェイトが負・非有限、あるいは 1 頂点のウェイト合計が 0

**ウェイトは読込時に合計 1.0 へ正規化される**（GPU 側では正規化しない）。

### バインドポーズ逆行列

`bones` のローカル TRS からグローバル行列（ルート→自分の合成）を組み、
その逆行列を**読込時に 1 度だけ計算してキャッシュ**する。実行時は毎フレーム
`bone_matrix = current_relative × inverse_bind` を作るだけである。

## 3. 座標系（ここを外すと全部ずれる）

- `.sprite_mesh` の `vertices` は **スプライトローカルのキャンバスピクセル座標**。
  原点は `SkinnedSpriteComponent` を持つアクターの `CanvasTransform` 原点、
  **+X が右・+Y が下**（既存のキャンバス座標系と同じ）。
- ボーンアクターの `CanvasTransform.position` も**まったく同じ空間**なので、
  頂点座標とボーン座標を無変換で突き合わせられる。
- `uvs` は `[0,1]×[0,1]`・左上原点（既存スプライトのユニットクワッドと同じ）。

### 従来スプライトとの等価性

`SpriteComponent { width: w, height: h }`（pivot 0）と等価なメッシュは:

```
vertices  = [[0,0], [w,0], [w,h], [0,h]]
uvs       = [[0,0], [1,0], [1,1], [0,1]]
triangles = [0,1,2, 0,2,3]
bones     = [ root（無変形） ]
weights   = すべて root へ 1.0
```

これが実際に一致することは
`runtime/src/engine/core/loader/sprite_mesh.rs` の
`quad_one_bone_matches_plain_sprite` テストが検証している
（フィクスチャ: `runtime/tests/fixtures/quad_one_bone.sprite_mesh`）。

### `CanvasTransform` の解釈の違い

| | `SpriteComponent` | `SkinnedSpriteComponent` |
|---|---|---|
| 使う行列 | `to_sprite_mat4(width, height)` | `to_mesh_mat4(scale_x, scale_y)` |
| 引数の意味 | スプライトの**実寸** | 親キャンバス由来の**追加スケール**（既定 1.0） |
| `pivot` の意味 | `pivot × サイズ`（正規化 0〜1） | `pivot × 追加スケール`（**メッシュローカルのピクセル値**） |

頂点が既に実寸を持っているため、スキンスプライトには `width`/`height` フィールドが無い。
サイズを変えたいときはメッシュ側を作り直すか、`CanvasTransform.scale` を使う。

## 4. スキニングの実装方式

### GPU（コンピュート）で変形 → 既存パイプラインで描画

1. **CPU**（`sprite_skin.rs::build_bone_palette`）
   ボーンアクターの現在姿勢を集め、`bone_matrix = current_relative × inverse_bind` を計算する。
   `current_relative` は「スプライトルートアクターからボーンアクターまでの
   `CanvasTransform::to_mat4()` の合成」。
2. **GPU パレット**
   2D アフィンは 6 成分しか要らないので、`mat4x4` ではなく **1 ボーン = `vec4` × 2**
   （`r0 = (a, b, tx, 0)` / `r1 = (c, d, ty, 0)`）で持つ。
   これは行優先 `[[f32;4];4]` の 0/1 行目そのままである。
3. **コンピュート**（`shaders/sprite_skin.wgsl`、1 スレッド = 1 頂点）
   バインドポーズ頂点にパレットを適用し、**変形後の頂点を
   `sprite_vertex` レイアウト（`pos.xy` + `uv.xy` = 16 bytes）で書き出す**。
4. **描画**
   出力バッファは既存の `sprite.wgsl` / `canvas_id.wgsl` の slot0 頂点バッファと
   **同一形式**なので、ユニットクワッドの代わりに差し替えて `draw_indexed` するだけ。
   **新しい描画シェーダは 1 本も足していない。**

### リソースの持ち方

| 資源 | キャッシュ単位 | 中身 |
|---|---|---|
| `GpuSpriteMesh` | `.sprite_mesh` のパス | バインドポーズ頂点（storage）＋インデックス |
| `SpriteSkinInstance` | **スロット `Entity`** | ボーンパレット・パラメータ・変形後頂点・BindGroup |

インスタンスがスロット単位なので、**同じメッシュを複数体が使っても各体が自分のパレットを引く**。

### ボーン解決規則

`.sprite_mesh` の各ボーン名について、次の順で解決する:

1. `bone_overrides` に明示エントリがあれば、その**アクター相対パス**（`"/"` 区切り）で解決
2. 無ければボーン名を直下パスとして解決
3. それでも見つからなければ、子孫を DFS 探索して**同名のアクター**を探す（自動解決）

どれでも見つからないボーンは**バインドポーズ（無変形）**として扱い、
「どのボーンが見つからなかったか」を**アクター × メッシュにつき 1 度だけ**警告する。

## 5. 描画規約（`SpriteComponent` と完全に同じ）

- **レイヤー / 描画ゾーン**: 矩形スプライトとスキンスプライトは**同じリストへ積まれ、
  同じ規則（ゾーン → レイヤー昇順の安定ソート）で並べ替えられる**。
  したがって両者の前後関係はレイヤー値だけで正しく決まる。
- **color**: テクスチャへの乗算（RGBA）。
- **キャンバス Transform**: アンカー・`scale_transform` / `scale_size`・アスペクト比維持まで
  スプライトと同一の変換連鎖を通る。
- **ID パス（GPU ピッキング）**: 変形後の頂点でメッシュ形状のまま ID を描くので、
  **クリック判定の形が見た目と一致する**。テクスチャのアルファ 0.1 未満は従来どおり discard。

## 6. スクリプト API

`docs/scripting_api.md` の「SkinnedSprite」節が正典。

```csharp
if (gameObject.GetComponent<SkinnedSprite>() is { } ss)
{
    ss.MeshPath;     // string（get/set）
    ss.TexturePath;  // string（get/set）
    ss.Color;        // Color（get/set）
    ss.Layer;        // int（get/set）
}
```

ボーンを動かす API は**持たない**。ボーンは普通の子アクターなので、
そのアクターの `CanvasTransform` を操作する（あるいは `.anim` で再生する）。

## 7. スプライトリグパネル（メッシュ作成・編集 / Phase B1a）

「画像を取り込む → 自動でメッシュ化する → 手で直す → `.sprite_mesh` を保存する」までを
エディタ内で完結させるドッキングパネル（`ContentId` = `sprite_rig`）。
**ランタイムは一切使わず、描画も編集も純 WPF で行う**ので、Play していなくても作業できる。

### ① パネルを開く / 画像を取り込む

開き方は 4 通り。どれも**編集中の他タブを壊さず、新しいタブが増えるだけ**である。

| 操作 | 結果 |
|---|---|
| プロジェクトパネルで画像を右クリック →「スプライトリグを作成」 | パネルを表示し、その画像の新規タブを開く |
| パネル上部の「画像を開く」 | ファイルダイアログ（複数選択可） |
| プロジェクトパネルからパネルへ画像をドラッグ＆ドロップ | ドロップした画像ぶんのタブを開く |
| 「表示」→「パネル」→「スプライトリグ」 | パネルの表示/非表示トグル |

画像と同じ場所に同名の `.sprite_mesh` が既にある場合は、新規作成ではなく**それを開いて続きから編集**する。

### ② 既存の `.sprite_mesh` を開き直す

`.sprite_mesh` をダブルクリック、または右クリック →「スプライトリグを編集」。
パネル上部の「メッシュを開く」でも同じ。

重ねる画像は次の順で決まる:

1. `texture` フィールド（`.sprite_mesh` からの相対パス）が指すファイルが実在すればそれ
2. 無ければ、同じフォルダの**同名画像**（`hero.sprite_mesh` → `hero.png` など）
3. それでも見つからなければ**画像選択ダイアログ**を出す

ファイルには頂点と三角形しか入っていないため、編集モデルが必要とする「輪郭ポリゴン + 内部点」は
**境界辺（片側にしか三角形が無い辺）を繋いで復元**する。
このとき三角形は**ファイルのものをそのまま保持**し、勝手に三角分割し直さない
（開いただけで形が変わらないようにするため）。

### ③ キャンバスの操作

| 操作 | 割り当て |
|---|---|
| ズーム | ホイール（カーソル位置を固定して拡大縮小） |
| パン | 中ボタンドラッグ |
| 全体表示 | 上部ツールバーの「全体表示」 |
| ピクセルグリッド | 上部ツールバーのトグル（**6 倍以上に拡大したときだけ**描画される） |
| Undo / Redo | Ctrl+Z / Ctrl+Y（**パネル内だけのローカル履歴**。シーンの Undo とは独立） |

座標系は画像ピクセル（左上原点・+X 右・+Y 下）で、**そのまま `.sprite_mesh` の頂点座標になる**。

### ④ 自動メッシュ化（アルゴリズムとパラメータ）

左パネルの「自動メッシュ生成」で、アルファから輪郭とメッシュを作る。処理は 5 段:

1. **二値化** — アルファが `アルファ閾値` 以上のピクセルを不透明とみなす。
2. **輪郭抽出**（`ContourTracer`）— ピクセル境界を辿る *crack following*。
   補間点を作らず**ピクセルの境界線そのもの**を繋ぐので、輪郭は 1px もはみ出さない。
   不透明側が常に進行方向の右に来る向きで張るため、
   **外周 = 正の符号付き面積 / 穴 = 負**が機械的に決まる（穴・複数島に対応）。
   分岐点では右折を優先＝前景 8 連結・背景 4 連結。
3. **簡略化**（`PolylineSimplifier`）— Douglas-Peucker。閉多角形は
   「重心から最遠の点」と「そこから最遠の点」をアンカーに固定してから 2 本の開折れ線として処理するので、
   始点の取り方に結果が依存しない。**3 点未満になる／面積の符号が反転する場合は元の輪郭へ戻す**。
4. **内部点の配置** — 六方格子（行を半ピッチずらした正三角形格子）で候補を撒き、
   領域内かつ**輪郭から `内部点の間隔 × 0.6` 以上離れている**候補だけ残す
   （輪郭のすぐ内側に点を置くと極端に細長い三角形ができるため）。
5. **三角分割**（`Triangulation`）— 穴を外周へブリッジで結合して単純多角形にし、
   耳の切り出し（ear clipping）で三角化 → 内部点を含む三角形を 3 分割 →
   **輪郭辺（制約辺）以外**を外接円条件で辺フリップして Delaunay 化する。
   耳切りは多角形の内部しか三角形にしないので、**三角形が輪郭の外へ出ないことが構造的に保証される**。

| パラメータ | 既定値 | 意味 |
|---|---|---|
| アルファ閾値 | 128 | この値以上のアルファを不透明とみなす |
| 輪郭の簡略化 (px) | 2.0 | Douglas-Peucker の許容誤差。大きいほど頂点が減る |
| 内部点の間隔 (px) | 24 | 0 にすると内部点を置かない（輪郭だけの粗いメッシュ） |
| 島の最小面積 (px²) | 16 | これ未満の輪郭はノイズとして捨てる |

**透過が無い画像**は輪郭が画像枠そのものになり、簡略化で 4 隅へ落ちて
「従来スプライトと等価な矩形メッシュ」になる（§3 の等価性と一致する）。
**全画素が透明な画像**でも輪郭が 0 本にならないよう、画像枠の矩形へフォールバックする。

### ⑤ 手動での編集

左パネルの「ツール」で、左クリックの意味が切り替わる。

| ツール | 操作 |
|---|---|
| 選択 | 頂点をクリックして選ぶ |
| ポリゴン描画 | クリックで頂点を足す。**始点クリックか Enter で閉じて確定**／右クリックか Esc で破棄。複数本描ける |
| 頂点追加 | **輪郭の辺の上**をクリック → その辺を分割／**領域の内側**をクリック → 内部点を追加 |
| 頂点移動 | 頂点をドラッグ（画像範囲へクランプされる） |
| 頂点削除 | 頂点をクリックして削除（Delete キーでも可）。輪郭が 3 頂点未満になるとポリゴンごと消える |

自動メッシュ化の後にそのまま手で直せる。「再三角分割」を押すと、
**現在の輪郭と内部点から三角形だけを作り直す**（輪郭・内部点は変わらない）。

> ユーザーが直接編集するのは**輪郭ポリゴンと内部点だけ**で、頂点配列と三角形は毎回そこから作り直す派生データである。
> どの操作も「入力データを変えて作り直す」1 本の道に揃うため、三角形リストを直接いじる方式で必ず起きる
> 「辺の整合が壊れる」問題が構造的に起こらない。
>
> 穴かどうかは指定させず、**他ポリゴンに何重に囲まれているかの偶奇**で自動判定する（偶数 = 外周・奇数 = 穴）。

### ⑥ 保存

| ボタン | 保存先 |
|---|---|
| 保存 | 既に保存先があるならそこ。無ければ**画像と同じフォルダの同名 `.sprite_mesh`** |
| 名前を付けて保存 | ダイアログで指定した場所 |

保存内容の規約（Phase B1a）:

- `vertices` は画像ピクセル座標そのまま、`uvs` は画像サイズで割った `[0,1]²`（左上原点）。
- `bones` は**ルート 1 本だけ**（`name: "root"` / 無変形）、`weights` は**全頂点がルートへ 1.0**。
  これは「ランタイムのパーサが受理する最小構成」であり、この状態でも
  `SkinnedSprite` に割り当てれば**バインドポーズのまま正しく描画される**。
- `texture` に元画像への相対パスを書く（再編集時の引き当て用。§2）。

書き出し前に「頂点がある / 三角形が 3 の倍数 / インデックスが範囲内 / ボーン名が空でなく重複しない」を
エディタ側で検証するので、**保存はできたのにランタイムで読めないファイル**は作られない。
保存後のプロジェクトパネルの一覧更新は既存の `FileSystemWatcher` が拾う。

### ⑦ タブと未保存の扱い

- 画像 1 枚 = 1 タブ。**別の画像をインポートしてもタブが増えるだけで、編集中のタブは破棄されない**。
- 未保存のタブは見出しに `*` が付き、パネル自体の見出しも「スプライトリグ *」になる。
- 未保存のタブを閉じようとすると「保存する / しない / キャンセル」を確認する。
- 同じ `.sprite_mesh` を二重に開こうとした場合は、読み直さず既存タブへ切り替える（編集内容を失わない）。

### ⑧ ボーン / ウェイトモード（Phase B1b の枠）

左パネルの「編集モード」には メッシュ / ボーン / ウェイト の 3 つがあるが、
**B1a で操作できるのはメッシュだけ**（他は選んでも編集を受け付けず、案内文が出る）。
データ構造だけ先に用意してあり、B1b は次の 2 点を実装すれば繋がる:

| 用意済みの受け皿 | B1b での使い道 |
|---|---|
| `SpriteRigMesh.Bones`（`SpriteRigBone`: 名前・親名・位置・回転・スケール） | ボーンの追加・親子付け・バインドポーズ配置 UI |
| `SpriteRigMesh.Weights`（頂点ごとの `SpriteRigInfluence`: ボーン添字・重み・最大 4 本） | ウェイトペイント。現在は `ResetWeightsToRoot()` が毎回ルート 1.0 で張り直しているので、<br>ここを「既存ウェイトを座標で引き継ぐ」実装へ差し替える |

## 8. エディタでの作り方（Phase A2）

「メッシュを用意 → ボーンを生やす → ポーズを付ける → アニメを打つ」の 4 手順。
ボーンは普通の 2D 子アクターなので、③④ に専用の機能はほとんど要らない（§1）。

### ① スキンスプライトを置く

1. ヒエラルキーで 2D アクターを作り、`SkinnedSprite` コンポーネントを足す。
2. インスペクタの **メッシュ** に `.sprite_mesh` を、**テクスチャ** に画像を指定する。
   この時点ではまだボーンアクターが無いので、メッシュは
   **バインドポーズ（無変形）** で表示される。

### ② ボーンアクターを生成する

インスペクタの **「ボーンアクターを生成」** ボタンを押す。

- `.sprite_mesh` の `bones` 宣言どおりの**子アクター階層**がスプライト配下に作られる。
- 各アクターの `CanvasTransform` には**バインドポーズのローカル TRS** が入る。
  したがって生成直後は `current_relative × inverse_bind = 単位行列` となり、
  **見た目は 1 ピクセルも変わらない**。ここがポーズ付けの出発点である。
- **既に同名のアクターがある位置は作り直さない**ので、メッシュを差し替えて
  ボーンが増えたときに押し直せば、既存のポーズを保ったまま不足ぶんだけ増える。
- 操作全体が Undo 1 件（Ctrl+Z で全部戻る）。

### ③ ボーン対応表を確認・修正する

インスペクタのボーン一覧が「メッシュのボーン名 → 実際に使われるアクター」を示す。

| 表示 | 意味 |
|---|---|
| 薄字のパス | **自動解決**（同名の子孫アクターが見つかった。§4 の規則②③） |
| 通常字のパス | **明示指定**（`bone_overrides` にエントリがある。規則①） |
| 赤字 + 警告アイコン + `(未解決)` | 対応アクターが無く、そのボーンだけ無変形で描かれている |

自動解決で意図しないアクターに当たった場合（同名の子孫が複数あるときなど）は、
その行へ**ヒエラルキーからアクターをドラッグ＆ドロップ**するか、
**パス欄をクリックして候補一覧から選ぶ**と明示指定になる。
明示指定を消して自動解決へ戻すには、行右端の × を押す。

> 対応表は**アクター名ではなくスプライトルートからの相対パス**で持つ。
> 同名の子孫が複数あっても一意に定まるようにするためである。

### ④ ポーズを付ける（ビューポートのボーン表示とギズモ）

スキンスプライト（またはその配下のボーンアクター）を選ぶと、ビューポートに
**ボーンが「親関節 → 子関節の線 + 関節の丸」で描かれる**。

- 色: 水色 = 通常 / オレンジ = 選択中のボーン / **赤 = 未解決**（対応アクター無し）
- 末端ボーン（子を持たないボーン）は既定長のスタブで向きだけ示す。
- 表示の ON/OFF はシーンビュー上部の **「ボーン」トグル**（グリッド・軸と並ぶ）。
  セッション限りの設定で `.scene` には保存されない。
- **Play 中は描かれない**（エディタ専用のオーサリング補助のため）。

ボーンアクターを選んで **回転ギズモ（E）** を回すと、その `CanvasTransform.rotation`
が変わり、メッシュがその場で追従する。2D の Z 回転は加算で合成されるので、
親ボーンが回っていても**ギズモの回転量 = 見た目の回転量**になる。

### ⑤ アニメーションを打つ

ボーンは普通のアクターなので、専用のアニメ機構は要らない（§1）。
アニメーションタイムラインで、ボーンアクターの `CanvasTransform` の
`rotation` / `position` / `scale` にキーを打つだけでよい。

```json
{ "actor_path": "root/elbow", "component": "CanvasTransform", "property": "rotation" }
```

`AnimatorComponent` で再生すれば、スキニングは毎フレームその姿勢を拾う。

| 項目 | 状況 |
|---|---|

| ボーンアクターのギズモ位置（アクター編集 2D タブ） | **ネストしたアクターでギズモの描画位置がずれる**（下記） |

| compute のディスパッチ | 1 体につき 1 submit。体数が増えたら 1 フレーム 1 エンコーダへまとめる（TODO） |
| インスタンスキャッシュの寿命 | スロット `Entity` キーで、シーン切替時に明示破棄していない。<br>メッシュパス変更は検出して作り直すため**描画結果は常に正しい**が、<br>長時間セッションではエントリが積み残る（メモリのみの問題） |
| CPU メッシュキャッシュの再読込 | ボーン一覧・CPU ピック用の CPU 側キャッシュは、<br>インスペクタで**メッシュパスを設定し直したときだけ**破棄される。<br>エディタを開いたまま `.sprite_mesh` を外部エディタで書き換えた場合は、<br>メッシュ欄を選び直すと反映される |

### ギズモ位置のずれ（アクター編集 2D タブ）

**アクター編集タブに限り**、ネストした 2D アクター（＝ ボーンアクターは常にこれ）の
ギズモが「祖先の位置・回転を積んでいない座標」に描かれる。

- **回転の結果そのものは正しい**。`CanvasTransform.rotation` への書き戻しは
  画面上のドラッグ角をそのままローカル回転へ加算する形で、2D の Z 回転は
  加算合成なので中心位置に依存しないためである。ずれるのは**ギズモの輪の描画位置**だけ。
- **2D シーンビュー（ビューポートタブ）では正しい位置に出る**。
  こちらは描画と同一の変換連鎖（`collect_actor2d_contexts`）を通っているため。
  ボーンのポーズ付けはこのタブで行えば問題ない。
- 原因: `gizmo_handler.rs::selected_actors_centroid` の 2D 分岐が、
  `compute_viewport_size_2d()` が `None`（＝ アクター編集タブ）のとき
  `CanvasTransform.position + 直近親のアンカーオフセット` しか見ておらず、
  祖先の位置・回転を合成していない。移動ギズモの書き戻し
  （`drag_handler.rs` の「従来経路」分岐）が同じ前提に立っているため、
  中心だけを直すと移動が壊れる。**両方を同時に直す必要がある**。
- これはスキンスプライト固有ではなく、アクター編集タブの
  ネストした 2D アクターすべてに元からある挙動である。
