# スクリプトパネル（内蔵テキストエディタ）（正典）

SEED エディタ（`editor/`, WPF）の**スクリプトパネル**の仕様書。
C# スクリプト（`.cs`）・シェーディングアセット（`.wgsl`）に加えて、
**JSON / テキスト系のアセットをその場で編集する**ための土台でもある。
「どの拡張子を開けるか」「開いたとき何が有効になるか」を触るときは必ずここを見る。

| ファイル | 役割 |
|---|---|
| `editor/src/Panels/ScriptEditorPanel.cs` | パネル本体（タブ・エディタ生成・保存・補完・診断・デバッグ） |
| `editor/src/Panels/ScriptEditorPanel.DiskSync.cs` | ディスク追従（監視・点検・表示の切り替え・再読み込み） |
| `editor/src/Panels/ScriptEditorPanel.Navigation.cs` | 戻る／進む（位置の解決と入力の受け口） |
| `editor/src/Panels/ScriptEditor/DiskSync/ScriptDiskState.cs` | **ディスク追従の判定表（WPF 非依存・テスト対象）** |
| `editor/src/Panels/ScriptEditor/DiskSync/ScriptDiskWatcher.cs` | フォルダ単位のファイル監視とデバウンス |
| `editor/src/Panels/ScriptEditor/DiskSync/ScriptDiskNoticeBar.cs` | タブ上部の非モーダル通知帯 |
| `editor/src/Panels/ScriptEditor/DiskSync/ScriptMissingFileView.cs` | 「ファイルが見つかりません」表示 |
| `editor/src/Panels/ScriptEditor/Navigation/ScriptNavigationHistory.cs` | **戻る／進むの履歴（WPF 非依存・テスト対象）** |

| `editor/src/Panels/ScriptEditor/TextEditableCatalog.cs` | 拡張子 → 言語の対応表の読み込み・検証（WPF 非依存） |

## 1. 対応拡張子（データドリブン）

対応表は `editor/config/text_editable_extensions.json` にあり、
コードには**同じ内容の組み込み既定**だけが入っている（JSON を消してもエディタは動く）。
形式を増やすときは JSON へ 1 行足す。

| 拡張子 | 言語 | 備考 |
|---|---|---|
| `.cs` | `csharp` | 補完・診断・デバッグ・整形・AI 補完の全機能 |
| `.wgsl` | `wgsl` | 着色・静的辞書補完・ランタイム検証（赤下線） |
| `.json` | `json` | `layers.json` / `props.json` / `terrain_meta.json` など |
| `.txt` | `text` | クレジット・メモ |
| `.csv` | `csv` | 表データ |
| `.md` | `markdown` | ドキュメント |
| `.inputmap` | `json` | 入力マップ（中身は JSON） |
| `.icons` | `json` | アイコンセット（専用エディタが無い） |
| `.anim` | `json` | アニメーションクリップ（中身は JSON） |

読み込みは `EditorPaths.ConfigDir`（開発配置＝`editor/config`、配布配置＝exe の隣の `config`）から
起動時に 1 度だけ（`MainWindow.LoadTextEditableCatalog`）。壊れていても**起動は止めず**、
組み込み既定へフォールバックして理由を `EditorLog` へ出す。

### 対象外にしているもの（意図的）

| 拡張子 | 理由 |
|---|---|
| `.scene` / `.actor` / `.actor2d` | **エディタが常時読み込んで編集している実体**。テキストで書き換えるとランタイム側の状態と二重管理になり、「保存した瞬間に相手の変更が消える」「壊れた JSON でシーンが開けなくなる」という戻せない壊れ方をする。`TextEditableCatalog` は JSON にこれらが書かれていても**読み込み時に拒否する**（データで安全策を外させない） |
| `.tvox` / `.tscatter` / `.tcover` | 地形の中間データで**独自バイナリ**（magic `TVOX` / `TSCT` / `TCOV`）。テキストで開けば文字化けし、保存すればファイルが壊れる。プロジェクトパネルでも既定で非表示（[docs/editor_project_panel.md](editor_project_panel.md) §7） |
| `.mat` | 現状はダブルクリックで OS の既定関連付けアプリを開く（Phase R7 の最小実装のまま。[backlog](backlog.md)） |

## 2. 開く動線

### ダブルクリック（プロジェクトパネル）

**専用エディタを持つ形式が優先**。テキストエディタは最後のフォールバックに置いてある
（`ProjectPanel.xaml.cs` の `AttachItemEvents`）。

```
.scene → シーンを開く
.actor/.actor2d → アクタータブ
.inputmap → 入力マップエディタ
.anim → アニメーションタイムライン
.mat → OS の既定アプリ
.sprite_mesh → スプライトリグパネル
それ以外で対応拡張子 → スクリプトパネル（.cs / .wgsl / .json / .txt / .csv / .md / .icons）
```

### 右クリック「テキストエディタで開く」

`ProjectPanel.TextEdit.cs`。対応拡張子のファイルを単一選択しているときだけ出る。
**専用エディタを持つ形式（`.anim` / `.inputmap`）の中身を直接直したいとき**の入口で、
ダブルクリックの動線（＝専用エディタ）を壊さずにテキスト編集へ入れる。

どちらの動線も `ProjectPanel.ScriptFileOpened` → `MainWindow.OnScriptFileOpened` →
`ScriptEditorPanel.OpenFile(path)` と同じ経路を通る。

## 3. 言語ごとに有効な機能

分岐はすべて `DocTab.Language`（タブ生成時に拡張子から確定）で行う。
判定は `EditorLanguages` に集約してあり、ここが緩むと
「JSON を開いたら WGSL の補完候補が出る」といった事故になる。

| 機能 | `.cs` | `.wgsl` | JSON / CSV / Markdown / テキスト |
|---|---|---|---|
| 構文ハイライト | ○（C# ダーク調整） | ○（`Wgsl.xshd`） | JSON=○ / Markdown=○（ダーク調整） / CSV・テキスト=無着色 |
| 補完（IntelliSense） | ○ Roslyn | ○ 静的辞書 | **×** |
| 診断（赤波線） | ○ Roslyn | ○ ランタイム検証 | × |
| ブレークポイント・デバッグ | ○ | × | × |
| AI インライン補完 | ○ | × | × |
| コード整形（Ctrl+K,D） | ○ | × | × |
| 保存後のコンパイル検証・`RELOAD_SCRIPTS` | ○ | × | × |
| 保存・タブ・変更マーク・検索・置換・Undo | ○ | ○ | ○ |

保存は全種別で同じ経路（`Ctrl+S` / タブの未保存マーク / クラッシュ復元の退避）。
C# 以外はファイルへ書くだけで終わる（`.wgsl` はランタイムが mtime を見て自分でホットリロードする）。

### ハイライト定義について

- JSON は AvalonEdit に**同梱の `Json` 定義があるが使わない**。同梱版はライトテーマ向けで、
  区切り記号が黒（`#000000`）などエディタ背景（`#1E1E1E`）では読めないため、
  独自の `Syntax/Json.xshd`（定義名 `JSON`）を埋め込みリソースから登録している。
- Markdown は同梱の `MarkDown` 定義を使うが、見出し `#800000`・引用 `#00008B` と暗すぎるので、
  C# 定義と同じやり方で初回だけダークテーマ向けに塗り替える（`BuildDarkMarkdownHighlighting`）。
- JSON にコメント（`//`）の着色は入れていない。JSON 仕様にコメントは無く、
  ランタイム側（`serde_json`）も受け付けないため、書いてよいと誤解させないのが目的。

## 4. 大きいファイルの扱い

`max_editable_bytes`（既定 **1 MiB**）を超えるファイルは**読み取り専用タブ**で開く。

- 「開けない」ではなく「編集させない」にして、中身の確認だけはできるようにする。
- 理由（サイズと上限）は `EditorLog` へ出す。
- 上限は `editor/config/text_editable_extensions.json` で変えられる。
  0 以下を書いた場合は「何も編集できないエディタ」になるのを防ぐため既定へ丸める。

## 5. ディスク追従（開いているタブを実ファイルへ合わせる）

バージョン管理（Lore）でブランチをマージ・切り替え・最新取得すると、
開いているスクリプトが**ディスク上で書き換わったり消えたりする**。
タブが開いた瞬間の中身を持ち続けると、
「別ブランチの中身を編集して保存 → 取り込んだ変更を丸ごと巻き戻す」事故になる。

### 5.1 検知

| 経路 | 内容 |
|---|---|
| `FileSystemWatcher` | 開いているタブの**親フォルダ**を監視（`Filter="*"` / サブフォルダ無し）。原子的保存（一時ファイル → リネーム）でも拾えるようファイル単体にしない |
| ウィンドウのアクティブ化 | エディタのウィンドウが再び手前に来たら全タブを点検する。監視の取りこぼし対策で、**フォルダごと消された場合の復帰**もここが拾う |

- どのファイルが変わったかは伝えず、「まとめて全タブを点検し直す」に落とす。
  ブランチ切り替えでは何百件ものイベントが一斉に飛ぶため、個別に突き合わせるより速く確実。
- イベントはデバウンス（**400 ms**）して UI スレッドで 1 回だけ処理する。
  監視バッファ溢れ（`Error`）も「大量に変わった」として同じ点検に落とす。
- 考え方は `editor/src/Scene/SceneAutoReloader.cs`（シーンの自動再読込）と揃えてある。

### 5.2 判定表

`ScriptDiskState.Decide` が ［ファイルの有無］×［ディスクの内容が基準と同じか］×
［未保存の編集］×［いまの表示状態］から操作を 1 つ決める。**純粋関数**で、
同じ入力なら何度呼んでも同じ結果になり、適用後にもう一度呼ぶと「何もしない」に落ち着く。

「基準」＝ そのタブが**最後にディスクと読み書きした内容**のハッシュ（SHA-256）。
保存時にも更新するので、**自分の保存で自分を再読み込みすることはない**。

| ファイル | 内容が基準と同じ | 未保存の編集 | 動作 |
|---|---|---|---|
| 在る | 同じ | どちらでも | **何もしない**（自分の保存・タイムスタンプだけの更新） |
| 在る | 違う | 無し | **黙って再読み込み**（キャレット・スクロール位置は保つ。Undo 履歴は捨てる） |
| 在る | 違う | あり | **上書きしない**。帯で「ディスク上で変更されました」＋［再読み込み（編集を捨てる）］［このまま編集を続ける］ |
| 無い | — | 無し | エディタ領域を**「ファイルが見つかりません」＋パス**へ差し替える（編集不可） |
| 無い | — | あり | 本文はそのまま。帯で「削除されました。保存すると作り直されます」 |
| 在る | — | 無し（「見つかりません」表示中） | **通常表示へ戻して読み直す**（ブランチを戻した等） |

- **保存（Ctrl+S）の直前にもディスクを見る**。基準と違っていたら**書かずに上の判定表へ委ねる**
  （未保存なし → 黙って再読み込み／未保存あり → 帯）。マージが入った直後
  （検知のデバウンス中）に Ctrl+S を押すと、取り込んだ変更を黙って巻き戻してしまうため。
  ここで独自に分岐しないのが要点で、表を迂回すると
  「未保存でもないのに帯が出て、［このまま編集を続ける］で基準だけ新しい内容へ進み、
  以後どの点検でも食い違いを検出できない」状態を作ってしまう。
  実体はあるのに**読めない**（他プロセスが書き込み中・ロック中）ときも保存を見送る。
  見送ったことは `EditorLog` に出す。
- ただし**「タブを閉じる」「アプリを終了する」の保存確認で［はい］と答えた保存だけは見送らない**。
  そこで黙って見送ると、直後に本文ごと捨てられて**取り戻せない編集内容を失う**。
  外部変更を上書きした方はバージョン管理の差分に残るので取り戻せる。
- ［このまま編集を続ける］は、**ディスクの現在の内容を「了承済み」として基準に据える**。
  こうしないと、監視イベントやウィンドウのアクティブ化のたびに同じ帯が出続ける。
  ディスクがさらに変われば、また帯が出る。
- 帯は非モーダル。マージ直後に何十枚もダイアログが出ないようにするため、必ず帯で出す。
- 読み取り専用タブ（エンジン API のソース）にも同じ判定が効く（未保存は常に無し）。

### 5.3 再読み込みで通すこと

本文を差し替えると、本文に紐づく位置情報が全部壊れる。差し替え前に控えて後から戻す。

| 対象 | 扱い |
|---|---|
| キャレット・スクロール位置 | 行・桁とオフセットを控えて復元（範囲外なら丸める） |
| Undo 履歴 | **捨てる**（差し替え前の内容へ戻せるとディスクとの食い違いが分からなくなる） |
| ブレークポイント | 行番号で控え、`BreakpointSet.ResetTo` で張り直す（新しい行数を超える行は落ちる）。落ちた結果は `BreakpointStore` と `BreakpointsChanged` へ流し、デバッグ中の netcoredbg とズレないようにする |
| 戻る／進むの履歴 | そのファイルの点を行・桁の固定値へ落としてから差し替える |
| 診断（波線・エラー一覧） | 差し替え前の結果はオフセットも行番号も合わないので**先に消す**（再解析が終わるまで古い結果を見せない） |
| 診断・意味着色・ワークスペース同期 | `RunPostLoadPasses` で初回に開いたときと同じ後処理を通す |
| AI インライン補完 | 差し替え中は無効化する（総入れ替えも `TextChanged` なので、そのままだと開いているタブの数だけクラウドへ要求が飛ぶ） |

### 5.4 見た目

- **エディタ**: 消えたタブは本文ごと「ファイルが見つかりません」＋フルパスへ差し替え、編集不可にする。
- **「タブ」パネル**: 消えた行は警告アイコン＋薄い色＋取り消し線、ツールチップに「（ファイルが見つかりません）」。
  `OpenDocInfo.IsMissing` で伝える。
- 帯の色は `SeedColorTable.NOTICE_BAR_*`（コントラストは `ThemeContrastTests` が検査する）。

### 5.5 「ファイルが見つかりません」タブを作る経路・作らない経路

利用者が**開こうとした**ものだけタブにする。そうでないものまで空タブにすると、
ブランチ切り替えのたびに身に覚えのないタブが増える。

| 経路 | 無いとき |
|---|---|
| プロジェクトパネルからの `OpenFile` | 「見つかりません」タブを作る |
| エラー一覧からのジャンプ（`GoToDiagnostic`） | 「見つかりません」タブを作る |
| クラッシュ復元（`RestoreDoc`） | タブを作り、退避してあった未保存内容を流し込む（＝削除の帯へ移る） |
| 定義へ移動（F12） | **作らない**（ログのみ） |
| デバッガの行表示（`GoToLine`） | **作らない** |
| 戻る／進むでの移動 | **作らない**（消えた点は読み飛ばす。6.4） |

- 「見つかりません」タブでは **Ctrl+S を受け付けない**。中身は消える前の古いテキストなので、
  書き戻すと別ブランチのファイルを復活させてしまう。未保存の編集があるタブは
  この状態にならない（本文と帯を保つ）ので、失うものは無い。

## 6. 戻る／進む（ナビゲーション履歴）

Visual Studio の Navigate Backward / Forward を手本にしている。
参照をたどって別ファイルへ飛んだあと元の場所に戻る、編集した箇所を順に辿る、
といった往復を**ファイルをまたいで**行える。

### 6.0 本文を丸ごと差し替える処理が守ること

本文の総入れ替え（ディスクからの再読み込み・コード整形）は、
**キャレットを端へ飛ばす**うえに**アンカーを潰す**。どちらも履歴を壊すので、
差し替える側は必ず次の 2 つを通す。

1. `FreezeNavigationAnchors(パス)` — そのファイルの履歴点を行・桁の固定値へ落とす。
2. `WithNavigationSuppressed(...)` で囲む — 差し替え中のキャレット移動・編集を記録させない。
   記録は「進む」履歴を捨てるので、囲み忘れると**戻る／進むが黙って壊れる**。
   抑止は入れ子で呼ばれても外側を解除しない（履歴移動 → タブを開く →
   ディスク点検 → 再読み込み、と区間が重なる経路が実在する）。

### 6.1 履歴の 1 点

- ファイルの絶対パス＋位置。
- **開いているドキュメントでは AvalonEdit の `TextAnchor` で保持する**ので、
  上の行を編集しても指す場所がずれない。
- タブを閉じるとき・本文を丸ごと読み直すときに**行・桁の固定値へ落とす**
  （アンカーはそこで壊れるため）。
- 履歴本体（`ScriptNavigationHistory`）は WPF / AvalonEdit 非依存。
  位置の解決（アンカー ↔ 行桁）はパネル側のアダプタが行う。

### 6.2 記録するタイミング

履歴には**「移動する直前の位置」**を積む。移動した先は現在位置なので、
戻った瞬間に「進む」側へ乗る。これで両方を辿れる。

| きっかけ | 記録する位置 |
|---|---|
| 定義へ移動（F12） | 飛ぶ直前 |
| エラー一覧・診断からのジャンプ | 飛ぶ直前 |
| デバッガの行表示（`GoToLine`） | 飛ぶ直前 |
| 検索の「次へ／前へ」 | 飛ぶ直前（`FindReplaceBar.BeforeJump`） |
| タブの切り替え・別ファイルを開いた | 離れる側の現在位置 |
| 同一ファイル内でキャレットが**閾値以上**飛んだ | 飛ぶ直前 |
| 直前の編集位置から**閾値以上**離れた場所を編集した | その編集位置 |

- 近い点の連続は 1 点にまとめる（同じファイルで閾値以内なら最新で置き換え）。
- **戻る／進むによる移動そのものは記録しない**（抑止フラグで止める）。

### 6.3 定数

`ScriptNavigationHistory` の公開定数。値を変えるときはここだけを見ればよい。

| 定数 | 既定 | 意味 |
|---|---|---|
| `MergeLineDistance` | 10 行 | 同一ファイル内でこの行数以内の 2 点は「同じ場所」。記録時は 1 点にまとめ、移動時は「いま居る場所」として読み飛ばす |
| `JumpLineThreshold` | 10 行 | キャレットがこの行数以上離れたら「ジャンプ」とみなして記録する |
| `MaxEntries` | 50 件 | 片側のスタックの上限。超えたら古いものから捨てる |

### 6.4 移動

- **戻る**: 現在位置を「進む」側へ積み、1 つ前の点へ移動（閉じているファイルなら開く）。
- **進む**: その逆。
- 戻った状態で新しい移動をしたら「進む」側は捨てる。
- **消えたファイルの点は読み飛ばして次の点へ進む**（履歴移動で「見つかりません」タブを量産しない）。
  開いているタブが「見つかりません」状態のものも無効として飛ばす。
- 「いま居る場所」と同じ点（押しても動かない点）も読み飛ばす。
- タブを全て閉じていても辿れる（「進む」側へ積む現在位置が無いだけ）。

### 6.5 キー・マウス割り当て

| 入力 | 動作 |
|---|---|
| マウスのサイドボタン手前（`XButton1`） | 戻る |
| マウスのサイドボタン奥（`XButton2`） | 進む |
| `Ctrl` + `-` | 戻る（Visual Studio と同じ） |
| `Ctrl` + `Shift` + `-` | 進む（Visual Studio と同じ） |
| `Alt` + `←` / `Alt` + `→` | 戻る／進む |

- マウスはパネル全体の `PreviewMouseDown` で拾うので、エディタ上でも検索バー上でも効き、
  **パネルの外では反応しない**。
- `Alt` + `↑↓` は行移動、`Ctrl` + `Alt` + `↑↓` は垂直カーソルで使用済みなので、
  `Alt` 単独は左右だけを取る（既存の割り当てと衝突しない）。

## 8. 既知の制限

- 外部の変更への追従は **5.** の仕組みで行う（`.cs` を含む全種別）。
  ランタイムへのホットリロードとシーンの読み直しは別の仕組み
  （[docs/editor_auto_reload.md](editor_auto_reload.md)）で、こちらはエディタのタブだけを見る。
- **フォルダごと消されている間は監視を張れない**。その状態でファイルが戻ったことは
  ウィンドウのアクティブ化まで気付かない（エディタへ戻れば必ず追いつく）。
- 点検のたびに開いているタブのファイルを**全文読んでハッシュを取る**。
  タブ数が少なくファイルも小さい前提の作り（[backlog](backlog.md)）。
- CSV は無着色のプレーンテキスト編集（列の整列・区切りの着色は無い）。
- **専用エディタと同時に開くと保存を取り合う。** `.anim` をタイムラインで開いたまま
  テキストでも編集すると、後から保存したほうが相手の変更を丸ごと上書きする
  （タイムラインは自分のメモリ上の内容を書き出すため）。どちらか一方で編集すること。
  `.inputmap` も同じ。検出・警告の仕組みは無い（[backlog](backlog.md)）。
- `.anim` / `.inputmap` をテキストで壊すと、それぞれの専用エディタが開けなくなる。
  専用エディタで編集できることはそちらで行うこと。
