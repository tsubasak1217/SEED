# アニメーションタイムライン（キーフレーム編集）

`.anim` クリップをフレーム単位で編集するパネルの正典。
「ビューポートでアクタを動かして、その姿勢をキーにする」ワークフローを軸にしている。

- パネル本体: `editor/src/Panels/AnimationTimelinePanel.xaml(.cs)`
- ドープシート描画: `editor/src/Panels/AnimationTimeline/DopeSheetPanel.xaml(.cs)`
- 純ロジック: `editor/src/Panels/AnimationTimeline/Anim{FrameMath,KeyEditor,HierarchyNav,UndoStack,ActorSnapshot}.cs`
- データ／IO: `AnimClipModel.cs` / `AnimClipIO.cs` / `AnimPropertyRegistry.cs`
- ランタイム側: `runtime/src/engine/animation/clip.rs`、`app/animation_ops.rs`、`app/anim_preview_clip_ops.rs`
- 単体テスト: `editor/tests/AnimationTimelineTests`（`dotnet run --project editor/tests/AnimationTimelineTests`）

---

## 1. 基本ワークフロー

1. **アクタを選ぶ** — ヒエラルキーで、動かしたいアクタ（Animator を持つ親でも、その子でもよい）を選択する。
   子を選んだ場合は**祖先を遡って最も近い Animator 保持アクタ**が自動で編集文脈になり、
   選んだ子は「キー対象」として記憶される（ツールバー右の `Animator: … / キー対象: …` 表示で確認できる）。
2. **必要なら 🔒 で固定する** — ロックを ON にすると、以後アクタ選択が変わっても編集文脈は切り替わらない。
   ビューポートで他のものをクリックしながら作業したいときに使う。
3. **フレームを合わせる** — ルーラーをドラッグする / フレーム番号ボックスに打ち込む /
   `←` `→`（Shift で 10 フレーム）/ `Home` `End` で移動する。
4. **ビューポートでアクタを動かす** — ギズモでも Inspector でもよい。
5. **`I` キー（または「キー挿入」ボタン）** — いまの姿勢が、そのフレームのキーになる。
   対応するトラックが無い場合は作成を提案するダイアログが出る
   （［はい］= 位置・回転・スケールの 3 本＝**全変換キー**、［いいえ］= 位置だけ）。
6. **スクラブして確認する** — ルーラーをドラッグすると、その時刻の姿勢がビューポートに即反映される。
   **保存しなくても反映される**（後述のライブプレビュー）。
7. **保存** — ツールバーの「保存」。ここで初めて `.anim` が書き換わる。

「もう一度そのフレームを打ち直したい」ときは、同じフレームで `I` を押せば値が上書きされる
（キーは増えない）。ドープシート上のキーを選んでから `U` を押しても同じ結果になる。

## 2. フレームとスナップ

タイムラインの時間軸は**フレーム**で表示・操作する。

- クリップは編集用フレームレート `fps` を持つ（`.anim` の `"fps"`、既定 30）。
  ツールバーの `fps:` ボックスで変更できる。
- ルーラーの主目盛はズームに応じたフレーム刻み（1 / 2 / 5 / 10 / 15 / 30 / 60 …）で、
  十分ズームしているときは 1 フレームごとの副目盛も出る。ラベルは**フレーム番号**。
- プレイヘッド・キーの新規作成・キーのドラッグ移動は、すべてフレーム境界へスナップする。
- 値エディタは選択キーの **フレーム番号（編集可）** と **秒（編集可）** を併記する。
  秒で入力してもフレーム格子へ丸められる。

### fps はランタイムに影響しない

`.anim` に保存されるキー時刻は**常に秒**であり、ランタイムのサンプリングも秒でしか行わない
（`runtime/src/engine/animation/clip.rs`）。`fps` は
「エディタが何フレーム目として見せるか／どこにスナップするか」だけを決めるメタデータで、
Rust 側は `#[serde(default)]` で読み飛ばせる。

その帰結として、**fps を変えても既存キーの秒は動かない**。
たとえば 30fps で打った 15 フレーム目（0.5 秒）のキーは、fps を 60 にすると 30 フレーム目として表示される。
再生結果は変わらない。

`fps` を持たない旧 `.anim` は、エディタ・ランタイムとも既定 30fps として読む。

## 3. 編集文脈（Animator アクタとキー対象アクタ）

`.anim` は「Animator を持つアクタ」に紐づき、その中の各トラックが
`actor_path`（Animator からの相対アクタ名パス）で配下の子アクタを指す。

編集時に選びたいのは動かす子アクタのほうなので、パネルは次のように振る舞う。

| 選んだアクタ | 編集するクリップ | キー対象 (`actor_path`) |
|---|---|---|
| Animator を持つアクタ | そのアクタのクリップ | 空文字列（Animator 自身） |
| その配下の子アクタ | **祖先の**Animator のクリップ | 子への相対パス（例 `Arm/Hand`） |
| どの祖先にも Animator が無い | なし（案内表示） | — |

- 祖先の探索はヒエラルキー（`HIERARCHY` 通知）を辿り、
  候補ごとに `GET_ACTOR_COMPONENTS`（**選択は変えない**問い合わせ）を投げて Animator の有無を見る。
- **選択 ID の正規化に注意** — `RuntimeManager.SelectionChanged` が渡す id は、単一選択時
  Rust 側 `send_selected()` が付ける「仮想 ID（`999_000_000 + DFS ID`）」であり、`ACTOR_COMPONENTS`
  の `id`（生の DFS ID）とは別の数値空間にある。`HierarchyPanel` / `InspectorPanel` と同じ規約
  （`VirtualActorNodeIdBase`）で正規化してから DFS ID として使うこと。これを忘れると
  「選択したアクタの現在値スナップショットがいつまでも更新されない」不具合になる
  （実際に 2026-09 まで本パネルに存在していたバグ。以降の版で修正済み）。
- `actor_path` の生成では**フォルダノードを飛ばす**。
  ランタイムの `resolve_actor_path`（`runtime/src/engine/animation/system.rs`）がフォルダを透過解決するため、
  フォルダ名を書かない素直な名前パスで正しく解決される。
- 新規トラック追加欄の `actor_path` には、いまのキー対象のパスが自動で入る。
- トラックリストでは、いまのキー対象と `actor_path` が一致するトラックの先頭に `●` が付く
  （`I` で打たれる候補が一目で分かる）。

### 🔒 ロック

ツールバーの 🔒 を ON にすると、以後 `SELECT` による編集文脈（Animator アクタ／キー対象アクタ）の
切り替えを無視して固定する。クリップやキー対象を保ったまま、ビューポートで別のものをクリックしたい
場合に使う。

ロック中でも、**固定中のキー対象アクタ自身の `ACTOR_COMPONENTS`（現在値）は更新され続ける**
（2026-09 修正。それ以前はロック中 `ACTOR_COMPONENTS` を丸ごと無視しており、ロック中に姿勢を
動かしても `I` に反映されなかった）。文脈（どのアクタが対象か）だけを固定し、その対象の
「いまの値」は常に最新のものを使う、という区別になっている。

## 4. キー挿入（`I`）と現在値上書き（`U`）

### 対象トラックの決まり方（`I`）

1. トラックリストで 1 本選択中 → **そのトラックだけ**に打つ。
2. 未選択（＝サマリー行「全チャンネル」選択時と同義）→
   `AnimKeyEditor.InsertOnAllTracks` に委譲し、キー対象アクタ（`actor_path` 一致）のトラック
   **全部**に打つ。**1 本も一致しなければクリップの全トラックへ打つ**
   （Blender の Summary チャンネルと同じ「対象が絞れないなら全部」挙動）。
3. クリップにトラックが 1 本も無い → トラック作成の提案ダイアログ（全変換キー / 位置のみ / キャンセル）。

打ち込む値は、直近の `ACTOR_COMPONENTS` から取り出した**アクタの現在値**。

| トラック | 現在値の取得元 |
|---|---|
| `actor_transform.position` / `.rotation` / `.scale` | `transform` の `px,py,pz` / `ex,ey,ez`（度）/ `sx,sy,sz` |
| `canvas_transform.position` / `.rotation` / `.scale` | `canvas_transform` の `px,py` / `rotation` / `sx,sy` |
| `sprite.color` | `SpriteComponent` / `SkinnedSpriteComponent` の `cr,cg,cb,ca` |
| `text.color` / `text.font_size` | `TextComponent` の `text_r..text_a` / `font_size` |

現在値が取れないトラック（キー対象と `actor_path` が違う等）は、
従来どおり**直前のキーの値**を複製する。

ドープシートの**ダブルクリック**も同じ規則でキーを作る（現在値が取れればそれを使う）。

#### 現在値スナップショットがまだ届いていないとき

選択直後など、キー対象アクタの `ACTOR_COMPONENTS` がまだパネルに届いていない状態で
`I` / `U` を押した場合、黙って「直前キーの値」へフォールバックすることはしない。
`EnsureKeyTargetReady` が明示的に `GET_ACTOR_COMPONENTS:{dfs_id}` を送って応答を待ち、
届いた時点で `I` / `U` を自動的にやり直す（最大 2 秒、`AnimationTimelineConstants.SnapshotFetchTimeoutSeconds`）。
タイムアウトした場合はツールバーの状態表示にその旨を出す。

`I` / `U` を押した瞬間の状態は、`KeyInsertPrecheck.Evaluate`（純ロジック。
`editor/src/Panels/AnimationTimeline/KeyInsertPrecheck.cs`）が判定する。詳しくは
下の「現在値が取得できないとき」を参照。

#### 現在値が取得できないとき（トラブルシューティング）

`I` / `U` が効かず、ツールバーの状態表示にメッセージが出た場合の対応表。
判定は `KeyInsertPrecheckResult`（`KeyInsertPrecheck.Evaluate` の戻り値）に対応する。

| 状態表示 | 判定 (`KeyInsertPrecheckResult`) | 原因 | 対応 |
|---|---|---|---|
| 「ファイル単独モードでは現在値を取得できません…」 | `FileOnly` | 「直接開く」で `.anim` を単体で開いている（アクタ文脈が無い） | Animator を持つアクタを選択してから「タイムラインで編集」等で開く |
| 「対象アクタが定まっていません…」 | `NoContext` | Animator を持つアクタもキー対象も未確定（クリップ未選択直後など） | アクタを選び直す。通常は自然に解消する |
| （状態表示は「現在値をまだ受信していません…再試行します」→自動で消える） | `NoSnapshot` | 選択直後で `ACTOR_COMPONENTS` がまだパネルに届いていない | 何もしなくてよい。`EnsureKeyTargetReady` が自動的に取得して `I` / `U` をやり直す（最大 2 秒） |
| 「フォルダは変換を持たないためアニメーションできません…」 | `Folder` | キー対象アクタが**フォルダノード**（「グループを作成」等で作った整理専用ノード）。フォルダは Transform を持たず、階層としても透過されるため単体ではアニメーションできない | 子をまとめて動かしたいだけなら、フォルダではなく**通常の空の 2D/3D アクタ**を親にして、そこへ Animator を付ける |
| 「〈名前〉の現在値が取得できません（transform なし / canvas_transform なし）…」 | `NoTransform` | フォルダではないのに、届いた `ACTOR_COMPONENTS` に `transform` も `canvas_transform` も無い（想定外・ランタイム側の不具合の可能性） | 再現手順を記録して報告する |
| 「対象アクタは 3D(Transform) ですがトラックは CanvasTransform です」（逆方向もあり） | `KindMismatch` | クリップのトラックが要求する種別（2D/3D）と、キー対象アクタの実際の種別が食い違う（例: クリップは元々 3D アクタ用に作ったが、いま開いているのは 2D アクタ） | **「はい」を選べばそのままトラックを変換できる**（下記参照）。手動でやり直したい場合は正しい種別のアクタを選ぶか、トラックの `actor_path`/対象を見直す |

いずれのメッセージでも、ツールバーの文脈表示（`Animator: … / キー対象: … [名前 (dfs N) 2D/3D/フォルダ]`）
で「いま何がキー対象と認識されているか」を確認できる。

#### KindMismatch はその場で変換できる（自己修復）

`I` / `U` / サマリー行のダブルクリック / 個別トラック行のダブルクリックで `KindMismatch` を
検知すると、エラーで中断するだけでなく「トラックの種別が対象アクタと違います。
{CanvasTransform|Transform} 用に変換しますか？」ダイアログを出す。
「はい」を選ぶと、**キー対象アクタと同じ `actor_path` を持つ Transform/CanvasTransform 系
トラック全部**をその場で変換し（1 回の Undo 履歴にまとまる）、そのままキー挿入・上書きを続行する。
「いいえ」を選べば何もせず中断する（従来どおり）。

変換規則（`AnimKeyEditor.ConvertTrackKind`）:

| プロパティ | 3D → 2D | 2D → 3D |
|---|---|---|
| position | vec3(x,y,z) → vec2(x,y)（z を切り捨て） | vec2(x,y) → vec3(x,y,0) |
| rotation | vec3 Euler(ex,ey,ez) → float(z=ez) | float(rz) → vec3 Euler(0,0,rz) |
| scale | vec3(sx,sy,sz) → vec2(sx,sy)（sz を切り捨て） | vec2(sx,sy) → vec3(sx,sy,1) |

時刻・補間方式・タンジェントの有無は保たれる（タンジェント配列も値と同じ規則で詰め直す）。
Sprite の色など変換規則を持たないプロパティのトラックは対象外（そのまま残る）。

同じ `actor_path` にトラックが無い（＝クリップ内の**別アクタ**宛トラックが原因で
`KindMismatch` になっている）場合は自動変換できないため、従来どおりの案内文で中断する。

#### トラック追加ドロップダウンの既定値と非対応項目のグレーアウト

「トラック」パネル左上のドロップダウン（`CmbNewTrackProperty`）は、キー対象アクタの種別が
判明するたびに既定選択をその種別の Position（2D なら「CanvasTransform / 位置」、3D なら
「Transform / 位置」）へ自動的に合わせ直す（`AnimPropertyRegistry.DefaultIndexFor`）。
ユーザーが一度でも手動で項目を選び直したら、以後はキー対象アクタが変わるまで
自動での上書きをやめる。

対象アクタの種別と食い違う項目（例: 2D アクタに対する「Transform / 位置」）は
ドロップダウン上でグレー表示になるが、選択自体は禁止しない
（`actor_path` で意図的に別アクタを狙う上級者の使い方を妨げないため）。
グレーな項目のままトラックを追加した場合は、エラーにはせず
「対象は 2D です。CanvasTransform 用のトラックを選ぶと現在値でキーを打てます」
のようなヒントをツールバーの状態表示に出すだけに留める（ブロックしない）。

### `U`（選択キーを現在値で上書き）

ドープシートで選択中のキーを、現在値で置き換える。時刻は動かさない。
複数選択中は選択キーすべてが対象で、それぞれのトラックに対応する現在値が使われる
（現在値を取れないトラック＝キー対象アクタと `actor_path` が違うトラックのキーは触らない）。

### サマリー行（「全チャンネル」）

トラックリストの先頭に常設される、削除できない集計行（Blender の Summary チャンネル相当）。

- ドープシート最上段にも対応する行が表示され、**いずれかのトラックにキーがあるフレーム**へ
  ◆が立つ（`AnimKeyEditor.SummaryFrames` による派生表示。保存はされない）。
- サマリー行を選択している状態は「トラック未選択」と同じ扱いで、上記 2. の一括挿入が働く。
- サマリー行の空白部を**ダブルクリック**すると、その時刻のキーを**対象トラック全部**へ一括挿入する
  （`AnimKeyEditor.InsertOnAllTracks`）。
- サマリー行の◆を**クリック**すると、そのフレームのキーが**全トラックぶんまとめて選択**される。
  以降の移動・削除・コピーは通常の複数選択と同じ経路（下記 5 章）で処理される。
  ◆の色は「そのフレームのキーが全部選択されている」ときだけ選択色になる（状態を別に持たない派生表示）。

## 5. ナビゲーションと複数選択編集

### 5.1 時間軸のナビゲーション

| 操作 | 動作 |
|---|---|
| ホイール | 横スクロール |
| `Ctrl` + ホイール | **カーソル位置を軸に**時間軸をズーム（`MinPixelsPerSecond`〜`MaxPixelsPerSecond` でクランプ） |
| `Shift` + ホイール | トラックを縦スクロール（行がビューに収まらないときだけ動く） |
| ホイールボタン ドラッグ / `Alt` + 左ドラッグ | 水平パン |
| `F` | クリップ全体が画面幅に収まるようズーム（先頭へスクロール） |
| `Home` / `End` | プレイヘッドを先頭 / 最終フレームへ |

- **横位置の状態は 1 つだけ**（ドープシートの `ScrollViewer.HorizontalOffset`）。
  ルーラー・グリッド・◆・プレイヘッド・サマリー行はすべて同じ Canvas に描くため、
  定義上ずれようがない。縦位置は `_scrollY`（ルーラーだけを固定し、行を送る）で、
  変化はトラックリスト側へ `VerticalScrollChanged` で伝えて追従させる。
- ズーム後の横位置は `AnimTimelineZoom.ScrollXForZoomAtCursor`（純関数・単体テスト済み）で求める。
  「カーソル下の時刻 `t = (scrollX + cursorX) / pps` を固定する」1 行が仕様のすべて。
- ルーラーのラベルは**どのズームでもフレーム格子の上**に出る
  （刻みは `RulerTickStepsFrames` から「間隔が `MinRulerTickSpacingPx` 以上になる最小の候補」を選ぶ）。
- ナビゲーションはクリップを一切変更しない ＝ **Undo 履歴を汚さない**。

### 5.2 選択

選択は「(トラック添字, キー添字) の集合」（`AnimKeySelection`、純ロジック）。

| 操作 | 動作 |
|---|---|
| ◆クリック | そのキーだけを選択 |
| `Ctrl` + ◆クリック | 選択をトグル |
| `Shift` + ◆クリック | 選択へ追加 |
| 空白部をドラッグ | ラバーバンド（矩形選択）。トラックをまたいで、矩形に入る◆をすべて選択（`Ctrl`/`Shift` 併用で追加選択） |
| サマリー行の◆クリック | そのフレームのキーを全トラックぶん選択 |
| `Ctrl` + `A` | 全キーを選択 |
| `Esc` | 選択解除 |

選択中の◆は `KeyDiamondSelectedFill`（黄）で描かれる。
添字は編集のたびに動くため、正規化経路は `AnimKeySelection` に閉じている
（並べ替え後は `SetFromKeys`、削除後は `NormalizeAfterDelete`、復元後は `Normalize`）。

### 5.3 選択キーへの操作

すべて `AnimKeyEditor` / `AnimKeyClipboard` の純関数 + `CommitEdit`（ダーティ化 →
Undo 1 段 → 再描画 → ライブプレビュー送信）を通る。フレーム境界へのスナップも共通。

| 操作 | 動作 |
|---|---|
| ◆ドラッグ | 選択キー**全体**を同じフレーム数だけ移動（ドラッグ終了で Undo 1 段） |
| `←` / `→` | 選択キーを ±1 フレーム移動（`Shift` で ±10）。**選択が無いときは従来どおりプレイヘッド送り** |
| `Delete` / `BackSpace` | 選択キーをすべて削除（選択が無ければ選択中トラックを削除） |
| `Ctrl` + `C` / `X` / `V` | コピー / 切り取り / プレイヘッド位置へ貼り付け |
| `Shift` + `D` | 選択キーをプレイヘッド位置へ複製（クリップボードは汚さない） |

- **移動の衝突は「置き換え」**（Blender と同じ）。移動先に選択外のキーがあればそれを削除して上書きする。
  移動量は「先頭が 0 フレーム未満／末尾が最終フレーム超へ出ない」ようにクランプされ、
  **選択内の相対間隔は必ず保たれる**（個別クランプではなく移動量そのものを詰める）。
- **コピー / 貼り付けの表現**は JSON（`AnimKeyClipboard`）。トラックは添字ではなく
  対象（`actor_path` + `component.property`）で照合し、キーは
  **選択中の最小フレームを 0 とした相対フレーム**で持つ。
  そのため貼り付けは「先頭キーがプレイヘッドへ来る」形で相対位置を保つ。
  - 貼り付け先に対象トラックが無ければ `value_type` ごと**新規作成**する（別クリップへの貼り付けが成立する）。
  - 同一フレームの既存キーは**上書き**。`duration` を超えるフレームは最終フレームへ丸めるので、
    長いキー列を貼るときは先にクリップ長を伸ばすこと。
  - クリップボードはアプリ内の静的フィールドと**システムクリップボード（テキスト）**の両方に載る。
    読むときはシステム側を優先するため、エディタを跨いだ貼り付けもできる。
    形式マーカー（`seed.anim.keys`）を持たないテキストは無視する。
- **値エディタ**は選択件数で表示が変わる。1 個なら従来どおりフレーム／秒／値／補間／タンジェント、
  複数なら「N 個のキーを選択中」＋**補間の一括変更**＋一括削除。
  補間がバラバラのときはコンボボックスを未選択表示にする。

## 6. ライブプレビュー（保存不要）

キーの追加・移動・削除、値／補間／タンジェントの変更、`fps` / `duration` / `loop_mode` の変更 —
**クリップを変更したら必ず**、編集中の内容がランタイムへ送られ、
現在のプレイヘッド位置で適用し直される。

```
ANIM_PREVIEW_CLIP:{clip_path},{json_base64}   … 編集中の本文でプレビューキャッシュを差し替え
ANIM_PREVIEW:{actor_dfs_id},{clip_path},{time} … その時刻を対象アクタへ適用
```

- JSON は改行・カンマを含むため Base64 で包む（IPC は 1 行 1 コマンドのテキストプロトコル）。
- ランタイム側は `App::handle_anim_preview_clip`（`app/anim_preview_clip_ops.rs`）が
  `anim_preview_cache` の該当エントリを差し替えるだけ。**ディスクは一切触らない**。
- Edit モード専用。Play 中は無視される。
- 編集途中で JSON が壊れていた場合は既存キャッシュを残し、警告だけ出す。
- 保存時は従来どおり `ANIM_RELOAD:{clip_path}` を送るので、キャッシュは保存済み `.anim` に戻る。

以前は「ディスクの `.anim` をロードしてキャッシュ → `ANIM_RELOAD`（保存後）でしか捨てない」
仕様だったため、**保存してスクラブし直すまで編集が見えなかった**。この経路がそれを解消している。

## 7. ショートカット一覧

パネルにフォーカスがあるとき:

| キー | 動作 |
|---|---|
| `←` / `→` | **キー選択があれば**選択キーを 1 フレーム移動、無ければプレイヘッドを 1 フレーム移動 |
| `Shift` + `←` / `→` | 同上を 10 フレーム単位で |
| `Home` / `End` | プレイヘッドを先頭フレーム / 最終フレームへ |
| `F` | クリップ全体を画面幅に収める |
| `Esc` | キー選択を解除 |
| `Ctrl` + `A` | クリップ内の全キーを選択 |
| `I` | プレイヘッド位置に現在値でキー挿入（サマリー行選択時は全トラックへ） |
| `U` | 選択キーを現在値で上書き（複数選択なら選択キーすべて） |
| `Delete` / `BackSpace` | 選択キーをすべて削除 → 選択が無ければ選択中トラックを削除 |
| `Ctrl` + `C` / `Ctrl` + `X` | 選択キーをコピー / 切り取り |
| `Ctrl` + `V` | クリップボードのキーをプレイヘッド位置へ貼り付け |
| `Shift` + `D` | 選択キーをプレイヘッド位置へ複製 |
| `Ctrl` + `Z` / `Ctrl` + `Shift` + `Z` / `Ctrl` + `Y` | クリップ編集の Undo / Redo（パネル内で完結。シーンの Undo とは独立） |

マウス操作（ズーム・パン・矩形選択）は 5 章の表にまとめてある。

トラックの削除は `Delete` キーのほか、各行右端の削除ボタン・行の右クリックメニュー「トラックを削除」からも行える
（サマリー行にはどちらも無い＝削除不可）。

ビューポートにフォーカスがあるとき（`I` / `U` のみ）:

`I` と `U` は、パネルが表示されていてビューポートにフォーカスがある場合にも効く
（ウィンドウの `PreviewKeyDown` を購読している）。
スクリプトエディタや入力欄で "i" / "u" を打っても横取りされないよう、
**フォーカスがビューポート（`ViewportHost`）配下にあるときだけ**発火するホワイトリスト方式にしている。
フレーム送りや `Delete` はパネルにフォーカスがあるときだけ有効。

テキスト入力中（fps / 長さ / フレーム番号ボックス）は、いずれのショートカットも素通しする。

## 8. Undo / Redo

クリップ全体の JSON スナップショット + **そのときの選択**を積む単純なスタック
（`AnimUndoStack` / `AnimUndoSnapshot`、既定 64 段）。

- **すべての編集操作が 1 操作 = 1 段**になる。

  | 操作 | 段数 |
  |---|---|
  | ◆ドラッグ移動（複数選択含む） | ドラッグ**終了時に 1 段**（移動が 0 フレームなら積まない） |
  | `←` / `→` の 1 押下 | 1 段（N 回押せば N 回の Undo で戻る） |
  | 切り取り / 貼り付け / 削除 / 複製 / 補間の一括変更 | それぞれ 1 段 |
  | コピー（`Ctrl` + `C`） | **積まない**（モデルを変えないため） |
  | ズーム・スクロール・パン | **積まない**（ナビゲーションはモデルを変えないため） |

- **選択も一緒に戻る**。削除を Undo すると、戻ったキーが選択された状態になる
  （選択が消えると「Undo 直後に ←→ を押したら別のキーが動く」ことになるため）。
- Undo / Redo は必ずライブプレビューを送り直す（`PushClipToRuntimeAndPreview`）ので、
  ビューポートの見た目も戻った状態へ揃う。
- 貼り付けで作られたトラックは、その 1 段の Undo で**トラックごと**消える
  （スナップショットがクリップ全体だから当然にそうなる）。
- クリップを開き直す／新規作成すると履歴は破棄される。
- シーンの Undo（エディタ本体）とは完全に独立。`.anim` は別アセットで、保存も明示操作のため干渉しない。

## 9. 既知の制限

- **プレビュー適用中の「現在値」** — スクラブ／再生でプレビューを当てている間、アクタの
  Transform はアニメーションの評価値になっている。その状態でビューポートから動かして `I` を押すと、
  次のプレビュー送信で上書きされて見える。手で姿勢を作るときは、いったん再生を止めてから動かすこと。
- **同種コンポーネントの複数スロット非対応** — 現在値の取得は種別ごとに最初の 1 スロットだけを見る。
  `.anim` の `TrackTarget` 自体がスロットを表現できないため、フォーマット側の制約と一致している。
- **自動トラック作成は Transform 系のみ** — 提案ダイアログが作るのは位置・回転・スケール。
  色やフォントサイズのトラックは左のトラック追加欄から手動で足す。
- **モデル内蔵アニメ（`kind=model`）は編集不可** — `.anim` を持たないため、
  従来どおり Inspector で再生設定のみ行う。
- **ファイル単独モード（「直接開く」）はプレビュー不可** — アクタ文脈が無いため、
  ライブプレビューも `ANIM_PREVIEW` も送られない。
- **祖先探索はヒエラルキー取得後に効く** — 起動直後などで `HIERARCHY` をまだ受け取っていない間は、
  子アクタを選んでも祖先の Animator を見つけられない（ヒエラルキーが届けば以後は動く）。
- **サマリー行の「全部に打つ」フォールバックは対象を選ばない** — キー対象と `actor_path` が
  一致するトラックが 1 本も無いとき、サマリー行からの挿入は**クリップの全トラック**
  （＝場合によっては無関係なアクタのトラック）に打つ。トラック作成の提案ダイアログは
  「クリップにトラックが 1 本も無い」ときだけ出るようになった（2026-09 の変更。それ以前は
  「一致するトラックが無ければ提案ダイアログ」だった）。
- **未検証（エディタ実機）** — サマリー行のドラッグ操作の見た目、削除ボタン/右クリックメニューの
  実機での操作感、`GET_ACTOR_COMPONENTS` 再問い合わせのタイムアウト表示は、
  エディタを起動しての目視確認が必要（本セッションでは静的検証とユニットテストのみ）。
