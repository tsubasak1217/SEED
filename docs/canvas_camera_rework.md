# カメラ アスペクト比 / キャンバス解像度自動化 / 描画ゾーン / レイヤー — 設計仕様

world/viewport 概念（docs/editor_2d3d_tabs.md）に続くキャンバス・カメラ周りの刷新仕様。
（2026-07-08 ユーザー承認済み。実装時はこのドキュメントを正典とする）

## 1. カメラ: 「解像度設定」→「アスペクト比」

- CameraComponent の `target_width` / `target_height` は**実質アスペクト比**として
  使われてきたため、**データ・serde はそのまま維持**する（移行なし）。
- 変更は**表示と既定値のみ**:
  - インスペクタの見出し「解像度設定」等 →「**アスペクト比**」（ピクセル数と誤認させない）。
    入力は横・縦の 2 値直入力（例 16 : 9。1920 : 1080 のような値も比として有効）
  - 「**ウィンドウアスペクト比を適用**」ボタンを設置。押下でプロジェクト設定の
    解像度（window_width / window_height）の値を target_width / height に設定する
  - **カメラ新規追加時の既定値**もプロジェクト設定の解像度値
    （ランタイムの ADD_COMPONENT 処理で App が読み込み済みのプロジェクト設定から設定。
    取得不能時は従来既定 1920×1080）

## 2. キャンバスのインスペクタ簡素化

- **子キャンバス**（親キャンバス配下にあるキャンバス）:
  「基準領域」（旧ビューポート参照）セクションを**非表示**にする。
  親キャンバス内に配置されるだけであり、基準領域の概念を持たない
- **ルートキャンバス（ビューポート所属）**:
  幅・高さ（解像度）フィールドを**非表示**にし、以下の**自動計算値**を使う:
  - 基準領域 = カメラ参照（MainCamera / 明示参照）あり:
    「プロジェクト設定の解像度」×「カメラのアスペクト比」を照合し、
    レターボックス等のスケーリングモードを考慮した**最終的な縦横ピクセル数**を
    キャンバス範囲（解像度）とする
  - 基準領域 = ウィンドウ、またはカメラ不在:
    プロジェクト設定の解像度（スクリーン解像度）をそのまま使う
  - **実行中の動的リサイズ追従ではなく、編集時の事前計算**である点に注意。
    Play 時のウィンドウ実サイズへの適応は従来どおり auto_scale・スケールモードが担う
  - **データ（width / height / auto_scale / スケールモード）は削除せず維持**する。
    ルートキャンバスではインスペクタから直接編集させず、自動計算値で上書き運用する
    （スケールモード関連の設定 UI は従来どおり）
- **ワールド配置のキャンバス**（3D ワールドキャンバス）は従来どおり
  幅・高さを手動設定する（自動計算の対象外）

## 3. ビューポートタブ: ルートキャンバスの Transform 固定

- ビューポート所属の**ルートキャンバス**は Transform 編集不可:
  position / rotation / pivot / anchor = 0、scale = 1 に**固定**
  - インスペクタ: 該当フィールドを読み取り専用（または非表示）にする
  - ギズモ: ルートキャンバスに対する移動・回転・スケール操作を不活性化
  - 描画・レイアウト計算: 保存済みデータに非ゼロ値があっても**書き換えずに無視**し、
    恒等（0 / 1）として扱う（後から復帰しやすいようデータは温存）
- **子キャンバス**は親キャンバス基準で従来どおり編集可能

## 4. 描画ゾーン（CanvasComponent に追加）

- ビューポート所属キャンバスに **描画ゾーン: 前面（既定）/ 背景** を追加する
- 描画順（奥→手前）: **zfar ← 背景キャンバス | 3D ワールド | 前面キャンバス → znear**
  - 背景ゾーンのスプライトは zfar（最奥）で描画され、**必ずワールドの背景**になる
    （カメラのクリアカラーの上・ワールドの下）
  - 前面ゾーンは従来のオーバーレイ（ワールドの上）
- ゾーン設定は**ルートキャンバスのみ**に表示する（子キャンバスはルートに従属。
  基準領域と同じ理由で子には出さない）
- ワールド配置のキャンバスにはゾーン概念は適用しない（3D 空間内の深度で決まるため。
  設定 UI も非表示）
- serde: `#[serde(default)]` で旧データは前面として読み込む

## 5. レイヤー（表示コンポーネント共通の描画優先度）

- キャンバス内の表示オブジェクト（現状 SpriteComponent。将来のテキスト等も）に
  **`layer: i32`（既定 0）** を追加する
- 描画優先度: **大きいほど手前**。同値はヒエラルキー順（従来の DFS 順）
- 比較は**同一描画ゾーン内**で行う:
  - ビューポート・前面ゾーン: 全前面キャンバス横断でレイヤーを共有ソート
  - ビューポート・背景ゾーン: 全背景キャンバス横断で共有ソート
  - ワールドキャンバス: レイヤー概念は常に存在し、その**キャンバス内**での
    描画順制御として機能する（所属場所によって取り扱いが変わる）
- **キャンバス自体はレイヤーを持たない**（キャンバス単位の前後はゾーンで表現）
- インスペクタ: SpriteComponent に「レイヤー」数値フィールドを追加
- スクリプト API: `gameObject.Sprite.Layer`（get/set）を追加し
  docs/scripting_api.md 第 7 節へ追記（host_api の "Sprite" レジストリに layer を追加）

## 6. レイアウトの走査と切り抜き・レイアウトの部品（W2-1a・W2-1b・2026-09-27。実装の正典）

§1〜§5 の後に入れた、2D キャンバスのレイアウト計算の置き場と、UI の切り抜き（W2-1a）、
レイアウトの部品（コンテナ・子の側の指定・dp・安全領域。W2-1b）の規則。
コードの正典は `runtime/src/engine/core/canvas_layout/`（各ファイルの冒頭の説明）。

### 6.1 レイアウトの計算は 1 か所（`canvas_layout`）

以前は描画（`collect_sprite_items`）・キャンバス枠（`collect_canvas_rects`）・GPU の ID 描画
（`collect_canvas_id_items`）・当たり判定（`pick_2d::walk_pick_candidates_2d`）・2D 物理とギズモ
（`physics2d_ops::collect_actor2d_contexts`）の 5 か所が同じ計算を複製していた。今は次の 2 つに寄せてある。

| 部品 | 役割 |
|---|---|
| `placement::resolve(parent, node, env)` | ノード 1 つの配置を求める**純関数**。root_auto の上書き → 基準ビューポート（Camera 参照の上書き優先）→ アンカー → 有効位置（scale_transform）→ 描画ゾーン → サイズ倍率（scale_size・アスペクト比維持）→ 自身のワールド行列 → 子へ渡す文脈（アンカー基準・累積スケール・自動スケール）。浮動小数の演算の順序も旧実装と同じ |
| `CanvasLayoutPass::run(roots, world, wl, root_frame, env)` | 木を 1 回たどって**表**（`CanvasLayoutTable`）を作る。行は `find_actor_by_dfs` と同じ深さ優先の並び（添字 = DFS 番号）。フォルダは文脈をそのまま子へ渡し、CanvasTransform を持たないノードの子孫は 2D レイアウト木の外にする。祖先までの世界線・active・visible をフラグにする |

読み手は表を読むだけにする。どのノードを扱うかは旧実装の打ち切り規則をフラグで表す
（描画・枠・ID 描画 = `is_drawn`、当たり判定 = `is_pickable`〈エディタの選択は非アクティブも選べる〉、
2D 物理 = すべてのノード〈active だけ追う〉）。フレームの描画は、メインの 2D キャンバスの表を
**フレームに 1 回**作り、スプライト等の収集とキャンバス枠と（エディタでは）ID 描画で使い回す。
文脈（ビューポート・自動解像度・設計空間表示）が違う読み手（エディタのクリック選択・Play のポインタイベント・
2D 物理・3D ワールドキャンバスの子）は同じ走査で自分の文脈の表を作る。3D ワールドキャンバスの子の GPU の ID 描画
（`walk_3d_canvas_children_id`）とエディタの枠（`collect_3d_canvas_child_outlines`）も W2-1b から表を読む
（旧い走査とランダムな木 1,500 個でビット単位の一致を確かめた。違いは CanvasTransform を持たないノードの下を
描画と同じく出さなくなった 1 点だけ。`canvas_layout_equivalence/world_canvas_walks.rs`）。

**アンカーの規則**（`anchor.rs`）: 最上位ノードはビューポートを仮想親とし（設計空間表示では左上が原点、
Play・SS 合成では中央が原点）、子は**親の CanvasComponent の領域 × anchor**（親までの累積スケールが掛かる）。
CanvasComponent を持たない親（Sprite だけのノード等）の子では anchor は効かない（基準 0）。

**同値の保証**: 置き換えの前に旧 5 か所をテスト用に写し（`app/canvas_layout_equivalence/legacy.rs`）、
ランダムな木 3,000 個（12 万ノード）で旧実装と新しい表の結果が**浮動小数のビット単位で一致**することを確かめた
（`legacy_walks_equal_layout_table_on_random_trees`）。旧実装どうしの食い違い（2D 物理の独自の計算・自動スケールの
割り算の扱い）は、読み手ごとの結果を変えないよう残してある（docs/backlog.md「W2-1a で見つけた旧実装の食い違い」）。

### 6.2 切り抜き（`CanvasClipComponent`）

| 項目 | 規則 |
|---|---|
| 付け方 | 2D キャンバスのノードに CanvasClipComponent（インスペクタ「UI → Canvas Clip」）。スロットの有効・無効と、コンポーネントの `enabled`（スクリプトの `CanvasClip.Enabled`）の両方が有効のときだけ切る |
| 矩形 | CanvasComponent があればキャンバス領域（エディタのキャンバス枠と同じ）、無ければ最初の有効な SpriteComponent の矩形、どちらも無ければ切らない |
| 切るもの | **子孫だけ**（ノード自身の描画は切らない）。スプライト・スキンスプライト・テキスト（インライン画像を含む）・2D パーティクル・`SEED.Draw` の図形（`space` の持ち主のノードと同じ切り抜き）。スクリーンスペースの図形（`space: null`）は切らない |
| 入れ子 | 外側の領域を親に持ち、描画は祖先との積（AABB の交差）で切る。深さの上限なし（番号は u16） |
| 描画 | 描画順のランを切り抜きの番号の変わり目で分け、ランごとに `set_scissor_rect`（`renderer/ui_clip.rs`）。オーバーレイパスは描画先の全体、メインパスは set_viewport の矩形（Play のゲーム領域）へ写してパスの元の scissor と交差させ、描き終えたら元の scissor へ戻す。1 画素も残らないランは描かない。切り抜きが無ければ従来と同じラン・同じ描画 |
| 当たり判定 | `pick_2d`（エディタの 2D の選択と Play のポインタイベント）は、点が祖先のすべての切り抜きの AABB の内側のときだけ判定する（切られて見えない所は押せない）。ジェスチャー（W2-2。`CanvasGestureComponent`）も同じ表と同じ規則で、切り抜きの外で押した指はアリーナに参加しない（docs/input_gestures.md §3） |
| ID 描画 | エディタの GPU の ID 描画（3D ビューでのキャンバスの選択）も同じ領域で scissor を張る（W2-1b）。アイテムに切り抜きの番号を持たせ（`CanvasIdItem.clip`）、描画と同じカメラで画素の矩形を求める（`canvas_id_scissors`）。切り抜かれて見えない所はクリックしても選べない |
| 制限 | 回転したノードは 4 隅の外接矩形で切る。3D ワールドキャンバス（透視）は切らない。角丸・円の切り抜きは W2-4（シェーダーの SDF） |

### 6.3 レイアウトのコンテナと子の側の指定（W2-1b）

| 部品 | 並べ方 |
|---|---|
| `CanvasStackComponent`（Canvas Stack） | 縦・横に 1 列。子の間隔・内側の余白・主軸の揃え（先頭・中央・末尾・両端・前後等分・均等）・交差軸の揃え（先頭・中央・末尾・Stretch）・逆順。伸ばす子（`CanvasLayoutItem.flex`）へ主軸の余りを重みで分ける |
| `CanvasWrapComponent`（Canvas Wrap） | 主軸（既定 横）へ並べ、箱の長さを超えたら次の行へ。子の間隔・行の間隔・行の中の揃え・行の中の交差軸の揃え（Stretch は行の高さまで）・行の塊の揃え |
| `CanvasGridComponent`（Canvas Grid） | 左上から行優先でセルへ。列数（1 以上で固定、0 でセルの最小幅から自動）・セルの縦横比（幅 ÷ 高さ。0 以下は行の高さを中身の最大に）・列と行の間隔・セルの中の置き方（既定 Stretch = セルいっぱい） |
| `CanvasLayoutItemComponent`（Canvas Layout Item） | 子の側の指定。コンテナに無視させる・伸ばす重み（Stack のみ）・大きさの指定（0 = 中身）・下限・上限（0 = なし）・揃えの上書き（Grid はセルの中の置き方）・親に合わせる（fill_width / fill_height） |

**規則**（コードの正典は `canvas_layout/pass.rs` の `place_node`・`measure.rs`・`containers/`）

1. **コンテナの配置が子のアンカー・位置より優先する**。コンテナの下の子（フォルダの中の子も、フォルダが無いのと同じに並ぶ）は、
   `CanvasTransform` の `anchor`・`position`・`scale_transform` を使わず、コンテナが割り当てた矩形（`LayoutSlot`）で置く:
   有効位置 = 矩形の左上 + pivot × 矩形の大きさ。`rotation`・`scale` は残り、pivot の周りの見た目の変化として掛かる。
   並べないのは CanvasTransform を持たない子・`ignore_layout` の子・非表示か無効で「詰める」の子（自分のアンカー・位置のまま）。
2. **矩形がノードの領域になる**。矩形を割り当てられたノードは、CanvasComponent があればキャンバス領域（枠・切り抜き・子のアンカーの基準）が
   矩形の大きさになり、無くても矩形を領域として扱う（子のアンカーの基準・ローカルの原点＝矩形の左上）。
3. **伸ばした軸はスプライトも伸びる**。コンテナが大きさを決めた軸（伸ばす重み・交差軸の Stretch・Grid のセルいっぱい・親に合わせる・
   fit で中身に合わせたコンテナ）では、そのノードの Sprite を矩形の大きさで描き、当たり判定・ID 描画・切り抜きの矩形も同じ大きさにする
   （`CanvasNodePlacement::sprite_size`）。伸ばしていない軸は従来どおり Sprite の幅・高さ × サイズ倍率。スキンスプライト・テキストの大きさは変えない。
4. **子の自分の大きさ**（軸ごと。先にあるものが勝つ）: 親が伸ばした大きさ → `preferred_*` → コンテナで CanvasComponent を持たないか fit の軸なら中身
   （子を並べた大きさ＋余白）→ CanvasComponent の大きさ → 最初の有効な Sprite → 最初の有効な Text の枠（0 より大きい軸）→ 0。下限・上限へ収める。
   大きさの単位はキャンバスの単位（子のサイズ倍率が掛かる。Sprite の幅・高さと同じ）。枠の無い Text の文字の寸法は測らない（W2-6 の Text.Measure）。
5. **コンテナの箱**（子が並ぶ領域。コンテナのローカルの画素）: CanvasComponent があれば「基準の大きさ × 子の累積スケール」
   （子のアンカーの基準と同じ。auto_scale のルートならビューポートの画素）。無ければ親のコンテナが割り当てた矩形、それも無ければ中身に合わせる。
   `fit_width` / `fit_height` は CanvasComponent を持つコンテナのその軸を中身に合わせる（親のコンテナの割り当てがあれば割り当てが勝つ）。
   間隔・余白・セルの最小幅はキャンバスの単位で、子の累積スケールを掛けて画素にする（縦横比は縦横の倍率の比で補正）。
6. **伸ばす**: Stack の主軸の箱の長さが決まっているときだけ。残り＝箱 − 伸ばさない子 − 間隔を重みで分け、子の下限・上限へ収める
   （収めて余った分は配り直さない）。交差軸の Stretch は箱の交差軸の大きさが決まっているときだけ（決まっていなければ先頭と同じ）。
   はみ出す（子の和が箱より大きい）ときは揃えにかかわらず先頭から並べる。
7. **非表示・無効の子**: `hidden_children` が「詰める」（既定）なら並べない（場所を取らない）、「場所を残す」なら見えている子と同じに並べる。
8. **親に合わせる**（`fill_width` / `fill_height`。コンテナの外の子）: 合わせる軸は親の箱（親の CanvasComponent の領域 × 累積スケール）の全体、
   合わせない軸は自分の大きさ・自分の位置。最上位のノード（ルートキャンバス）には効かない（ルートの矩形はビューポート）。
9. 複数のコンテナを同じノードに付けたときは、スロットの順で最初の有効なもの。

**1 回の走査で 2 段の計算**: 子の大きさが決まってから親が並べる（測る → 並べる）。走査は深さ優先で、コンテナのノードを訪ねたときに
子を測って並べ（`LayoutMeasurer::arrange_children`）、子ごとの矩形を「割り当て待ち」に積む。子は必ずコンテナより後に訪ねるので、
子の配置は割り当てを取り出すだけで済む。測った結果は（エンティティ, 決まった大きさ）で覚え、伸ばす子は伸ばした後の大きさで 1 回だけ測る。
走査がコンテナを並べるときは親が測ったときと同じ条件で箱を決める（`container_inner`）ので、表を引くだけになる。
測る回数はノード数に比例する（深さ 5・6 の入れ子の木で 1 ノードあたり 1.0 回。`layout_tests.rs` の `measure_calls_are_linear_in_node_count`）。
部品を使わない木は従来とまったく同じ計算（W2-1a の同値の性質テストがそのまま通る）。

**2D 物理とギズモ**: レイアウトの部品が矩形を決めたノード（`layout_adjusted`）だけ、物理・ギズモの位置も表の有効位置・領域を読む
（それ以外のノードは W2-1a の隔離のまま。docs/backlog.md「W2-1a で見つけた旧実装の食い違い」）。

**例**（縦画面のアプリの画面の骨組み）

```
UiRoot（Canvas・単位 dp）
├─ Background（Sprite・LayoutItem fill_width/fill_height）…… 画面の端まで塗る
└─ Body（Canvas・SafeArea・Stack 縦・cross_align Stretch）…… 安全領域の内側に縦に並べる
   ├─ Header（Sprite 高さ 56）
   ├─ Content（Sprite・LayoutItem flex 1）…… 残りの高さいっぱい
   │  └─ Chips（Canvas・Wrap 間隔 8）…… 行に収まらないチップは次の行へ
   └─ TabBar（Canvas 高さ 64・Grid 列数 4・縦横比 0）
```

### 6.4 dp（端末に依らない単位。W2-1b）

| 項目 | 規則 |
|---|---|
| 置き場 | **ルートキャンバスの `CanvasComponent.unit`**（px = 既定・従来 / dp）。単位は座標系の性質なので木の途中で混ぜない（子キャンバスはルートの単位に従う。インスペクタはルートキャンバスだけに「寸法の単位」を出す）。既存のシーンは px のまま（欄が無ければ px。px は保存しない） |
| 1 dp の画素数 | 表示倍率 = 端末の DPI ÷ `PlatformTraits::reference_dpi` = winit の scale_factor（Android は densityDpi ÷ 160。Pixel 6a の 420 dpi で 2.625。Windows は OS の表示スケール ÷ 96 dpi。100% で 1） |
| ルートの大きさ | 基準ビューポート（画素）÷ 1 dp の画素数（dp）。子の位置・大きさ・余白・アンカーは縦横同じ倍率（1 dp の画素数）で画素へ換算する（auto_scale は使わない＝縦横別の倍率で形が崩れない）。ルートの矩形（枠・切り抜き）は画面の画素そのもの |
| 文脈 | Play（PC・Android・エディタに埋め込んだ Play）は画面の写し（`SEED.Screen` と同じ値）から。エディタの Edit・設計空間の表示・アクター編集タブでは 1 dp = 1 px（設計解像度がそのまま dp の大きさ） |
| PC での模擬 | 環境変数 `SEED_SIM_SCALE_FACTOR`（正の実数。例 2.625）で表示倍率を上書きする（`Screen.DPI` も変わる）。`platform/screen/simulated.rs` |
| 例 | Pixel 6a の縦画面 1080×2400 px → 411.43×914.29 dp。48 dp のボタンは 126 px。PC の 540×1200 のウィンドウ（100%）→ 540×1200 dp |

### 6.5 安全領域の部品（`CanvasSafeAreaComponent`。W2-1b）

| 項目 | 規則 |
|---|---|
| 付け方 | CanvasComponent を持つ 2D キャンバスのノード（パネル。ルートキャンバスにも付けられる）に Canvas Safe Area。スロットの有効・無効と `enabled` の両方が有効のときだけ縮める |
| 縮め方 | ノードの箱（子が並ぶ領域）を、`Screen.SafeArea` をノードのローカル座標へ戻した矩形の内側へ、適用する辺（左・上・右・下）だけ縮める。子のアンカー・コンテナ・切り抜き・枠は縮めた領域を基準にする。子の累積スケールは変えない。重ならなければ大きさ 0 |
| 追従 | 安全領域はフレームごとの画面の写しから読む（Android は WindowInsets の報告。描画面の大きさが一致する報告だけを使うので、回転の直後の 1 フレームは前の値のことがある）。画面の回転・システムバーの出し入れ（`SEED.Platform.Window.SetSystemBarsVisible`）に次のフレームから追従する |
| 文脈 | Play だけ。PC は報告が無いので画面全体（縮めない）。環境変数 `SEED_SIM_SAFE_AREA=左,上,右,下`（画素）で模擬の切り欠きを出せる。エディタの Edit・設計空間の表示では縮めない |
| スプライト | 縮めた領域に合わせて Sprite の大きさは変えない（画面の端まで塗る背景は親のノードに置き、`fill_width`/`fill_height` で親いっぱいにする） |
| 制限 | 回転したノード（祖先を含む）では外接矩形になる。CanvasComponent を持たないノードでは何もしない |
