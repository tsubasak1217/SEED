# コントロールポイント（汎用パス）

シーン上に**順序付きの点列**を置くための、用途に依存しない ECS コンポーネント。
川のスプライン・キャラクターの巡回ルート・カメラのフライスルーパス・スポーン地点列など、
**点列で表せるものすべての共通の土台**として使う。

「点を置く側」（本コンポーネント＋エディタ UI）と「点を使う側」（川・巡回・カメラ）を
分離してあるので、消費側を増やしてもコンポーネントには一切手を入れなくてよい。

---

## 1. 使い方（最短手順）

### 1.1 コンポーネントを付ける

1. ヒエラルキーで 3D アクタを選ぶ
2. インスペクタの「コンポーネントを追加」→ カテゴリ **「ツール」** → **Control Point**
3. 点 0 個の空のコンポーネントが付く（追加した瞬間に意味不明な点は生えない）

> カテゴリが「環境」ではなく「ツール」なのは、これが水や地形に紐づく機能ではなく
> **用途に依存しない汎用の編集道具**だから。

### 1.2 画面へドラッグして点を置く（推奨）

インスペクタ「制御点」セクションの **「＋ 制御点を追加」ボタンを、ビューポートへドラッグ&ドロップ**する。
離した画面位置でメッシュ・地形・水面へレイキャストし、**当たった位置に点が追加される**。

- **背景（何にも当たらない場所）へ落としても点は追加されない。** 空に点が浮くのを防ぐため。
- ドロップのたびに 1 点。**連続してドロップすれば、数回のドラッグで地形に沿った線を引ける。**
- 追加された点は自動的に選択状態になるので、そのまま移動ギズモで微調整できる。
- ボタンを**クリック**した場合は従来どおり「末尾に数値で追加」（2 点以上あれば直前 2 点の外挿位置）。

> レイキャストに必要なシーン形状はランタイム側にしか無いため、エディタは画面座標を送るだけで、
> **ワールド座標の解決とアクタ相対への変換はランタイムが行う**（`ADD_CONTROL_POINT_AT_SCREEN`）。
> エディタ側でワールド行列を持たないので、アクタが回転・スケールしていても点がずれない。

### 1.3 ビューポートで点を編集する

- 選択中アクタの制御点は**ワイヤキューブ**で描かれ、点の間は補間ラインで結ばれる
- キューブをクリックすると**その点だけ**が選択され、移動ギズモの対象がアクタから点へ切り替わる
- ドラッグで移動。Undo は「掴む前」へ 1 回で戻る（ドラッグ中の中間フレームは記録しない）
- 何もない場所をクリックすると点の選択は解除され、ギズモはアクタへ戻る

### 1.4 インスペクタのリストで編集する

「制御点」セクションに 1 点 **2 段組み**で並ぶ。

| 段 | 列 | 内容 |
|---|---|---|
| 上段 | `#index` | 点の順序（＝パスの順序） |
| 上段 | 位置 XYZ | **アクタ相対**座標。Enter / フォーカス喪失 / 数値ドラッグで確定 |
| 上段 | time | この点の時刻パラメータ（下記 2.2） |
| 上段 | interp | この点から**次の点へ向かう区間**の補間方法（Linear / CatmullRom / Step） |
| 上段 | 削除 | その点を取り除く |
| 下段 | 回転 XYZ | オイラー角（度）。ビューポートのキューブの向きに反映される |
| 下段 | スケール XYZ | 軸ごとの倍率（既定 1）。ビューポートのキューブの大きさに反映される |

2 段にしているのは、位置・回転・スケールを 1 行に詰めると XYZ の入力欄だけで 9 個並び、
インスペクタ幅では判読も操作も成立しないため。上段だけ見れば従来と同じ操作感になる。

- 行をクリックすると**ビューポートの対応する点が選択される**（リスト → ビューポートの逆方向同期）。
  逆にビューポートで点を掴むと、リストの該当行がハイライトされる。
- 編集はすべて「点列の全置換」1 本で送られる（差分プロトコルは作らない）。

### 1.5 上限

1 コンポーネントあたり **256 点**（`MAX_CONTROL_POINTS`）。
上限に達すると追加ボタンが無効化される。上限があるのは、1 点 = ワイヤキューブ 12 本 + ピッキング ID 1 個で、
青天井にすると描画とピッキングのコストが予測不能になるため。

## 2. データの意味づけ

### 2.1 座標系

`position` は**アクタ相対（ローカル）**で持つ。ワールドへ出すのは評価時（`PathEval`）に
そのアクタの Transform を掛けて行う。これにより「アクタを動かすとパスごと動く」
「プレハブ化してもパスが崩れない」が無料で手に入る。

### 2.2' `rotation` / `scale`

`rotation`（度・YXZ）と `scale`（軸ごとの倍率・既定 1）も点ごとに持つ。
ワールド解決では**アクタの Transform と合成**され、`PathEval` の
`ResolvedControlPoint.rotation` / `.scale`（および `PathSample`）で取り出せる。
補間は姿勢と同じ規則（`Step` は保持、それ以外は軸ごとの線形補間）。

点のスケールは**点自身の原点まわり**に掛かるので、**点のワールド位置は動かない**。
したがって位置しか使わない消費側（川）はスケールの影響を一切受けない。
用途はカメラパスのズーム・巡回中のキャラサイズ・スポーン地点の生成スケールなど。
ビューポートのワイヤキューブはこの回転・スケールで変形して描かれる（設定値が見た目で分かる）。

### 2.2 `time`

「この点に到達する時刻」または「この点における基準時刻」。
**単位も原点も消費側に委ねる**（秒・拍・進捗率のいずれとしても使える）。
エンジンは「点列に沿って単調増加する 1 次元パラメータ」としてのみ扱う。

既定は「追加順に 1.0 ずつ増える連番」なので、何も設定しなければ
`position_at_time(t)` が「t 秒後の位置」として素直に振る舞う。

### 2.3 `interp`

**その点から次の点へ向かう区間**の補間方法（「前の点から来る方法」ではない）。

| 値 | 挙動 |
|---|---|
| `Linear` | 直線補間。曲がり角は角ばるが、点の位置がそのまま効く |
| `CatmullRom`（既定） | 制御点を必ず通る滑らかな曲線。追加ハンドルが要らない |
| `Step` | 次の点に到達するまでこの点の値を保つ（瞬間移動） |

最後の点の `interp` は次の点が無いので評価に使われないが、点を後ろに足したときの挙動が
予測できるよう保持される。
ただし後述の `closed`（閉ループ）を有効にすると「最後の点 → 最初の点」の区間が生まれるため、
**最後の点の `interp` もそのまま使われる**。

### 2.4 `closed`（始点と終点を接続）

インスペクタの「制御点」セクション先頭のチェックボックス。既定は **オフ（開いたパス）**で、
このフィールドを持たない旧 `.scene` も開いたパスとして読み込まれる（`#[serde(default)]`）。

オンにすると点列が輪になり、次の 4 点が同時に変わる。

| 対象 | 開いたパス | 閉ループ |
|---|---|---|
| 区間（線分）の数 | `点数 - 1` | `点数`（+1。`PathEval::segment_count()`） |
| ビューポートの経路線 | 終点で止まる | 終点 → 始点も描かれる |
| 時刻の問い合わせ | 両端で**クランプ** | 1 周ぶんで**周回（ラップ）** |
| Catmull-Rom の隣接点 | 端点は折り返して複製 | **周回**して取る（継ぎ目に角が立たない） |

点が 2 個未満のときは区間が作れないので、`closed` は無視される（`PathEval::is_closed()` が false）。

#### 閉じる区間の時刻の定義

「最後の点 → 最初の点」の区間の所要時刻は **`DEFAULT_TIME_STEP`（= 1.0）**、
すなわち定数 `PATH_CLOSING_SEGMENT_DURATION` とする。つまり

```
最初の点に戻る時刻 = 最後の点の time + DEFAULT_TIME_STEP
1 周の長さ         = (最後の点の time - 最初の点の time) + DEFAULT_TIME_STEP
```

既定の点列は「追加順に 1.0 ずつ増える連番」なので、この定義だと
**閉じる区間だけ速い／遅いということが起きない**（全区間が等時間になる）。

この定義に合わせて、閉ループでは
`time_range()` が `(最初の点の time, 最後の点の time + DEFAULT_TIME_STEP)` を返し、
`duration()` がそのまま「1 周の長さ」になる。

#### ループ再生

閉ループの `sample_at_time(t)` は端でクランプせず、1 周ぶんの長さで剰余を取る
（負の時刻でも正しく巻き戻る）。したがって**消費側は時刻を増やし続けるだけでループ再生になり**、
ラップ処理を各消費側に書く必要はない。`sample_at_progress` も同じ範囲へ写るので、
進捗 0.0 と 1.0 はどちらも始点を指す。

なお「点の時刻が全点同じ（＝時刻を設定していない）」ときだけ、進捗は時刻ではなく
**区間の添字空間**へ写る退避規則が働く。閉ループではこのときも閉じる区間が等分の対象に入る。

## 3. 川（WaterVolume kind = Spline）との統合

川が制御点を使うかどうかは、`WaterVolumeComponent.control_point_ref`（**参照先アクタ名**）で
**明示的に指定する**。

> **W4.1 の変更（2026-07-29）**: 以前は「同一アクタに `ControlPointComponent` があれば自動優先」
> だった。どちらが効いているのか UI から判別できず、コンポーネントを足しただけで川の形が
> 変わってしまうため廃止した。**自動優先はもう働かない**。既存シーンで自動優先に頼っていた川は、
> インスペクタで参照を設定し直す必要がある（下記 3.2 のボタン 1 回）。

### 3.1 切替の判定

| `control_point_ref` | 参照先の状態 | 川に使われる点列 |
|---|---|---|
| 空（既定） | — | `spline_points`（従来） |
| 設定あり | その名前のアクタが見つからない | `spline_points` |
| 設定あり | `ControlPointComponent` が無い / `enabled = false` | `spline_points` |
| 設定あり | 折れ線が 2 点未満 | `spline_points` |
| 設定あり | **上記以外** | **参照先の ControlPoint（`spline_points` は完全に無視）** |

- 参照先は**別アクタでもよい**。その場合、点列のワールド解決には**参照先アクタの Transform**を使う
  （＝制御点を持つアクタを動かすと川が動く。水アクタを動かしても川は動かない）。
- 参照先に `ControlPointComponent` が複数ある場合は**最初の有効スロット（0 番目）**を使う。
- 同名アクタが複数ある場合は **DFS で最初に見つかったもの**（決定的な規則なのでフレーム間で揺れない）。
- 存在しない名前も**そのまま保存される**（「参照を先に書いてからアクタを作る」作業を許すため）。
  解決できないあいだは `spline_points` が使われる。
- `spline_points` は**削除されない**。参照を外せばいつでも従来経路へ戻れる。

### 3.2 参照の設定方法

インスペクタの「川（スプライン）」セクション先頭に**参照ボックス**がある。

- **Hierarchy からアクタ行をドロップ**すると、そのアクタ名が参照に入る
- **✕ ボタン**で参照解除（`spline_points` 経路へ戻る）
- **ダブルクリック**で Hierarchy の参照先アクタへジャンプ

参照が設定されているあいだ、`spline_points` の編集 UI（点リスト・追加ボタン・地形スナップ・
移行ボタン）は丸ごと隠れ、案内 1 行だけになる（2 系統の「＋ 制御点を追加」が並ぶ取り違えを防ぐ）。

### 3.3 移行

`spline_points` で引いた既存の川は、同セクションの
**「このアクタに制御点を作って参照に設定」** ボタンで移せる。押すと:

1. `ControlPointComponent` をこのアクタへ追加
2. 現在の `spline_points` を `rotation = 0` / `scale = 1` / `time = 0,1,2,…` /
   `interp = CatmullRom` に変換して流し込む
3. この水ボリュームの `control_point_ref` に**このアクタ自身の名前**を設定して結線する

アクタ名が空の場合だけ ③ が行われない（名前を付けてから参照ボックスへ D&D すればよい）。

### 3.4 川に残るパラメータ

形（点列）だけが ControlPoint へ移り、**川幅・流速・川の深さ・分割長・見た目は WaterVolume 側に残る**。
`surface_height`（水面高さ）も参照経路で Y に上乗せされ続けるので、
点を動かさずに川全体の水位を上下できる。

**分割長（`river_segment_length`。既定 2.0m）** は「曲線長 何 m ごとに 1 分割するか」で、
小さいほど川が滑らかになる。下限 0.25m。総分割数の上限（256）は据え置きなので、
**長い川では設定を細かくしても上限で頭打ちになり自動的に粗くなる**。

> **座標系の注意**: 参照経路の折れ線は `PathEval` が返す**完全なワールド座標**
> （参照先アクタの位置・回転・スケール適用済み）である。`spline_points` 経路のようにアクタ位置を
> 足してはならない（二重加算になる）。この差は `water/resolved.rs` の
> `from_component_with_path` で吸収している。

### 3.5 川を D&D で引く手順

1. 3D アクタに **WaterVolume**（kind = **Spline**）を追加
2. 制御点を持たせるアクタ（同じアクタでも別アクタでもよい）に **Control Point** を追加
3. 「川（スプライン）」セクションの**参照ボックス**へ、そのアクタを Hierarchy からドロップ
4. Control Point セクションの「制御点を追加」ボタンを、地形の上流にしたい位置へドラッグ&ドロップ
5. 下流へ向かって数回ドロップする（地形にヒットするので川は自然に地形を下る）
6. 2 点目を置いた瞬間から川が描画される
7. 川幅・流速・分割長は「川（スプライン）」セクションで調整する

### IPC 一覧

| 向き | 文字列 | 意味 |
|---|---|---|
| Editor → Runtime | `SET_CONTROL_POINTS:{actor},{slot},{json}` | 点列の全置換（追加・削除・並べ替え・属性編集の全部） |
| Editor → Runtime | `SET_CONTROL_POINT_POS:{actor},{slot},{index},{x},{y},{z}` | 1 点の位置のみ（ギズモドラッグの軽量経路） |
| Editor → Runtime | `SET_CONTROL_POINT_FIELD:{actor},{slot},{key},{value}` | 点列以外のパス設定（現状 `closed` のみ。Undo は `field_edit.rs` の共通機構） |
| Editor → Runtime | `SELECT_CONTROL_POINT:{actor},{slot},{index}` | リスト行クリック → ビューポートの点を選択 |
| Editor → Runtime | `ADD_CONTROL_POINT_AT_SCREEN:{actor},{slot},{x},{y}` | ビューポートローカル画面座標へレイキャストして点を追加 |
| Runtime → Editor | `CONTROL_POINT_SELECTED:{actor},{slot},{index}` | ビューポートで点が選択された |
| Runtime → Editor | `CONTROL_POINT_DESELECTED` | 点の選択が解除された |

### `ADD_CONTROL_POINT_AT_SCREEN` の着弾点解決

1. **メッシュ・水面**: ID パスの RGB に焼かれたワールド座標を読み戻す（背景 = ID 0 ならヒット無し）
2. **地形**: 地形は ID パスに描かれないため、CPU レイマーチ（`terrain_raymarch_hit`）で別途取る
3. ①② のうち**カメラに近い方**を採る。どちらも外れたら**点を追加しない**

ID バッファの読み戻しは 1 フレームに 1 回しかできないため、優先度は
`通常ドロップ > コントロールポイント D&D > アクタ追加 > ピック` とし、
自分の番でなかったフレームは次フレームへ再キューする。

## 5. 既知の制限

- **2D ビュー・2D 編集タブでは点を扱わない**（パスは 3D の概念で、2D のレイと座標系が噛み合わない）。
  2D ビューへドロップしても何も起きない。
- 点の**並べ替え UI が無い**（削除して置き直す）。データ側は添字の順序がそのままパスの順序。
- 参照は**アクタ名**で持つが、エディタでアクタをリネームすると旧名一致の参照は**自動で新名に追従**する（同名アクタが複数ある場合は旧名一致の参照がすべて書き換わる）。シーンファイルを手編集で改名した場合は追従しない。
  切れているあいだは `spline_points` にフォールバックする。
- 参照先の `ControlPointComponent` は**スロット 0 番固定**。1 アクタに複数の点列を載せて
  別々の川から使い分けることはできない（当面はパスごとにアクタを分ける運用）。
- 点の**ピック判定は軸平行のまま**（描画は回転・スケール反映）。拡大した点が掴めなくならないよう、
  判定の箱には軸ごとのスケールの最大値を掛けている（縮小時は基準サイズを維持）。
- 川以外の消費側（巡回ルート・カメラパス）は未実装。土台（`PathEval`）は揃っている
  （`rotation` / `scale` の解決・補間まで用意済み）。
